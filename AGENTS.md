# Acpira

A chat shell for VS Code / Cursor (and IntelliJ) that drives official agent CLIs (`grok agent stdio`, `devin acp`, `kimi acp`, Google's `agy_acp_server`, or any ACP-compatible command) over [ACP](https://agentclientprotocol.com) (JSON-RPC over stdio). The shell owns UI, session organization, permission approvals, accounts, and context budget; model calls and agent execution stay in the CLIs.

## Working rules

- Done means: `pnpm typecheck` and `pnpm test` pass, plus `pnpm build` when a bundle entry or the webview changed and `cargo test --workspace` + `cargo clippy --workspace --all-targets --all-features -- -D warnings` (in `rust/`) when the engine changed, and no orphaned `fake-agent` process remains (the check is under `pnpm test` below). Kotlin changes also pass `cd apps/intellij && ./gradlew test`; Swift changes under `apps/ios/` pass `apps/ios/scripts/check.sh`. Visual changes are checked in `pnpm harness` or the LAB when a browser is available; otherwise the summary says they were not.
- Keep going while the next step needs no decision, and put status notes in the same message as the next action. Stop and ask only when blocked on a decision, or before: deleting files this task did not create, force-pushing or rewriting history, deleting or rewriting data outside the repository (`~/.acpira`, the CLIs' own stores), or sending real prompts to a CLI (the host probe scripts, `pnpm probe` with a prompt), since those spend model calls.
- Read the area's doc from the table below before changing it; the recorded wire behaviour outranks the ACP spec and memory of it. A newly verified fact goes into the matching `docs/dev/` file together with the agent version it was observed on. This file stays an index under 16 KB, because some hosts truncate it there.
- Long multi-part work keeps its checklist in `docs/TASKS.md` (ignored by git) and ticks items as they finish.
- A run that changed files closes with a short summary: any decision still needed first, then what changed, the commands actually run, and what was left unverified (and why). Sections with nothing to say are left out, and a plain question gets a plain answer. Anything not confirmed against code, tests or a real CLI is still called out as unverified, with where it was looked for.

## Commands

- `pnpm build` — each package's own `build`: the VS Code shell (→ `apps/vscode/dist/extension.cjs`), the picker (→ `dist/picker.js`) and the webview (Vite → `dist/webview/main.{js,css}`)
- `pnpm harness [port]` — `acpira --ws` via cargo (release build): the browser harness at the URL printed on stderr (`http://127.0.0.1:7357/?token=…`) runs the real webview bundle against the real sidecar and CLIs without any IDE (`test/host-preview/`, query also `host=editor&agent=kimi&theme=light&cwd=/abs/path`). The handshake token is required; data lives under `~/.acpira/harness` unless `--home` is given; hello `agents` from the page is ignored. Build first; the settings live in `localStorage`
- `pnpm typecheck` — `scripts/typecheck.mjs`: every project the root `tsconfig.json` references (one per package and Node shell, `test/`, `scripts/`; shared options in `tsconfig.base.json`), plus a local `lab/tsconfig.json`. The root `tsconfig.json` is a solution file with `references` only, never `compilerOptions`; a new TypeScript directory gets its own tsconfig and a reference
- `pnpm test` — vitest: every package's and shell's suites (`packages/*/test`, `apps/*/test`, a few beside their sources) plus the cross-package contracts in `test/`, such as envelopes against the Rust sidecar (`test/sidecarShell.ts`; `test/globalSetup.ts` brings `rust/target/debug/acpira` up to date, `ACPIRA_SIDECAR_BIN` points at another binary). `test/fake-agent.ts` is a fake ACP agent built on the SDK; `globalSetup` bundles it with esbuild into `node_modules/.cache/acpira-test/fake-agent.mjs` (the Rust engine suites into `CARGO_TARGET_TMPDIR`, `tests/engine/support.rs`) and suites run it with plain `node`, so a signal reaches the agent (`ps -eo pid,ppid,command | awk '$2==1 && /fake-agent/'` should print nothing after a run).
- `pnpm probe grok [--auth] [--api-key-env VAR] [--import-local] [--image PATH] [--link PATH] [--embed PATH] [--elicit] [--mcp] [--wait MS] [--cmd "<command line>"] [--cwd DIR] [--log FILE] [prompt]` — run `initialize` + `session/new` (+ one prompt, optionally with an inline image / `resource_link` / embedded `resource` block) against a CLI without VS Code; `--elicit` advertises form elicitation and prints / auto-answers `elicitation/create`; `--mcp` passes a marker stdio MCP server in `session/new` and reports whether the agent launched it (no prompt needed); `--wait MS` keeps the process alive after the last response, which is where `available_commands_update` arrives (Grok / Kimi send it after `session/new` returns, Devin during). Use this first when debugging protocol issues. `--cmd` launches an explicit command line with the agent's `initialize` (a CLI not installed where the registry looks), `--log` appends the full ndjson wire (authenticate secrets redacted)
- `pnpm exec tsx scripts/probe/agent-host.ts <agent> [--attach] [--shell] [--write] [--plan] [--image] [--raw]` — the same path the webview takes (envelopes into the Rust sidecar, `scripts/lib/host.ts`) against a real CLI: new session, controls, one prompt, boolean controls flipped on/off, optionally a dropped text attachment, a shell command, a permission-card write (`--write`), a plan-review reject (`--plan`) or an image view (`--image`), permission cards answered like a click; `scripts/probe/opencode-host.ts` (OpenCode modes, a two-file write, import) and `scripts/probe/restore-host.ts <agent>` (reopen + import round trip for any agent) are described under "Host probes" in `docs/dev/host-architecture.md`. All spend real model calls; give the CLI a temp store (`DSH_HOME`, `PI_CODING_AGENT_DIR`) where it has one
- `pnpm exec tsx scripts/probe/subagents.ts <agent> [--air] [--no-caps] [--import-local] [--cmd "<command line>"] [--wait MS]` — raw-ndjson subagent probe (what an agent really emits, SDK validation bypassed) and `scripts/probe/subagents-host.ts <claude|devin>` — the same through the sidecar; both spend real model calls and leave their logs / temp stores in place for inspection
- `pnpm exec tsx scripts/probe/steering.ts <agent> [--model TEXT]` — raw-wire `_session/steering` (mid-turn, idle, a prompt afterwards) and `scripts/probe/steering-host.ts <agent> [--model TEXT]` — the queue's Steer button through the sidecar; both spend real model calls
- `pnpm exec tsx scripts/probe/goal-host.ts [--bin PATH] [--keep]` — Codex's goal controls through the sidecar (set, automatic continuation with a queued prompt, pause, resume, complete, clear), in a temp `CODEX_HOME` copied from `~/.codex` with the raw wire teed to the temp dir; spends real model calls
- `acpira serve --socket PATH [--idle-grace S] [--home DIR]` — the persistent engine the VS Code shell connects to on macOS / Linux (sessions outlive windows and dropped remote connections; `ACPIRA_ENGINE=stdio` falls back to the attached sidecar); socket, log and leases under `$ACPIRA_HOME/run/` (`docs/dev/host-architecture.md`)
- `acpira install-agent antigravity [--force] [--archive FILE]` — download (or take a hand-fetched copy), digest-check and unpack a native-release agent under `$ACPIRA_HOME/agents/<id>/` (what the settings page's install button runs; `docs/dev/host-architecture.md`)
- `acpira handoff-pack --cwd DIR [--base REV] [--recipe FILE] [--json]` — the handoff pack of a work tree's uncommitted changes (diff widened to whole functions, small files in full, optional uses of changed definitions; `docs/dev/host-architecture.md`)
- `scripts/eval/review/run.ts` (review bench), `scripts/eval/run.ts` (harness / Fusion comparison), `acpira quota [--json]` (the CLIs' own quota windows): `docs/dev/evals.md`; real runs spend model calls or quota
- `pnpm catalog:update` — regenerate the built-in model catalogue `rust/crates/acpira-shared/assets/model-catalog.json` from models.dev (`acpira model-catalog [--out FILE]`); refresh before a release
- `pnpm package` — build everything and package this machine's `.vsix` (its sidecar at `bin/`); `pnpm build:sidecar [--all | <os>-<arch>…]` builds release sidecars into `dist/sidecar/`, `node scripts/release/package-vsix.mjs [--all | <vsce-target>…]` packages from them (one VSIX per platform, no universal package); `pnpm version:set X.Y.Z` sets every shell's version (`docs/releasing.md`)
- `cd rust && cargo test --workspace` — the engine both shells ship (see `docs/dev/host-architecture.md`): unit tests plus `crates/acpira-host/tests/engine/` (sessions, manager, accounts, subagents … against `test/fake-agent.ts`; skipped without `node_modules`). `test/fixtures/engine-*.json` are its golden normalize / diff output, which the webview suites render; `ACPIRA_UPDATE_FIXTURES=1 cargo test golden` rewrites them after an intended change. `acpira agents --json` shows how each built-in CLI resolves and is initialized
- `apps/ios/scripts/check.sh [simulator]` — the iOS app (`docs/dev/ios.md`): `AcpiraKit`'s tests on the Mac and on an iOS simulator, then the app scheme's tests; `apps/ios/scripts/shot.sh [out.png] [simulator]` builds, launches and screenshots the app on a simulator (default iPhone 18 Pro)
- `cd apps/desktop && pnpm smoke` — the desktop app end to end (temp home, fake agent, a real window; ~35 s); `pnpm package` its macOS dmg (`docs/dev/desktop.md`)

## Hard rules

- `packages/ui/` must never import `vscode`. Only `apps/vscode/src/extension.ts`, `bridge.ts`, `vscodePlatform.ts` and `files.ts` import it, never `packages/engine-client/`
- All engine behaviour lives in the Rust sidecar; the TypeScript under `apps/vscode/src/` is the VS Code shell only (webview panels, platform RPCs, sidecar lifecycle, the one-time legacy migration). `HostRuntime::create` in `rust/crates/acpira-host/src/runtime.rs` is the engine's single composition root
- `packages/shared/transcript.ts` (`SessionView`) and `packages/shared/protocol.ts` (`HostMsg` / `WebviewMsg`) are the only host ↔ webview contract; `packages/shared/sidecar.ts` is the sidecar wire contract (`SIDECAR_PROTOCOL_VERSION`)
- Sidecar stdout carries envelopes only; logs go to stderr
- The root `tsconfig.json` holds `references` only
- `~/.acpira` is shared by every VS Code / Cursor window and IDEA sidecar: files are written tmp + rename, and `accounts.json`, `secrets.json`, `settings.json` and `sessions/prefs.json` are edited under `store/fileLock.ts`
- Every stream chunk pushes the session view, as a `sessionPatch` (only the changed tail) to the real webview; nothing may defeat the `shared/reuse.ts` reference reuse and `memo` chain (see the render budget and session patches in `docs/dev/webview.md`)
- Write code comments in English
- Components must not contain raw numbers: sizes, type scale, spacing, and radii all use token classes (`h-ctl`, `px-pad`, `gap-gap`, `rounded-md`, …)
- Every "row" (thought / plan / tool / status / session item) uses `ui/Row`; command execution is a row too (command on the row, output card below), not a separate block

## Layout

The engine, shared packages, and one directory per shell under `apps/` (new shells go there too). One pnpm workspace (`pnpm-workspace.yaml`, one lockfile): each package declares its own dependencies, versions live in its `catalog`, and code imports another package by name (`@acpira/shared/transcript`), never by relative path. Packages export their TypeScript sources; nothing imports from `apps/`. Shared build output goes to the root `dist/`; the root `package.json` holds the version, scripts and tooling.

- `rust/` the engine (`acpira-shared` contracts; `acpira-host`: `acp/` the ACP client — `transport/` JSON-RPC + agent process, `agents/` registry / launching / pool / installer, `session/` state machine, `transcript/` normalization, `vendors/` quirks — plus `session_manager.rs`, `store/`, `accounts/`, `external/`, `sidecar/`; `acpira-agent` the built-in agent; binary `acpira`)
- `packages/`: `shared/` contracts and pure logic (transcript, protocol, sidecar, appearance, models, export); `ui/` the React UI (`ui/` primitives, `chat/`, `settings/`, `effects/`, `styles/`); `engine-client/` the engine client the VS Code and desktop shells share; `picker/` the browser panel's element picker
- `apps/vscode/` the extension: manifest, nls files, `.vscodeignore`, `build.mjs`, `src/` (`extension.ts`, `bridge.ts`, `vscodePlatform.ts`, `files.ts`, `store/` + `accounts/` for the legacy migration); `scripts/release/package-vsix.mjs` stages it with the root's `dist/`, `media/`, README, CHANGELOG and LICENSE, and F5 reads those from the root
- `apps/desktop/` the Electron app (own pnpm package); `apps/intellij/` the IntelliJ plugin; `apps/ios/` the iOS app (local only)
- `test/` cross-package contracts (sidecar envelopes, engine golden fixtures, iOS / Rust exports), `fake-agent.ts` and fixtures the Rust tests share; `scripts/` probes; `lab/` the LAB (local only)
