# Acpira

A chat shell for VS Code / Cursor that drives official agent CLIs (`grok agent stdio`, `devin acp`, `kimi acp`, or any ACP-compatible command) over [ACP](https://agentclientprotocol.com) (JSON-RPC over stdio). The shell owns UI, session organization, permission approvals, accounts, and context budget; model calls and agent execution stay in the CLIs.

## Commands

- `pnpm build` — host bundles (esbuild → `dist/extension.cjs` for VS Code, `dist/host-server.cjs` the sidecar) + webview bundle (Vite → `dist/webview/main.{js,css}`)
- `pnpm harness [port]` — `node dist/host-server.cjs --ws`: the browser harness at the URL printed on stderr (`http://127.0.0.1:7357/?token=…`) runs the real webview bundle against the real sidecar and CLIs without any IDE (`test/host-preview/`, query also `host=editor&agent=kimi&theme=light&cwd=/abs/path`). The handshake token is required; data lives under `~/.acpira/harness` unless `--home` is given; hello `agents` from the page is ignored. Build first; the settings live in `localStorage`
- `pnpm typecheck` — two tsconfigs (`tsconfig.webview.json` covers `src/webview` + `src/shared` + the LAB in `src/lab` / `lab`; `tsconfig.host.json` the host; shared options in `tsconfig.base.json`); the root `tsconfig.json` is a solution file with `references` only, do not add `compilerOptions` to it. A source directory outside both `include` lists is neither type-checked nor alias-resolved by the IDE
- `pnpm test` — vitest; `test/fake-agent.ts` is a fake ACP agent built on the SDK that feeds events to `AcpSession` tests. Suites start it through the `node_modules/.bin/tsx` wrapper, which relays SIGTERM to the real node; a test that SIGKILLs the agent must spawn `process.execPath --import tsx/dist/loader.mjs` directly (`test/AgentProcess.test.ts`), or the kill hits the wrapper and the fixture lives on as an orphan (`ps -eo pid,ppid,command | awk '$2==1 && /fake-agent.ts/'` should print nothing after a run)
- `pnpm probe grok [--auth] [--api-key-env VAR] [--import-local] [--image PATH] [--link PATH] [--embed PATH] [--elicit] [--wait MS] [prompt]` — run `initialize` + `session/new` (+ one prompt, optionally with an inline image / `resource_link` / embedded `resource` block) against a CLI without VS Code; `--elicit` advertises form elicitation and prints / auto-answers `elicitation/create`; `--wait MS` keeps the process alive after the last response, which is where `available_commands_update` arrives (Grok / Kimi send it after `session/new` returns, Devin during). Use this first when debugging protocol issues
- `pnpm exec tsx --tsconfig tsconfig.host.json scripts/probe-agent-host.ts <agent> [--attach] [--shell]` — the same path the webview takes (`SessionManager` → `AcpSession`) against a real CLI: new session, controls, one prompt, optionally a dropped text attachment and a shell command, permission cards answered like a click; `scripts/probe-opencode-host.ts [--model provider/model]` adds OpenCode's mode / effort switching, a two-file write and the native-session import round trip on a second manager (`--model` when the CLI's default route is down — OpenCode retries a 503 silently, so a first prompt that never returns is the gateway, check it with curl before suspecting the host). Both spend real model calls; give the CLI a temp store (`DSH_HOME`, `PI_CODING_AGENT_DIR`) where it has one
- `pnpm exec tsx --tsconfig tsconfig.host.json scripts/probe-subagents.ts <agent> [--air] [--no-caps] [--import-local] [--cmd "<command line>"] [--wait MS]` — raw-ndjson subagent probe (what an agent really emits, SDK validation bypassed) and `scripts/probe-subagents-host.ts <claude|devin>` — the same through `SessionManager`; both spend real model calls and leave their logs / temp stores in place for inspection
- `pnpm package` — build a `.vsix`

## Architecture

- `src/shared/transcript.ts` — normalized transcript shape, the single contract between host and webview; `SessionView` is the full state pushed to the webview
- `src/shared/protocol.ts` — `HostMsg` / `WebviewMsg` message contract; `src/shared/appearance.ts` — appearance axes
- `src/host/platform.ts` — `HostPlatform`, what a host application provides: environment facts (`cwd`, `home`, `hostLanguage`), settings storage (`readSetting` / `writeSetting` / `onSettingsChanged`), `onWindowFocus`, and IDE actions that only take resolved arguments (`openResolvedFile(absPath, line1)`, `openPlanDocument({ path } | { markdown })`, `openExternal` (already allowlisted), `revealInOS`, `openInEditor(sessionId?)`, `runInTerminal(title, command, args, env?)` with `null` env values meaning delete, `toast`, `searchFiles`), plus an optional `legacy` tree to migrate. Nothing in it imports `vscode`
- `src/host/runtime.ts` — `createHostRuntime(platform)` is the single composition root (registry, `FileVault`, `AccountStore`, `AccountManager`, `TranscriptStore`, `SessionManager`, `SettingsCenter`, `migrateOnce` when the platform declares a legacy source, `setHostLocale`); it subscribes to the platform's settings / focus events (appearance → push to views, `agents` → registry swap, `hiddenOptions` → `emitHidden`, anything else → `settings.emit`) and hands out one `BridgeCore` per view through `attachView` / `detachView`. Never re-create this wiring in another entry point — the VS Code extension and the sidecar both call it
- `src/host/bridgeCore.ts` — `BridgeCore`, one per view: routes `WebviewMsg` (`ready` → `init`, `openFile` resolved against the session's `cwd`, `openPlan` through `manager.planDocument` + `stat`, `openExternal` behind `isSafeExternalUrl`, `openPath` → reveal / open, `searchFiles` always answered, `editTurn` results, settings page requests, the rest to its `SessionViewer`) and pushes changes back through `HostMsgBatch` (30 ms coalescing, idle sessions flush at once). Transport-agnostic: `post` and `blobBase` come from whoever created the view. Verify with `test/hostRuntime.test.ts` (fake platform)
- `src/host/vscodePlatform.ts` — `VscodePlatform`: the `HostPlatform` over the vscode module (configuration, terminals, `vscode.open` with a 0-based `Range`, `revealFileInOS`, the `acpira.openInEditor` command, `WorkspaceFiles`, the `globalStorage` / SecretStorage legacy source). `src/host/files.ts` (`findFiles` index) stays vscode-specific behind it
- `src/host/extension.ts` — `activate`: builds `VscodePlatform` + `createHostRuntime`, registers the activity-bar WebviewView, editor WebviewPanel and commands; `src/host/bridge.ts` — `WebviewBridge`, the vscode.Webview wrapper (HTML + CSP + `asWebviewUri`, `postMessage`) around a `BridgeCore`. Only these two, `vscodePlatform.ts` and `files.ts` import `vscode`
- Sidecar (`src/host/server.ts` → `dist/host-server.cjs`, not `external: vscode`, so a stray import fails the build): the same runtime behind an ndjson envelope channel for shells that are not VS Code (the IntelliJ plugin). `src/shared/sidecar.ts` is the wire contract (`SIDECAR_PROTOCOL_VERSION`; shell → `hello` / `attachView` / `detachView` / `webviewMessage` / `platformResponse` / `platformEvent` / `shutdown`; sidecar → `helloOk` (with `sessionsDir`, the shell serves blobs from it) / `helloReject` / `hostMessage` / `platformRequest` / `shutdownOk`). `hello` carries the shell's `capabilities` (the `PlatformRequest` methods it implements), the IDE env (`cwd`, `hostLanguage`, `blobBase`) and a flat `acpira.*` settings snapshot — the shell owns the settings store; `writeSetting` is an RPC to it and `settingsChanged` events bring the new snapshot back. `sidecar/SidecarPlatform.ts` is the `HostPlatform` over that channel (RPC methods in `PLATFORM_RPC_METHODS` await a `platformResponse`, 30 s timeout, all pending ones fail on shutdown; the rest are notifications; an undeclared capability falls back — `searchFiles` walks the workspace with `nodeFiles.ts`, `runInTerminal` becomes an error toast with the command line — or is logged). `sidecar/SidecarServer.ts` is the per-wire state machine: a version mismatch answers `helloReject` and exits 2; control messages run strictly in order while a view's `WebviewMsg`s are dispatched in order but never awaited (a `send` resolves at turn end, `stop` must not queue behind it); lines that are not JSON envelopes are logged to stderr and skipped; EOF on stdin still honours the lines received before it (a shell that writes `shutdown` and closes gets `shutdownOk`). stdout is envelopes only: `console.log` is redirected to stderr at startup and agent processes are spawned with pipes. `--ws [port]` runs `sidecar/ws.ts`, a dependency-free HTTP + WebSocket server for the browser harness (one `SidecarServer` per connection; `/webview/*`, `/host-preview/*`, `/blobs/*` served with root confinement). Verify with `test/hostServer.test.ts` (spawns `tsx --tsconfig tsconfig.host.json src/host/server.ts` — plain `tsx` cannot resolve `@shared/*` because the root tsconfig has no `paths`) and by chatting in `pnpm harness`
- `src/host/SessionManager.ts` — session hub (live processes, summaries); all webview actions enter here; must not import `vscode`. The active session is per viewer (`SessionViewer`, one per webview via `manager.attach(initial)`), so the sidebar and any number of editor tabs each show their own conversation over the shared list and process pool; `session` events go only to viewers showing that session, global events to all. `dropEmptyCurrent` leaves a session another viewer shows alone; `deleteSession` re-homes every viewer that was on it. The single-view API (`activeId` / `active()` / `handle()` / `newSession()`) is a lazily created default viewer for tests and scripts. `acpira.openInEditor` opens a fresh session unless given a session id; `acpira.openInNewWindow` opens the same tab then moves it into a fresh auxiliary window (`workbench.action.moveEditorToNewWindow`)
- `src/host/acp/` — `AgentRegistry` (built-in grok / devin / kimi / opencode / dsh / pi + user-defined via `acpira.agents`, binary probing), `AgentProcess` (spawn + ndjson + `acp.client`), `AcpSession` (state machine: start → resume | load | new → ready, with auth_required / readonly / error states), `normalize.ts` (`session/update` → blocks, pure functions)
- Launching: `acp/launch.ts` is pure and unit-tested from macOS. `resolveExecutable` requires the execute bit on POSIX; on win32 it tries the bare name then every `PATHEXT` suffix (as given and lower-cased) and requires a regular file (a PATH directory named like the command must not resolve). `spawnSpec` routes `.cmd` / `.bat` through `ComSpec` `/d /s /c` with cross-spawn's escaping and `windowsVerbatimArguments` — not yet run on a real Windows machine. `AgentProcess.spawn` bounds `initialize` with `INIT_TIMEOUT_MS` (30 s, `opts.initTimeoutMs` for probes) and kills the child on timeout; `KILL_GRACE_MS` is 5 s (DSH's own teardown window). `AgentDef.requires` names helper commands that must also resolve (Pi: `pi-acp` spawns `pi`); the ones not found land in `AgentInfo.missing` and on the settings page's install description. `AgentDef.controls.ignoreModes` hides an agent's protocol modes and drops its `current_mode_update`s (pi-acp advertises its thinking levels both as modes and as `thought_level`). `AgentDef.prompt.imagesRegardless` is the per-agent override for a lying `promptCapabilities.image` (Grok). Custom agents get the same fields (`requires`, `ignoreModes`, `prompt`). Verify with `test/launch.test.ts`, `test/AgentRegistry.test.ts`, `test/AgentProcess.test.ts`
- Prompt staging follows the agent's advertised `promptCapabilities` (`attachments.ts` `PromptCaps` / `promptCapsOf(init, def)`, threaded into every `preparePrompt` call: live prompt, queue staging, edit rebuild, `historyContext`): `embeddedContext: false` turns a dropped text attachment into a `text` block bracketed by `[Attachment: <name>]` / `[End of attachment: <name>]` (the blob is still saved); `image: false` drops image drafts and image files with a `host.imageUnsupported` problem unless the agent declares `imagesRegardless`. DSH and pi-acp advertise `embeddedContext: false` and reject embedded `resource` blocks. Verify with `test/pastedText.test.ts` and the `FAKE_PROMPT_CAPS=strict` cases in `test/AcpSession.test.ts`
- Tool content is a list: `ToolCallBlock.contents?: ToolContent[]` holds every renderable item of a `tool_call_update` in wire order (a diff per `diff` item, one merged text per run of `content` items) whenever there is more than one; `content` stays the primary item (a diff wins over text) so records written before the field render unchanged, and `diffStat` sums every diff. `ToolCall.tsx` stacks `contents` with each diff under its own `source.path`; `Terminal.tsx` joins the texts. `terminal` items carry no body of their own: pi-acp streams bash output through `_meta.terminal_output.data` deltas and `_meta.terminal_exit.exit_code` (a non-zero code appends `exit code N`), which `mergeTool` folds into the text content; a bare terminal item from an agent that expects a client terminal keeps the `host.terminalNotWired` note. Permission requests are low-fidelity: OpenCode's `session/request_permission` embeds a `toolCall` with `kind: 'other'`, the parent directory as `title`, and both the file and its directory as `locations`, racing the real `tool_call_update`; `permissions.ts` `permissionToolUpdate` applies it only as an upgrade to an existing block (never `other` over a specific kind, locations only when there are none, title / rawInput only without a target), the whole thing when no block exists yet (Devin / Kimi plan approvals). OpenCode's `write` completes with text only (`rawOutput.output` "Wrote file successfully.", `metadata.exists: false`); `NormalizeState.pendingWrites` remembers the in_progress `rawInput.content` per tool id and, on that evidence of a new file, synthesizes an all-add diff as the primary content (an overwrite keeps the receipt text — an all-add diff would lie). Verify with `test/normalize.test.ts` and the `tool-downgrade` / `tool-downgrade-late` cases in `test/AcpSession.test.ts`
- Native session import: the history list's Import button (`chat/SessionList.tsx` `ImportSessions`, `Import` icon on the filter row) asks the host for an agent's own sessions (`WebviewMsg listNativeSessions` → `SessionManager.listNativeSessions` → `acp/nativeSessions.ts`: a throwaway spawn runs `initialize` + paged `session/list { cwd }` and dies — never `session/new`, since OpenCode / DSH / Pi all persist a session on creation) and answers `HostMsg nativeSessions` with `NativeSessionInfo[]`, `localId` set for sessions a record already holds (`SessionSummary.acpSessionId`; summaries written before the field are back-filled from their record once and marked `touched` so the index write keeps it). `importNativeSession` creates a record with `acpSessionId`, `importPending: true`, `importedFrom`, and starts it: `openSession` then tries `session/load` before `session/resume` so the native history replays into the empty transcript (`sealReplay` closes the streamed blocks and stamps `stop: 'end_turn'`), a 'gone' answer becomes `host.importGone` (error + Retry, never a silent `session/new`), and an import that resumed without replay (DSH has no `load`) gets the `host.importNoHistory` toast. Picking an already-imported row selects its record. Verified end to end against OpenCode 1.18.15 with `scripts/probe-opencode-host.ts`; `test/SessionManager.test.ts` covers list / import / dedupe with the fake's `FAKE_SESSION_DIR` store
- Subagents are first-class nodes, never mixed into the parent transcript: `src/shared/subagents.ts` (`SubagentSummary` on `SessionView.subagents`, `SubagentRecord` with the child's own `turns` on `SessionRecord.subagents`) and `src/host/acp/subagents/` (`SubagentTree` per `AcpSession`: nodes with their own `NormalizeState`, peer-id indexes, orphan buffer 8 ids × 64 updates, lifecycle; `wire.ts` the extension decode). Three visibility tiers, each verified on the wire with `scripts/probe-subagents.ts` (raw ndjson, nothing validated away) and `scripts/probe-subagents-host.ts` (the `SessionManager` path): `session` — claude-agent-acp 0.78/0.79 streams the child's own updates under its own session id after `subagent_spawned` / `subagent_state_update` on the parent (the RFD #1992 `subagent_update` upsert is decoded too; the RFD is still open and its wire shape changed 2026-09-15), gated by `_meta.jetbrains.air = { version: 1, capabilities: ['nativeSubagentSessions'] }` because the adapter's SDK strips the draft `clientCapabilities.subagents` field (both are advertised at `initialize` unless `AgentDef.subagents === false`; Devin / Kimi / Grok / OpenCode accept the unknown key and ignore it); `nested` — Devin 3000.11.1 announces with `tool_call_update` `_meta['cognition.ai/subagent_started'] { agentId, title, task, profile, model, depth, isBackground }` whose `toolCallId` is the agentId (never a root tool row), ends with `subagent_completed { agentId, success, summary }`, and marks the child's own tool calls and `usage_update`s with `subagent_context.parentAgentId` (a child usage must never land on the root ring); `run_subagent` rows link by title+task and get `subagentId`, `read_subagent` rows stay visible as `verb.awaitSubagent`; Claude without AIR uses `claudeCode.subagent` + `parentToolUseId` the same way; `receipt` — Kimi 0.41.0's `Agent` tool with `rawInput { prompt, description, subagent_type }`, result text only. SDK 1.4.0's `zSessionUpdate` is a closed union, so `AgentProcess` rewrites extension kinds into `session_info_update._meta['acpira/extension']` before the SDK parses them (same handler ⇒ wire order kept; a custom method would dispatch through another handler index). Lifecycle follows the RFD: a child still `running` when the parent prompt returns, the connection ends or the session is disposed becomes `disconnected` / `stateSource: 'local'` (never failed / cancelled); a later agent terminal replaces it, nothing revives a terminal node, and content that arrives after the terminal word drops (usage metadata still applies); `session/cancel` with the child id only when `controls.cancel`. Permission / elicitation requests route by `sessionId` into the owning transcript (`PermissionGate` / `QuestionGate` `stateFor`, which answers `cancelled` for a terminal node), mirrored on `SubagentSummary.permissions` / `question` so the root view shows them with provenance; a child going terminal (`SubagentTreeDeps.onTerminal`) or being cancelled — descendants included — answers its pending requests `cancelled`, and `QuestionGate.settle` pins a card to its owning transcript because block ids restart at `q-1` on every reopen. Routing invariants: `toolOwner` indexes only nested / receipt children (a `session` child's updates arrive under its own session id; registering them would hijack a same-named root call), Devin `subagent_started` / `subagent_completed` read before `subagent_context` routing (a nested child's spawn carries its own parent link), and updates naming a not-yet-announced owner buffer under `agent:<id>` / `tool:<id>` orphan keys rather than leaking onto the root. A launch receipt links through three paths (`toolResponse.isAsync`, `pendingLaunches`, the child's `parentToolUseId`) that share `sealLaunchReceipt`, and a nested / receipt node already sitting on the same root call is upgraded in place (`adoptCallNode`) rather than duplicated. `SubagentRecord.rev` persists so a restore never hands the webview a lower revision than it holds. The webview keeps the parent light (`chat/subagents/SubagentGroup` two-line rows in the announcing turn, delegation rows with `subagentId` hidden from the process fold), opens `SubagentInspector` docked at ≥ `--subagent-dock-min` or as a full-width overlay over the inert thread (scroll + draft survive), and subscribes to one child transcript at a time (`observeSubagent` → `HostMsg subagent`, per viewer, `msgBatch` keyed per child); the inspector never offers prompt / edit / retry / fork, and the child's Working row uses a static icon — the root turn owns the only Orb. `lab/subagents.preview.html` holds the five acceptance scenarios; `test/subagents.test.ts` + `test/subagentState.test.ts` cover routing, lifecycle, persistence and the pure UI helpers. Observed, not yet explained: one claude-agent-acp run left the launch receipts unlinked (no `toolResponse`, node without model) — the `parentToolUseId` link path exists for that case; capture the wire with `probe-subagents.ts --air` if it recurs.
- Empty ACP prompt completions: a normal message acknowledged with `end_turn` but no blocks or only whitespace text becomes a persisted, retryable `empty_response` turn error. The message explicitly says the CLI supplied neither a reply nor error details; no upstream cause or JSON-RPC code is invented. Slash-command receipts, automatic compaction, thought/tool output, refusal and cancellation retain their existing handling. Verify with the empty-completion cases in `test/AcpSession.test.ts`.
- Agent availability is live, never a reload-time snapshot: `AgentRegistry.probeAll` / `resolveBinary` re-verify cached paths (`access X_OK`) and notify `subscribe`rs when the available set changes; `SessionManager` re-pushes `agents` on that, polls every 10 s while `registry.missing()`, and `reprobe()`s on webview `ready` and window focus (`onDidChangeWindowState`). The first `probeAll` only sets the baseline (returns false). `AgentInfo.install` (`AgentDef.install` posix / windows / docs, custom agents via `acpira.agents.<id>.install`) feeds the settings page's install section (copy, `installAgent` → `bash -c` / `powershell -Command` in a terminal, docs link); the webview drops an agent's cached inventory when its `available` flips so the facts card rescans. Verify with `test/AgentRegistry.test.ts` and the SessionManager poll test
- The settings page's option lists (models / thinking) only ever come over ACP: `manager.knownControls(agent)` is the newest session's `configOptions` (live or stored), so a hand-edited CLI config (a model added to `~/.kimi-code/config.toml`) is invisible until a fresh process runs `session/new`. The page's refresh button (`refreshAgent` → drops both caches → the `controls` effect re-requests with `fresh: true`) makes the host run `manager.probeControls(agent)`: `acp/probeControls.ts` spawns a throwaway process (`initialize` + `session/new`, 20 s timeout, killed in `finally`), the result is cached in `probed` and preferred by `knownControls` / `runtimeInfo` until the next real session of that agent starts, the agent's warm slot is invalidated (`pool.invalidate(agent)`) and re-warmed so the next new session never borrows a process spawned before the change, and `bridgeCore` re-posts `inventory` after it so the facts card shows the probe's version. Failure (no binary, auth, timeout) falls back to the last known list. Verify with the `probeControls` cases in `test/SessionManager.test.ts` (`FAKE_MODELS` on the fake agent)
- `src/host/store/dataDir.ts` — `ACPIRA_HOME` or `~/.acpira`; `migrateOnce` merges a legacy `globalStorage` / SecretStorage tree in once per source (`.migrated` is JSON `{ sources: [...] }`; a legacy timestamp marker means "one unknown source", and a source whose UUIDs already exist in the destination is that one). VS Code and Cursor each have their own `globalStorage` but share `~/.acpira`, so the second IDE to start still brings its sessions / accounts along; nothing in the destination is overwritten and `index.json` is not copied (the store rebuilds it). Old files are left in place
- `src/host/store/TranscriptStore.ts` — `~/.acpira/sessions` holds `index.json` + `<id>.json` + `<id>/` (attachment blobs, content-hash names) + `trash/` (soft-deleted records during their undo window); record writes are debounced, every file is written tmp + rename. The directory is shared by every extension host (each VS Code / Cursor window), so `index.json` is a cache, never the truth: `syncIndex(mine, own)` re-reads it and reconciles with the record files (a file no index knows is loaded and summarized, an id without a file drops out; `mine` wins only for `own` ids — live or just patched — the disk for the rest), and `SessionManager` runs it debounced after changes plus `refreshIndex()` on webview `ready` and window focus so two windows converge without a reload. Record writes are chained per id (`inflight`) and `syncIndex` / `trash` / `remove` wait for writes already on their way: the save and index debounces are both 400 ms, so a fresh session's first write was regularly still mid-rename when the reconcile listed the directory, and the manager took its own brand-new session for one "deleted in another window" (toast + rehome on every new session). Verify with the two-store / two-manager tests in `test/TranscriptStore.test.ts` and `test/SessionManager.test.ts`
- Attachments: the webview turns pastes / drops / `@` picks into `Draft`s (`webview/chat/drafts.ts`, `Mention.tsx`) and sends them with the prompt; `host/acp/attachments.ts` (`preparePrompt`) writes images and dropped text to the session's blob dir and builds the `ContentBlock[]` — text → inline `image` → embedded `resource` (uri = blob path) → `resource_link` (Explorer / `@` files; image files among them are read and sent as `image`). The turn keeps `Attachment`s (blob name / uri only); the webview loads blobs from `InitState.blobBase` (the sessions dir as a webview URI, added to `localResourceRoots`). `@` search is `host/files.ts` (`findFiles` cached 15 s, fuzzy-scored host-side) answered over `searchFiles` → `files`. Inline editors (history / queue) pass their kept attachments as bare `EditAttachments` items through `ComposerProps.edit.attachments`; `DraftChips` renders them at the head of its own wrapping row (`before`), so kept and newly pasted attachments share one row instead of stacking two
- Slash commands are the agents' own: `available_commands_update` → `normalize.ts` (`SlashCommand { name, description, input?: { hint } }`, each update replaces the whole list, an empty one clears it) → `SessionView.commands` → `App` → `ShellProps.commands` → `composerProps.commands` (so the inline history / queue editors get the same list) → `chat/Slash.tsx` (list + hook; the pure `commandAt` / `completeCommand` / `matchCommands` / `commandHint` / `commandMarks` live in `chat/slashCommands.ts`, DOM-free so the host tsconfig can type-check their test). A `/` at the start or after whitespace with the caret inside its token (`commandAt`, the same shape as `mentionAt`, so a command / skill can also be called up mid-sentence like Cursor's `/`) opens the list (`matchCommands`: name prefix, then name substring / description word start, agent order within each tier) in the `chat/Completion.tsx` shell the `@` mention list also uses; ↑↓ move, Tab completes that token in place to `/name ` (`completeCommand`), Enter completes unless the token already is the active command (then it sends), Esc parks it by the token's `start`. Picking only edits the text — the command goes out through the ordinary `send` → `preparePrompt` → `session/prompt` and the agent runs it; the list is discovery, never a whitelist: no hit means the slash is plain text (`/tmp/file.ts` sends as typed), and nothing is rewritten, expanded or intercepted host-side (Acpira has no slash commands of its own; `/compact` for auto-compaction is the agent's). `commandHint` shows `input.hint` as a faint line under the text while the command the text ends with still has empty arguments. `PromptInput`'s mirror paints every advertised `/name` token with the accent mark — leading or mid-sentence alike (`commandMarks`, the same boundary rules as `commandName`, so a path / partial name / punctuated tail never lights up; Cursor and Codex paint mid-sentence commands the same way) — while `turn.command` in the transcript stays a leading-token receipt. `AcpSession.openSession` clears `state.commands` before `session/new` (never after — Devin advertises during the request), resume / load keep the persisted list until the peer replaces it; `sessionEdit` does the same for its fresh session. Skills the CLIs expose show up here under their own naming (Grok `/release`, Kimi `/skill:release`, Devin `/agents:release` / `/claude:release`); the settings inventory scan (`inventory.ts`) is a read-only listing and is not turned into commands. Verify with `test/slash.test.ts`, the resume / gone cases in `test/AcpSession.test.ts`, and `pnpm probe <agent> --wait 4000`

## Protocol gotchas

Hard-won facts about the ACP implementations we drive; check here before assuming the spec:

- Historical message editing uses a fresh `session/new` plus retained transcript context because standard ACP has no turn-addressed rewind. Never truncate only the UI while keeping the old peer context, and never replay historical tool actions as prompts. `AcpSession.editTurn` stages attachments and exact model/config/mode selections before replacing the local continuation; failed edited-turn retries rebuild that context. Workspace files are not rolled back. Oversized full-history editing automatically continues in the same native session with only the edited prompt and selected attachments; the full transcript remains intact. The editor keeps a single send action. `intent: 'continue'` on `EditTurnRequest` requests that path explicitly. Verify Grok / Devin / Kimi capability boundaries with `scripts/probe-edit-turn.ts`.

- Cross-agent oversized-edit verification on 2026-09-15: `pnpm exec tsx --tsconfig tsconfig.host.json scripts/probe-edit-turn.ts grok --oversized --model=asgard` and the equivalent `kimi --oversized --model=asgard/kimi-k3` both kept the native session, complete displayed history, retained context marker, and kept/new text attachments while changing reasoning to low. The probe adds approximately 1.09 MB of synthetic UI-only history after `/compact` to exercise the host byte limit; it is not a native model-window load test. Kimi 0.41.0 explicitly reported compaction completed. Grok 1.0.18 returned `end_turn` with no status/text and unchanged context usage in this small session, recorded as `rpc-completed-without-status`, not proof that compaction reduced the context. Adapter regressions in `test/AcpSession.test.ts` additionally cover Grok synthetic plan/yolo modes and Kimi background completion; `test/compaction-queue.test.ts` and `test/grok-usage.test.ts` cover their queue and usage differences.

- Resending an unchanged historical message after only identical empty failed attempts is a retry: `sessionEdit.unchangedFailedRetry` keeps the native session and sends only that message. Text and attachments must be unchanged and every discarded agent turn must be an empty error, but the retry may carry changed model/config/mode selections, applied natively through `applyEditSettings` on the live session rather than by rebuilding. This preserves native compaction; reserializing a multi-megabyte UI transcript for a plain retry exceeded Devin's model window. Genuine edited turns still rebuild their context.

- Model identity must preserve the ACP option ID and source/group identity, independently of the display name. Kimi's `kimi-code/k3` and `asgard/kimi-k3` both advertise `K3`; merging them by name routes selection to the first provider. Grok advertises custom config aliases such as `asgard` without source metadata, so `host/acp/modelSources.ts` reads custom endpoint declarations and `shared/modelSources.ts` annotates the options. Keep ACP select groups through normalization. New agent integrations must verify official/custom same-name selection, independent hiding, restoration, and config updates; unknown sources stay unclassified, and ambiguous duplicate parameter tuples remain separate by their original option IDs. Devin's genuine effort/Fast/1M variants still group normally.

- Devin 3000.10.21 sends 420 flat model options, 210 of them Fusion pairs named `Fusion (<lead> + <sidekick>)` (`fusion-gpt-6-astra-high-fast-sidekick-swe-2-medium`, description "Pairs frontier intelligence with cost-efficient execution"). Dimensions: 4 leads × Low–Max × 6 sidekicks (their own effort baked into the label) × Fast, not a full product (Luna / Sol sidekicks pair with a subset of leads). Fast is one pair-level switch — `-fast-` after the lead, `-priority` on the sidekick — and the name marks it on whichever side supports it, so a Fable lead (no Fast of its own) still reads Fast off its sidekick. `shared/models.ts` `parseFusionName` folds them into one `Fusion` family (`brand: devin`, `ModelVariant.lead` / `sidekick`, `ModelFamily.fusion.leads` / `sidekicks`); the ambiguity detector's tuple includes lead + sidekick or every pair would look duplicate. ## Conventions

- Official CLI quota monitoring is read-only: `host/accounts/local.ts` reads Grok `auth.json` and Kimi `credentials/kimi-code.json` / `device_id`, or an explicit `KIMI_CODE_API_KEY`. `LocalAccounts` publishes safe metadata through `AgentInfo.localAccount`; it never imports a switchable account or changes a session's credentials. - Motion decisions (after the rules distilled at [animations.dev](https://animations.dev/)): gate by frequency before designing anything — keyboard-initiated actions (slash / `@` completion, the command-style pickers, shortcuts) get no animation at all, elements seen tens of times a day stay near-imperceptible, occasional UI (menus, dialogs, toasts) gets standard motion, and the delight budget is spent only on rare / first-time moments. A new animation must name its purpose (feedback, spatial consistency, state indication, preventing a jarring change) or it is not built. Animate `transform` / `opacity` only, extend the existing `--dur` / `--enter-*` tokens and curves instead of adding a parallel system, prefer `transition` over `keyframes` for anything rapidly re-triggerable (keyframes restart from zero), enter from `scale(0.95)` + `opacity: 0` never `scale(0)`, and ship `prefers-reduced-motion` plus `@media (hover: hover) and (pointer: fine)` gating with the animation, not after. When tuning, work down this order before reaching for new values: delete the animation → shorten duration / distance → fix the easing → fix the origin → make it interruptible → move it to the GPU.
