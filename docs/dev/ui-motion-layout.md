# UI conventions: motion and layout

Orb, motion, rails, sticky prompts, scrollbars, to-do presentation, folding, appearance axes and rendering preferences. Component rules are in `ui-conventions.md`.

- A retired empty `CodexFold` cancels its reply-stack sibling gap on `Collapsible.Root`, the direct flex item. A negative margin on the inner head clip cannot cancel that outer gap and leaves the stopped outcome farther from the user prompt than from the composer. Keep the compensation on the root and delay it with the head collapse. Verified with the real Shell in `lab/stopped-spacing.preview.html` (2026-09-30; browser layout, no CLI calls): live stop and restored cancellation both have 24 px above/below the outcome at airy density, compact has 12 px, and 380 px width plus motion-off preserves the same spacing.

- The turn's top-level activity owns the only `Orb` (thinking-orbs), with a stable Working label throughout active execution, independent of folding and the latest tool. Initialization reuses the Orb with its built-in `connecting` state; turn activity uses `breathing`. The connecting label stays stable and the status row fades in together. Approval and question waits use static icons and their waiting labels. Expanded thought rows keep static icons, show Thinking with shimmer while streaming, and retain expandable text after completion. Empty streamed text adds no second waiting indicator. In-progress tool rows use the same static icon as their completed state plus a shimmer on the verb (`ui/Shimmer`, or `RowLabel shimmer`; pass a real boolean — an explicit `undefined` takes the active default) — never an Orb. The Orb is deliberately outside the motion switch: it is the one "still working" signal and a 20 px canvas on its own layer, so `motion: none` leaves it turning (the library itself goes static under the OS reduced-motion preference). The one spinner is the session list's `working` state (`LoaderCircle` + `animate-spin` in the time slot): a list item has no verb to shimmer, and a dot reads as "unread". Like the Orb it is a live status signal, so it carries `.live-spin` and `motion: none` leaves it turning (the OS reduce-motion query still stops it). The `unread` state is a `size-unread-dot` (7 px, one more than the 6 px waiting / error dots) `bg-fg-strong` dot with `.unread-halo`, a copy of the dot rippling out to 2.6× and fading every 2 s (not the accent: the default brand amber is indistinguishable from waiting's `warn`): `SessionManager::process_change` marks a session unread on its running → idle edge when no viewer shows it, and `set_active` / `attach` on that session clear it (in memory only, not persisted; a viewer counts as watching even while its panel is hidden). Working / waiting / error outrank it. Unlike the ring it is not exempt from the kill switches, so `motion: none` and reduced motion leave it lit and still (the halo copy rests at opacity 0, so dropping its animation hides it). Colour, size, ring size and motion were picked as D3-E2-G2-F2 in a LAB bench over the production SessionList (2026-09-30): a breathing dot (opacity 20% / scale 70%, and a milder 50% / 85%) read as weaker than the ripple, and focus blue was dropped for the plain foreground. Every mark sits in one `size-3` centred slot with a hover label (the ring itself is `size-2.5`, stroke 2.5: at the slot's full 12 px its arc outweighed even an 8 px dot), and the time after it is a right-aligned column (`min-w-session-time`, sized per render from the longest listed time by `timeWidth`): with a free-width time the marks drifted with each time's length (`3:45` vs `21:08`). `--session-time` is set on the list element and read by the utility directly, since a `:root` token wrapping it resolves to `auto` before the list sets it. Alignment checked in headless screenshots of the production SessionList (zh / en times, dark / light, 2026-09-30). Streamed prose and thought text are paced by `useSmoothText` (`chat/streamMotion.ts`): the visible text advances at the stream's measured throughput (a time-weighted EMA of characters per ms that counts stalls too), so agents that push 30–60 characters twice a second read as one continuous stream, and a big block after a stall plays at the running speed instead of all at once (draining each chunk within the next arrival gap burst 8× the median speed there); lag beyond `lagMs` (500 ms) raises the target speed proportionally, `maxLagMs` (1.5 s) is a hard floor, the actual speed eases toward the target over 180 ms, the tail flushes within 220 ms once the stream ends, a non-appending change (edit, replay) and motion-off show at once, and cuts land on grapheme boundaries and never right after markdown punctuation / whitespace / an ordered-list number (while streaming, a received tail that ends on syntax is held back): streamdown's animate plugin renders as many characters of a block as it already animated with a 0 ms duration, so a transient literal (`- *`, `**`, `1`) made the real text replacing it appear without an entrance. On top of that each grapheme gets a 180 ms opacity-only fade on inline spans (`sd-acpGlyph` in `motion.css`, `--stream-char-duration`), with no stagger. The duration is fixed in CSS rather than read from `--sd-duration`: streamdown re-renders the whole live block every pass and stamps already-animated characters 0 ms, which snapped mid-fade glyphs to full while an earlier block, no longer re-rendered, kept fading — text looked out of order (verified with the `整段砸下` scenario: 57 characters out of order before, 0 after). Inline spans keep CJK line-breaking rules; the former inline-block glyphs let a full stop start a line. The pacing was chosen in `lab/stream-pace.preview.html` (same chunk schedule, five configs side by side); the previous per-chunk cascade (22 ms stagger, 320 ms backlog, 380 ms entrance) stalled for ~1.2 s over a 4 s reply from a slow-chunk agent. Live row slots enter in sequence; restored history stays static. Rail growth is eased in JS by `ConnectedRail` (a CSS transition retargeted every frame stalls on the main thread), and motion-off / reduced-motion settings snap it instead. The stream and row animation rules live in `styles/motion.css`.
- Motion decisions (after the rules distilled at [animations.dev](https://animations.dev/)): gate by frequency before designing anything — keyboard-initiated actions (slash / `@` completion, the command-style pickers, shortcuts) get no animation at all, elements seen tens of times a day stay near-imperceptible, occasional UI (menus, dialogs, toasts) gets standard motion, and the delight budget is spent only on rare / first-time moments. A new animation must name its purpose (feedback, spatial consistency, state indication, preventing a jarring change) or it is not built. Animate `transform` / `opacity` only, extend the existing `--dur` / `--enter-*` tokens and curves instead of adding a parallel system, prefer `transition` over `keyframes` for anything rapidly re-triggerable (keyframes restart from zero), enter from `scale(0.95)` + `opacity: 0` never `scale(0)`, and ship `prefers-reduced-motion` plus `@media (hover: hover) and (pointer: fine)` gating with the animation, not after. If a trigger-anchored popover ever scales in, its `transform-origin` is Base UI's `var(--transform-origin)` (the trigger anchor), not center — modals are exempt. When tuning, work down this order before reaching for new values: delete the animation → shorten duration / distance → fix the easing → fix the origin → make it interruptible → move it to the GPU. Deliberate exceptions a reviewer must not "fix": row entrances exceed 300 ms by design, streamed text trails the received text by about 500 ms (continuity comes from arrival-rate pacing, not from long per-glyph entrances — lengthening the entrance again brings back the blurred leading edge), and the rail is JS-eased because retargeting a CSS transition every frame stalls the main thread — both measured, see `scripts/probe-fold-perf.ts`.
- Rail rule: indented disclosure bodies and tool result rows share `ui/ConnectedRail`. The line is measured from the actual icon strokes, ends with a short solid dot, and grows with streamed content. Its top end fades in from transparent over `--rail-fade` (14px in `tokens.css`, drawn by `.rail-segment::before` in `motion.css`): at full strength from the icon's last stroke it read as a thread pulled out of the icon. The fade is capped at 40% of the segment so the short icon-to-icon links of dense result lists stay visible. Picked over a 4px clearance at both ends (trimmed dense links shrank to stray ticks) and clearance + fade in `lab/tool-output.preview.html` (`?rail=stick|fade`, `&motion=none` for headless screenshots). Result rails stop at the final row before its output card. Full-width diff cards and process fold bodies get no outer rail. The command card is the exception (chosen as A3 in `lab/command-row-pick.preview.html`): it is indented to the label column (`Disclosure` default `indent` / `rail: 'body'`) and hangs from the row icon on the body rail, whose end dot lands on the card's bottom edge — the space after an open command (`mb-command-after`) sits outside the rail root for that reason. Thought text renders `trimEnd()`ed: models close thoughts with `\n\n`, and under `whitespace-pre-wrap` those blank lines push the end dot below the text (`lab/thought.preview.html` → `trailing`). The easing step (`railStep`) measures elapsed time with `performance.now()` at both ends and clamps it at zero: the rAF timestamp is the frame start, which on a busy main thread precedes the effect that scheduled it, and since an opening panel restarts that effect every measured frame, the negative interval compounded and drove `--rail-length` below zero — the line vanished and the dot flickered at the icon while the thought opened (reproduced in `lab/performance.preview.html` under 6× CPU throttling; no drop after the fix)
- User prompts (`chat/HistoryMessage`) stick within their exchange and have no hover actions — clicking the card opens the inline editor, which is also where the full text is copied from. Sent cards keep the same `--user-message-max` cap before and after sticking (`min(240px, max(40cqh, calc(3 * var(--text-1-lh))))`); short prompts retain their natural height. Long text always uses `overflow-y-auto` and a `scroll-fade` edge, preserving its inner scroll position when the conversation moves. Sticky positioning is CSS-only: no observer, folded state, height measurement or compensating spacer. Trailing blank lines are not displayed (`trimEnd`). The inline editor keeps its existing return animation. Verified on Chrome 153.0.8010.53 with the real Shell in `lab/history.preview.html?long`: 240 px before/after sticking at 900×820, 208.8 px at 380×720, inner reading position retained across sticking and sidebar hide/show, and edit cancellation restores the card. The `?long&images` fixture keeps the same cap with three image attachments; short prompts remain natural-height (46 px). This is browser layout behavior, independent of the agent CLI.
- Bottom follow (`chat/useBottomFollow.ts`, shared by `Thread` in `chat/Shell.tsx` and `SubagentInspector`'s session tab): a `ResizeObserver` on the scroller re-pins when the area above the composer grows, and the scroll listener decides the follow through `promptStuck.followsBottom` — only an upward scroll away from the bottom releases it. Scroll events arrive a frame late, so the one caused by a pin can read the gap left by a second shrink a few ms later (the connecting `Notice` appearing on an account switch, then the composer's chips changing); judging by gap alone released the follow and left the transcript tail under the notice. Reproduced in a Shell LAB page with two 60 px shrinks 1–12 ms apart. Re-arm only at the actual bottom (1 px rounding tolerance), not within a near-bottom zone: the former 48 px zone kept following after a 20 px wheel step away, so each streamed update snapped the view back before small steps could accumulate. Verified on Chrome 153.0.8010.53 with the real Shell in the LAB, 30 ms transcript updates and twelve 20 px wheel steps at 710 px and 380 px widths: no re-pins after leaving the bottom, monotonic downward scrolling, follow restored at the bottom, and both viewport shrinks still leave a zero bottom gap. Content also gains height with no transcript change: a slow `<img>`, a mermaid diagram (200 ms debounce, then an async render) and other async renders land after the mount pin, and with only the scroller observed a switched-back session stayed parked above its tail (the pin itself read a zero gap). A second `ResizeObserver` on the content box re-pins while following, but only until the user presses a pointer or key inside the scroller; the next pinning transcript change re-arms it. Observing the content unconditionally would move the view when a fold is opened by hand. Verified on Chrome 154.0.8037.58 with the real Shell in `lab/scroll-switch.preview.html` driven by `scripts/probe-scroll-switch.ts`: before the change a first mount left a 638 px gap and each switch back a 398 px gap; after it both end at 0 px, and opening the last fold while following leaves `scrollTop` unchanged (removing the pointer guard moves it by 58 px)
- Scrollbars are overlay-style everywhere: `scrollbar-gutter: stable` keeps layout still, the track is transparent, and the hairline thumb shows only while its element scrolls (`ui/useScrollReveal` on the shell roots stamps `data-scrolling` for 800 ms) or under the pointer — never on focus. `scroll-thin` is the 6px variant for lists and card text. A `scroll-fade` scroller (user prompt, thought, question body, to-do dock, terminal output) shows no vertical bar at all (`width: 0`): the masked edge already marks the overflow and the wheel still scrolls; a horizontal bar keeps its height. All scrollbar rules (including `.scroll-thin`, a plain class rather than an `@utility`) are unlayered in `base.css`: the host webview stylesheet paints `::-webkit-scrollbar-thumb` / `:hover` / `:active` with `--vscode-scrollbarSlider-*` unlayered, so a layered rule loses and every scroller grows a permanent grey bar. `lab/webview-defaults.css` replicates those host rules; import it in any LAB page that judges scrollbars
- Bottom dock rhythm: the floating plan dock (`PlanBar`, absolute over the thread) and every surface under the thread (`Questions`, `Alert`, `Notice` / `ExternalSessionNotice`, `Queue`, `Composer`) carry no outer vertical margin of their own; `ui/DockStack` puts `--dock-gap` between them and the plan dock's bottom padding is the same gap. The thread's tail clearance is `calc(var(--msg-gap) + <plan dock height>)` (`threadClearance` in `chat/Shell.tsx`), so the last message sits one message gap from the first dock surface with or without a plan; the former inline `paddingBottom` replaced `pb-msg` and left a row gap there (24 / 12 / 8 px under `airy` in one stack). The thread pads its right side by `--page` minus `--scrollbar` (`pr-page-gutter`), giving the stable scrollbar gutter back so prompts, cards and the dock share both edges; the island dock is `content-w + 2 × page` wide for the same reason. A finished reply's action row (`TurnActions`) keeps its height so hover never shifts the transcript, but stands in for the spacing around it: `-mt-gap` hugs the reply and an exchange ending in that row pulls the next one up to a row gap (`has-[…[data-turn-actions]…]` on the exchange section). Measured in `lab/dock-rhythm.preview.html` (real Shell, `?plan&question&queue`, `?idle`, `?editor`, `?density=compact`), Chrome via `lab-shot`
- To-do presentation separates history from the live dock: `chat/Plan` is a lightweight disclosure with a stable title, done/total and chevron; its entries expand to natural height without a card or current-task summary. `PlanBar` uses a two-level `PlanCard`: stable title/count on top, current task below while collapsed, replaced by the full `PlanEntries` list when expanded. The current task appears once per view. Only the dock list is height-limited and uses `useScrollFade`; each disclosure keeps its own state across plan updates.
- Process prose uses `--process-prose-gap` around action boundaries; consecutive tools retain `--process-row-gap`. Expanded process history stays in the conversation scroll flow, while thoughts retain their bounded viewport.
- Folding (`acpira.appearance.fold`, default `codex`): `codex` keeps one process fold per turn from the first moment of a live turn (chosen in `lab/live-head.preview.html` over a merged Thinking/Working head, a quiet thought row and the former separate Working row: a Working row above a sibling Thinking row read as the same status twice, and swapping it for the fold head at the first tool replayed its entrance). The fold follows the run: open while the turn works and while its reply is still drawing (`Prose` `onBusy`: received, paced out or fading in; the fold waited only for the last chunk before, and closed over a sentence still appearing), closed once both are done, however the turn was mounted: a live session opened mid-turn shows what it is doing (the former rule collapsed any turn first mounted with tools present, so switching to a running session showed a bare `正在处理 ›`). A turn with no process blocks shows the head only while running and retires it with a fade then collapse. The head keeps the Working label and Orb while running, including when expanded, and shows `用时 4 分钟 46 秒` after completion. Inside it (`acpira.appearance.autoExpand`, default `off`, the settings page's 自动展开过程细节 switch) the items follow the run too (`foldStates` in `chat/processGroups.ts`, driven by `CodexFold`'s `useProcessFolds`): the latest item (thought, search, read / edit group, command output, any tool card) is open while the turn works, a finished one closes once the next has started and it has been open `DWELL_MS` (900 ms, so a quick call never flicks open and shut), and a call still running alongside stays open. A lone edit never opens on its own: its body is a diff, too tall to open and close again as the next action starts (a multi-edit carries several); an edit group opens to list its files, its entries' diffs open by hand. When the turn's fold closes on its own, the rows inside hold still for `SETTLE_MS` (400 ms, the `--dur-close` close and a frame or two) instead of stacking a second collapse inside the first. A reader scrolled away from the bottom (`FollowContext`, the `useBottomFollow` pin) holds every automatic close, the turn's included, until they return. Items finished before the turn mounted count as long done, so opening a live session flashes nothing open. `off` keeps the rows closed and only the turn's fold follows the run. The rows read their state through `AutoFoldStore` (`chat/autoFold.ts`): `CodexFold` writes the whole map during its render and notifies after commit, and each row subscribes to its own item (`AutoFoldItem` names it), so a memoized row whose block did not change still hears its own fold and nothing else re-renders on a stream chunk; a context value would have re-rendered every row of the live turn. A manual toggle wins over every automatic state, the turn's and each row's, and is kept outside the component tree in `chat/foldMemory.ts` (turn keyed `<sessionId>:<turnIndex>:<startedAt>`, rows `<turn key>:<item id>`, module cache plus the webview's `setState`, 200 most recent entries), so an explicit choice survives a rebuilt message tree or a reloaded webview. Grouping (`groupProcess`, chosen as A2-B3-C3-E1-F2 in `lab/tool-grouping.preview.html`): consecutive reads form one group and consecutive edits another, running calls included so the group grows as the agent works; failed / cancelled calls, a completed read without a file reference and anything else stay on their own row, and a search is never grouped. The head is the verb plus the files it touched, two by name then a count (`已编辑 tokens.css、Turns.tsx 等 5 个文件`, the edit total trailing); read entries are the file rows with their ranges (each read listed, far-apart ranges never merged into one span that would claim the lines between), edit entries are one row per file with the first to last changed line (`Turns.tsx L535–549`) and its total, repeated edits of a file stacked in its diff. A single read is one row (`已读取 ConnectedRail.tsx L103–140`), a single edit names its span too. Entrances belong to the list, not to the row components: `ProcessBlocks` wraps every item in `EntranceOnce` under `item:<id>` (a group goes by its first call, entries by their first call too), so a single call that becomes a group keeps still and only the new entry fades in, and a remounted transcript (another session and back) replays nothing; per-component wrapping had left the new group rows and the fold head replaying on every remount (recorded per row with a MutationObserver in the LAB). Process prose and resolved question records stay inside at their chronological position (a record hoisted after the fold reads as if the answer arrived after every later action), trailing reply text and permission cards stay outside. ACP does not distinguish commentary from final text, so trailing text moves into history when another action arrives — but only a real action counts: thoughts and `plan` (to-do) updates after the last tool call do not end the reply (`splitCodexBlocks` `TAIL_PROCESS`), they join the end of the fold while every text after that action stays outside. Otherwise a summary followed by one more thought and a short coda collapsed to just the coda. In turns without tool calls only the trailing text run is the reply. Verify with `test/folding.test.ts`. Duration uses `AgentTurn.startedAt` / `endedAt`, never summed thought durations; older turns without timestamps show `已完成`. `cursor` folds only runs of read-only actions. Fold bodies are not indented
- Appearance axes: the combo code is positional (`encodeAppearance`), so new axes go at the end of `AXES`; baseline is `2011102003021001`. Only `motion` and `autoExpand` are exposed to users (settings → Appearance, a `Switch` each, over `setAppearance` → `acpira.appearance.motion` = `on` | `none`, `acpira.appearance.autoExpand` = `on` | `off`); the rest stay LAB decisions. `none` is kept as the off value so an existing "off" survives; the former `subtle` / `full` fail validation and fall back to the baseline `on`, which is what they meant
- User-facing rendering preferences are plain `acpira.*` settings (`theme` / `uiFontSize` / `codeFontSize` / `diffMarkers` / `fontSmoothing`, sanitized in `shared/settings.ts`) shown on the settings Appearance page. `webview/look.ts` turns them into root attributes (`lookAttrs`: `data-theme-fixed`, `data-diff`, `data-smoothing`, inline `--ui-font-size` / `--code-font-size`) that both shells spread after `appearanceDataAttrs`; the LAB omits `look` so defaults paint. Theme: `resolveTheme` in `App` maps `auto` to `useVsCodeTheme()` (body's `vscode-*` class) and a fixed scheme sets `data-theme-fixed`; the host-derived roles in `tokens.css` (`--fg-1`, `--bg-0`, `--line-strong`, `--focus`) go through `--host-*` indirections that the fixed rule sets to `initial` (guaranteed-invalid → the `var()` fallbacks paint), otherwise a light shell would keep VS Code's dark sidebar background. Components read the resolved scheme from `ThemeContext` (`useTheme`), never from the body class. Type scale: `--text-*` are declared on `:root, .acp-shell` in terms of `--ui-font-size` / `--code-font-size` — a custom property resolves where it is declared, so the shell's inline override only reaches tokens redeclared on the shell; density / settings line heights are `calc(var(--ui-font-size) + Npx)` offsets, keep new sizes that way. `data-diff="signs"` just blanks `--diff-add` / `--diff-del` (the lines already carry `+` / `-` / space prefixes from `host/acp/diff.ts`)
- `Collapsible.Panel` always keeps its DOM mounted and uses an inert grid transition when closed. Closing runs on its own curve (`--dur-close` 320 ms, `--ease-close` ease-in-out) rather than the opening `--dur-open` ease-out: sampled per frame in `lab/tool-grouping.preview.html`, the ease-out close dropped over half a read group's height within 80 ms and read as a snap, while opening already reads longer because its rows fade in. A `ConnectedRail` switched off by its own closing panel retracts with it for `--dur-close` (`data-retracting`: its inert rows still measured, bottoms clamped to the shrinking root, no easing, faded on the close curve) instead of disappearing on the first frame of the close; a rail under a closing ancestor keeps its drawn segments and is clipped along with that panel. Disclosure retains ConnectedRail, streamed text and row entrance ownership remain unchanged, and nested folds preserve state. The menu and settings switches share one primitive with separate skins. Image Dialog stays absolute inside the shell, preserves natural image size, and neither locks document scrolling nor transfers focus. Toast remains timer-driven because its eight-second lifetime must continue during hover, focus and window blur; its viewport stays in the Thread area above the composer.
