# UI conventions: components

Component, token, menu, overlay, composer and chip rules. Motion, folding and layout rules are in `ui-motion-layout.md`.

- Agent installation (`settings/AgentPage.tsx`) remains visible whenever the registry supplies an install command or guide, including already detected agents. The executable fact names the actual `AgentInfo.missing` commands, never the agent id; missing names do not get appended to the installation description. Install commands run in the host terminal (the remote machine under Remote SSH). Verify with `src/webview/settings/AgentPage.test.ts` and `lab/agent-install.preview.html`.

- Model visibility settings (`settings/AgentPage.tsx`) share one card across all ACP agents: search and an unlabelled master switch in the header, source-aware model rows, and a Show more footer without a count inside the same surface. The master switch retains its accessible label, is on only when every family is enabled, and writes one `hiddenOptions` update for the entire agent catalog, including collapsed and search-hidden rows. `shared/modelCatalog.ts` promotes newer numeric releases within each named series/source while preserving unrelated series order and opaque option IDs. More than ten families collapse to ten; search always covers the full catalog. `Group embedded` reuses the card surface without nested cards. Verify with `test/modelCatalog.test.ts` and `test/models.test.ts`.
- Components must not contain raw numbers: sizes, type scale, spacing, and radii all use token classes (`h-ctl`, `px-pad`, `gap-gap`, `rounded-md`, …)
- Every "row" (thought / plan / tool / status / session item) uses `ui/Row`; command execution is a row too (command on the row, output card below), not a separate block
- Command rows (`chat/ToolCall.tsx` + `chat/Terminal.tsx`, picked as A3-B1-C2-D2-E3 in `lab/command-row-pick.preview.html`): the row carries the verb and the whole command on one line (newlines collapse under `truncate`, the row width cuts it with an ellipsis; a program-only summary read as a stub and was dropped) with the full command as its tooltip. The card (`code-output` frame, compact `command-x` / `command-y` padding at the mono line height) opens with the full command behind a muted, unselectable `$`, wrapped and heredoc lines hanging under the command, cut to `--command-prompt-lines` (3) at a measured point so one chevron follows the text in both states (down to expand, up to collapse, height animated); the output follows it with only a half gap. Only a verbatim command (`targetMono`, no `verbKey`) moves into the card: title-derived targets may be prose, and background wait / kill rows name another command, so those keep the target on the row. Because the card holds the command itself, a verbatim command row is expandable from the moment it starts, before any output exists (other tool rows inside a process fold stay plain until they have `content`); the fold's auto-open then shows the command and the output streams into the open card, as in Cursor / Codex. Every command row ends with ✓ / ✗ (an async task's state tag replaces it) and its run time from `startedAt` / `endedAt` (`commandDuration`: tenths below ten seconds; a running command ticks whole seconds; no timestamps, no duration) — the verb label no longer carries seconds.
- Tool output cards (`ToolOutput` in `chat/Terminal.tsx`): a non-command tool whose visible content is text only (MCP results, background task reports such as Grok's `WaitFor`) opens the command card layout — indented to the label column on the row's rail, `code-output` frame, `command-x` / `command-y` padding, `--code-output-max` cap with edge fades and a hover copy button (the scrolling pane is `OutputPane`, shared with `TerminalOutput`). Unlike terminal output it wraps (`.tool-output`), each line a block with a `--command-prompt-indent` hanging indent, because a full-width `CodeSurface` with `whitespace-pre` put a horizontal scrollbar under short `key: value` reports. Several text items join into one card; diffs, lists and images keep their full-width bodies, and a text item among them uses the same card. Compare old and new in `lab/tool-output.preview.html`. A `fetch` tool (web fetch / web search results) whose text passes `looksLikeMarkdown` renders through `Prose` inside the same capped card instead of the monospace pane; the engine cuts each tool text item to `TOOL_OUTPUT_MAX` (20 000 UTF-16 units, `rust/crates/acpira-host/src/limits.rs`), so the rendered document stays bounded.
- Context compaction is an action row (`Turns.tsx` `Compaction`: `Row tone="action"`, `Shrink` lead — the context panel's compact icon — `TriangleAlert` when failed, no lead under `toolLine=text`). A live compaction shimmers at its own transcript position like a running tool, and its `Shrink` lead gets `compacting-icon` (`motion.css`: the four corner arrows push inward in turn, in the row's own ink; stopped by the motion kill switch); a compaction watched while running that completes keeps the running look until the loop's shared rest beat (all four arrows at rest, read from the live animation's `currentTime`), then plays `compaction-settle` once from that pose (the arrows clamp inward together and spring back, the label lands bright), so the two motions join without a jump; `useCompactionPhase` keeps seen ids at module level so a remount between the two renders still plays it and restored history never does), and the turn's activity / fold head stays "Working": when the heading owned it, a compaction running at the bottom read as the finished compaction row further up still running (Claude autocompacts several times in one turn). Devin / Kimi prose replies to `/compact` become the same row through `compactionForDisplay`. A `/compact` reply that holds only its compaction row shows no Working row / fold head (`compactionOnly` in `AgentMessage`): the row itself is the live status, and the head returns once other content arrives. The prompt Acpira sends for auto-compaction (`UserTurn.auto`) renders nothing; it stays in the transcript and in exports.
- `ui/Button` has exactly two tiers, settled in the buttons LAB (`#page=buttons`): `primary` is a tonal grey fill (strong text, medium weight, firmer outline), `secondary` an outline that fills on hover. One primary per card (the action to take: allow-once, import login, the first sign-in method), everything else secondary — no third "ghost" tier, and the inverted solid (`--btn-1-*`) belongs to the send button alone. `effects/SendButton` wraps the lit button in `MetalFx` (default `send: metal`), which keeps its whole wrapper at `opacity: 0; visibility: hidden` inline until the shared WebGL shader paints a first frame — a lost / stalled context in a long-lived webview made the send / stop button vanish while a turn ran. The wrapper carries `visible! opacity-100!` so the solid button always shows and only the silver ring waits for the shader; keep that override if the wrapper classes are touched. Agent-supplied sign-in method names are English on the wire; `notice.method.<agent>:<methodId>` keys localize the known ones (Notice falls back to the agent's name via `tOr`)
- Interactive primitives use `@base-ui/react` through the split parts in `ui/Popover`, `DropdownMenu`, `Command`, `Collapsible`, `RadioGroup`, `Switch`, and `Dialog`. Compose `Root / Trigger / Portal / Positioner / Popup` directly; never reintroduce `Menu items=[]`, `children(api)`, or `content(close)` wrappers. `PanelHeader`, `PanelFooter`, and `OptionContent` provide presentation only. Buttons, chips, rows, and cards use cva; `cn` merges Tailwind classes with the custom typography and spacing scales.
- Every overlay portal inherits `ShellLayerContext`. Positioners default to bottom/start, read the numeric `--pop-gap` and shell `--pad`, and shift horizontally inside the shell. Side flipping is explicit at the Permission menu. Menus are nonmodal; radio items close on selection. After the Base UI open lifecycle completes, menus focus the checked enabled item or the first enabled action for both pointer and keyboard opening. `onOpenChange` is a Base UI request callback; the composer's counter uses `onOpenLifecycle`, which pairs actual open mounts and cleanup, including unmount. Triggers recognize both `data-open` and `data-popup-open`.
- Model panels use inline `Command` lists with automatic highlight and a visible search field at 12 families/options. Menus carry one fill only, the pointer / keyboard highlight: the selected row is marked by its check mark and has no fill of its own (a filled current row next to a filled hovered row read as two selections, 2026-10-03), all rows reserve a check column when any is selected, and local `scrollTop` owns list positioning. Selecting a family closes the popup; changing effort/Fast/Thinking keeps it open. Agent/account pages use RadioGroup rows; SessionList keeps its own drawer/search/rename behavior and never uses Command. Its tree (`chat/sessionTree.ts`): pinned rows on top, then under the workspace scope the window's categories and loose rows with no project header, under `all` one collapsible project group per cwd (`Folder` / `FolderOpen`, bold name, "current" badge, the current project first). A project is a real directory and keeps the folder glyph; a user category is drawn with lucide `Inbox` (`chat/CategoryIcon.tsx`, `CategoryAddIcon` adds a small plus for "new category"), chosen from twelve candidates in `lab/session-folders.preview.html` so the two never read as one concept. Children indent by `ml-indent` with no rail line. Filing uses native HTML5 drag and drop (the browser's own translucent drag image, deliberately not a custom ghost) with the `application/x-acpira-session` type: the hovered target is the whole block (header plus children) outlined by an inset `ring-1 ring-fg-1/70` frame on `rounded-lg`, a category of another project dims and says "same project only", a collapsed category stays collapsed under a drag and is framed by its header alone (no spring-open, decided 2026-10-06), category headers drag to reorder with an accent insertion line positioned absolutely, and pinned rows and ChatGPT mirrors do not drag. The row menu's "move to category" submenu is the no-drag route. `lab/session-categories.preview.html` renders the production list against an in-page stand-in for the host; `lab/session-categories.drag.mjs` replays the drags through CDP drag interception (into, out, into a collapsed category, refuse, reorder, pinned). Its search matches titles and agent names locally on every key (every term must occur, `chat/sessionSearch.ts`) and, when the shell passes `onSearch`, asks the host for conversation hits after a 180 ms pause; a content hit joins the list with its snippet as a second `text-3` line, the terms marked in title and snippet, and the empty state reads "searching" until that query's reply lands. Mention anchors to the composer field with no initial/final focus transfer. Unpositioned Mention rows cannot receive pointer events; only actual mouse movement changes the active hit, since layout-triggered enter events can occur under a stationary pointer. Context usage keeps hover delays of 120/250 ms and opens immediately on focus that arrives from another element (`relatedTarget` set, i.e. Tab / Shift+Tab). Base UI hands focus back to the trigger after every close — outside click, Escape, the compact button — and that focus event has no `relatedTarget` because the card is already unmounted; opening on it reopened the card the user had just dismissed, so a second click on the ring was needed to get rid of it. Verify with a headless-Chrome CDP run against `lab/model-params.preview.html`: hover → click ring → click the transcript must leave the card closed, and Tab into the card → Escape must not reopen it. Vite's file watcher does not fire on `/Volumes/Nano`, so after editing a source file restart the LAB server (or the browser keeps receiving the previous transform)
- Menus: the options area holds only homogeneous option rows; unavailable items are greyed out, not hidden. Bars are `[lead square button] [text, entry with chevron when clickable] …spacer… [action square button]`, row-sized text (text-2), text only in the middle — icons live in lead / action (a lucide `svg` is `display: block` under preflight and wraps inside a truncating span). A sub-page (accounts) gets a `PanelHeader` navigation bar on top (back · title · action) and no footer; a top-level menu puts its entry / action in a `PanelFooter`. A small form tied to the selection (`ui/Field`: `RadioPills` / `SwitchRow`) may sit under the list in the footer slot
- Account menus (`chat/AccountPanel.tsx`) share one identity row, `ui/AccountLabel.tsx` `AccountIdentity`: a round `size-ctl` avatar, the name line and a caption. The official account (Grok / Kimi `localAccount`) shows email + plan with the caption "Official account", its quota bars, and the separated footnote about custom providers only when there are bars; signed out it reads "Not signed in" with the status as a wrapping caption. Switchable logins (Claude / Codex / Devin) put the plan in the caption so a long email keeps the width, the check sits at the end of the identity row, the quota bars span the full row, and the hover remove button is pinned to the identity row (`top-3`); an empty list uses the same identity row with “No accounts yet” and the add hint. Saved subscription accounts do not establish whether the CLI has local/API-key credentials; only a known `localAccount.status = login_required` reads “Not signed in”. States are in `lab/quota.preview.html` (dark / light, `locale=en`)
- Overlays pick a width tier (`Popover.Positioner width="sm | md | lg | xl"` → `--pop-w-*`) instead of sizing to content: mode → sm, agent / model / flat option → md, context usage → lg, session list → xl. Lists cap at `--pop-rows` (8) and use the `scroll-thin` bar. The one exception is the `@` mention list (`chat/Mention.tsx`): it is an inline completion, so it spans the composer field it completes
- Composer layout is shared across all ACP agents: only mode on the left; additional config options, context usage, the model with reasoning metadata, and send on the right. `shared/composerControls.ts` classifies native reasoning and `model_config` before any model-name heuristic; `chat/ModelPicker.tsx` uses the same Devin-style model panel for flat and grouped catalogs. Native `model_config` options join the footer below reasoning, never a separate toolbar chip when a model selector exists: every Fast shape (embedded variant, Fusion pair, Devin's Standard / Fast select, an adapter boolean) is one `FastState` shown as a `HeaderToggle` at the end of the first effort header, and only falls back to a `SwitchRow` when the panel has no effort scale; other parameters retain their labels and wire IDs in `SelectRow`. Hidden parameter options remain respected. Native reasoning selects and embedded model variants share `EffortField` / `SegmentScale` (`ui/Field.tsx`): one segmented capsule with every level spelled out (no L / M / H abbreviations), content-sized segments sharing the spare width so six Codex levels fit the `lg` panel on one line, the header holding only the label and the Fast toggle (the raised segment already names the level, so neither the header nor a hover preview repeats it); display labels normalize to Low / Medium / High / XHigh / Max / Ultra while original config and option IDs remain unchanged. Codex's `ultra` effort is the last segment, drawn in the `--ultra` tint, text only (`isUltraLevel`); `--fast` colours the bolt of an enabled Fast. 1M embedded variants are not offered: level, Fast and family changes all prefer the standard-context variant (a 1M variant still shows a `1M` badge if a session is already on one). Claude's ultracode takes the same path: the engine appends an `ultra` / "Ultra" option after Max on Claude's effort select and keeps it selected while ultracode is on (see `agent-quirks.md`), so the panel draws it as the tinted last segment and the chip reads `Opus 5.5 [Ultra]` with no Claude special case in the webview (LAB `lab/model-params.preview.html?agent=claude&ultra`). The layout was picked in `lab/model-tune-pick.preview.html` (combination MT-12221311, 2026-10-03). A model-less agent keeps reasoning in the same field behind a right-side chip and model parameters accessible as flat options. Agent IDs must not select a separate composer or layout. Verify with `test/composer-controls.test.ts` and `lab/model-params.preview.html?native`.
- Plan card (`chat/PlanDocument.tsx`, 2026-10-07): the Question card's shape. Header row = plan glyph (`ListTodo`, the Plan mode's) + the plan title (its leading `# heading`, which the body then drops; "Plan" falls back to `plan.title`) + a status word (`plan.pendingApproval` while a linked permission waits, else `plan.status.*`) + the open-file icon. The body is indented to the header's label column (`pl-indent`) and scrolls past `--plan-body-max` under `scroll-fade`, so the approval bar stays next to the plan. The bar (hairline on top, `h-ctl-sm` buttons) holds Revise on the left and the executor chip + one `primary` button on the right, labelled with the localized allow-once option (Claude: 开始实施) or `plan.build`; the chip's "more approvals" page widens to `xl` so long Claude labels stay on one line. Checked in the browser harness with fake-agent `claude-plan` at 980 and 420 px, dark theme
- Question card (`chat/Questions.tsx`): pinned above the composer, always visible while waiting, with no collapse control. The header shows a stable title and page count; exactly one question is mounted at a time, using only its question text, never a category/numeral prefix. Option rows use `ui/Row`, the same text-2 scale as buttons, first-line-aligned key slots and a check for selected options. The Other option is an inline input in its own row; focusing or typing selects it, and multi-select retains the other picks. Picking an option stays on the page; Previous / Next navigate and Submit answers sends the complete retained response. Only long current-question content scrolls, with a short edge fade; header and actions stay visible. Tab and named keys retain native focus behavior, focused buttons retain native Enter activation, and composition/modifier keys never choose an answer. Letters / digits select, arrows focus options, brackets navigate, and Escape skips. The resolved `QuestionRecord` remains an independent disclosure, rendered in sequence where the question was asked.
- Toolbar chips: exactly one `solid` Chip per toolbar (the mode: glyph from `chat/modeIcons.ts` + name, never truncates); everything else is `quiet`. The row's fieldset carries `min-h-ctl`: the context ring is the one `--ctl` control among `--ctl-sm` chips and it comes and goes with `usage` (Grok has none until its first model round and drops it on a model switch), which used to move the whole composer by the 6 px difference. The toolbar row is an `@container`; below the `sm` tier (a 380 sidebar leaves ~324px) chips collapse per `Chip.narrow` — mode / agent keep only their icon, the model keeps only its text, carets go first — so the model name never gets squeezed to a letter (Cursor collapses its mode pill the same way; Devin's composer has no carets at all). Mode menu rows are single-line (glyph + name, description as `hint` tooltip). The model choice is one chip — the family name (never truncated) plus `ChipTag` badges in `Chip.tags`: the effort level spelled out (Ultra in the ultra tint), Fast with its bolt, then any other enabled parameter, e.g. `Claude Fable 5.1 [Max] [⚡Fast]` or `K3 [High]`; a Fusion chip reads `Fusion` plus the lead's badges. Badges that do not fit wrap onto a clipped second line, so the trailing ones give way first. Provider/source names appear only in the expanded model list, never in the toolbar chip. The chip opens one `lg` panel: the family list (search / pin; picking closes) with the current family's params as a form underneath (effort as a `SegmentScale` with the Fast toggle in its header, a lone Standard / Thinking pair as a Thinking switch; changes apply at once and keep the panel open). Devin's side pane laid out vertically, because a 380 sidebar has no room beside the list. Never show the params again inside the family rows
