# HarmonyOS app

`apps/harmony/` is a prototype of the phone app in ArkTS (Stage model, ArkUI state management V2), built headless against the public OpenHarmony SDK. It is one more engine client: the list, the chat (prompt bubbles, the folded process, the reply's Markdown, permission cards) and the composer, with the iOS app's tokens, dictionaries and synthetic fixtures. The iOS app is the reference for behaviour and look ([ios.md](ios.md)); the Android app ([android.md](android.md)) is the nearer port when a Compose idiom maps to ArkUI better than a SwiftUI one.

## Toolchain

- SDK: the public OpenHarmony SDK, one folder per API level holding `ets`, `js`, `native`, `previewer`, `toolchains` (the `L2-SDK-MAC-M1-PUBLIC` archive of a release on `repo.huaweicloud.com/openharmony/os/`, same sha256 as the openharmony-rs GitHub mirror). No Huawei account; DevEco Studio is not needed.
- hvigor and its OHOS plugin come from the Huawei npm registry (`https://repo.harmonyos.com/npm/`, `@ohos/hvigor`, `@ohos/hvigor-ohos-plugin`, same version). `scripts/build.sh` links that install's `node_modules` into the project (`hvigorfile.ts` imports the plugin by name) and writes `local.properties`.
- From the Mac, both hosts above can crawl at a few KB/s while the PC fetches them fast; a single slow connection is common, ranged parallel requests are not slowed.
- The public SDK knows no `phone` device type (`ets/api/device-define`): `module.json5` says `default`.
- ArkTS refuses constructor parameter properties, implicit return types on arrow callbacks and untyped object literals; `@Param` names must not shadow component attributes (`size`, `id`, `enabled`); a `@Builder` call takes no attributes (wrap it in a container), and an `@Entry` build's root must be a container. `@Builder` methods must not share a name with a component member (`key`); `@Extend` cannot be exported (shared styles are `AttributeModifier` classes, `components/composer/ComposerBits.ets` `DOCK_CARD`); `@Monitor` on an optional `@Param` warns, so watched params take defaults.

## Previewer

- `scripts/preview.sh` screenshots a page from the tree's last build (own temp folder and port, so worktrees can run it at once).
- `previewer/common/bin/Previewer` runs the app's `modules.abc` (unpacked from the HAP) without DevEco: `-j` the abc folder, `-arp` the build's `intermediates/res/default`, `-ljPath` its `loader.json`, `-url` the page, `-or`/`-cr` the resolution, `-sd` the density, `-cm` the colour mode, `-lws` a port. Frames stream on that port as WebSocket binary messages with a JPEG inside (from the first `FF D8 FF`). hvigor's `PreviewBuild` only works when DevEco drives it.
- It runs no ability (state set up in `EntryAbility` is missing: pages initialise themselves), takes no want parameters and no input, has no `net.webSocket` module (the live wire needs an emulator or device), and rawfile reads come back empty, hence the dictionaries and fixtures compiled into `ets/generated/` by `scripts/build.sh`. `pages/Preview` opens chat fixtures directly for it; `pages/PreviewShell` / `PreviewForms` lay the list, menus, settings, new session and first run out as phone-wide frames side by side, `pages/PreviewSplit` is the frame without the first run (`pages/Index` always shows it there, having no prefs).
- Its resolution is capped at 3840 px a side: several frames at once need a lower density.
- `pages/PreviewComposer` sets each composer / dock state (beans and panels open, staged, quotes, edit, slash, question, alert, plan) up from its fixture without input, one phone frame each: `preview.sh out.jpg 3780 3510 dark pages/PreviewComposer 240 10` gives the 7 x 3 grid.
- `Path.commands` are px and a `Shape` viewport did not scale them: `components/Glyphs.ets` scales each path to the icon's px size. A path's `fill` given a colour resource stays black there and a resolved one came out empty or in the light table under `-cm dark`: filled glyphs are a box in the tint clipped to the path (`clipShape(new PathShape(...))`, `AgentMark`, `FilledGlyph`).

## Signing and running

- `scripts/sign.sh` signs with the SDK's OpenHarmony test keys (`toolchains/lib/OpenHarmony.p12`, password `123456`): a profile template with this bundle name and fresh validity, signed by the matching profile key, then the HAP signed by the application release key. The keystore's release entry carries a self-signed certificate; the chain must start from the template's own certificate (issued by the Application CA) or sign-app fails with "Signature does not match".
- A debug profile without a device list is refused at install ("device is unauthorized"), and the Oniro emulator has no UDID (`bm get --udid` fails): the script signs a release profile unless `UDID` is set.
- That runs on an OpenHarmony emulator or a developer-mode board. A HarmonyOS NEXT phone needs certificates and a profile from AppGallery Connect (a Huawei developer account), and DevEco's emulator needs a Huawei login.
- The Oniro emulator (`oniro_emulator.zip` from `eclipse-oniro4openharmony/device_board_oniro` releases) is x86_64 QEMU with `run.sh` / `run.bat`; its user network forwards HDC to `127.0.0.1:55555` (`hdc tconn`, through an SSH tunnel when QEMU runs on another machine). Accelerated on Linux KVM, very slow on Apple silicon.
- On Windows, `run.sh` picks WHPX with an AVX2 CPU model, yet the guest's `foundation` still died of SIGILL and init rebooted; TCG (`-accel tcg,thread=multi -cpu max`) boots it. Under TCG the first launch after boot often trips a lifecycle timeout (the main thread waits on the render service for a VSync receiver; a `sysfreeze` log in `/data/log/faultlog/faultlogger/`); launching again works.
- Driving it: `power-shell wakeup` / `setmode 602` (screen stays on) and a `uinput -T -m` swipe unlock (`aa start` refuses a locked screen); `uinput -T -c x y` taps in px; `uitest uiInput inputText x y text` types; `snapshot_display -f /data/local/tmp/x.jpeg` sometimes fails right after a wake, retry. Resolution comes from the QEMU `virtio-gpu` `xres`/`yres` plus the kernel's `video=` (density 1, so px = vp): 1280×800 shows the split.
## Engine wire

- Same contract as the other clients: hello, `attachView` (`initial: {empty: true}`), `ready` with `patches` and `listPatches`, `sessionPatch` / `sessionsPatch` applied as `sessionPatch.ts` and the sessions patch runs, `resync` / `resyncSessions` when one does not fit.
- The development engine checks the handshake's `Origin` is its own loopback port: the app dials `127.0.0.1` and an emulator needs that port forwarded to the engine (`hdc rport tcp:PORT tcp:PORT`, as `adb reverse`).
- NetworkKit's `webSocket` sends an `Origin` of its own (scheme and host, no port) ahead of the one the app sets; the engine accepts the handshake when any `Origin` header matches (`sidecar/ws.rs`). `EngineClient` logs the wire under the hilog tag `AcpiraWire`.
- ArkUI `ForEach` keeps a child whose key is unchanged, however its item changed: a nested `ForEach` (list sections) needs the outer key to carry the inner rows' keys, or rows keep stale summaries.
- A custom component's `hitTestBehavior` set inside its `build()` covers only its root: the wrapper node the call site creates is hit-testable by default and, stacked over the page (`GooLayer` at `zIndex(3)`), swallows every touch under it (hilog "Touch test result is empty"). Set the mode at the call site too. The Previewer takes no input, so only an emulator shows it.
- A `bindContextMenu` builder closes itself through `getUIContext().getContextMenuController().close()`; it has no `isShow` binding like `bindMenu`.
- `EntryAbility` sets the keyboard to resize the page; the default lifts the whole page, bar included, off screen.
- `scripts/build.sh` with `DEV_ENGINE=host:port:token` (and `DEV_PROMPT`) compiles a default engine in, since nothing passes launch parameters to the Previewer; `apps/ios/scripts/engine.sh` takes `TOKEN` to match.
- A field added to `SessionView` must be copied in `viewWithTurns` (`wire/Wire.ets`) too, or the app's own edits (send, stop, edit, fork) drop it; `applySessionPatch` completes the parsed patch in place, so a patch keeps every field the wire sent.
- Turn rows key on the turn object (`store/Thread.ets` `turnKey`): a patch keeps the objects of the turns before `keep`, so their rows stay. What a row reads from the view beyond its turn (subagents, controls, the running and retryable turn) comes through the observed `ThreadContext`, written only when its content changed, not through ForEach params.
- The live turn and its stretches are built again whenever their content changes (the nested keys carry block signatures), so nothing a row must keep lives in its own state: fold choices sit in `components/Rows.ets` `folds` keyed by session and block, and clocks, the shimmer and the Orb run off the shared `ticker` / one epoch. Sheets and expansions on a streaming turn's rows (`@Local`) still reset with each chunk.
- `maxLines(0)` shows no line at all (`WebMetrics.allLines` lifts the cap), and a custom component's `flexShrink` does not reach the Text inside it: a row label that must not give way is a plain `Text`.
- Code is coloured by the regex tokenizer in `logic/Syntax.ets` (`syn_*` colours); iOS runs shiki. `PREVIEW_FIXTURE=name` / `PREVIEW_OPEN=1` for `scripts/build.sh` give `pages/Preview` one fixture at full height / with every fold open.

## Paired remote

- The library is `rust/crates/acpira-mobile-ohos`: napi-ohos over `acpira-mobile`, the UniFFI binding's surface. Its crate type stays `lib` and `scripts/build-net.sh` links the cdylib with `cargo rustc --crate-type cdylib` per OHOS target, so workspace builds and clippy on macOS / Windows never link the N-API symbols. Its work dir is `rust/target/ohos`: hvigor wipes `apps/harmony/build` at the start of every build.
- No ohpm in this toolchain: `remote/Net.ets` loads the `.so` with `loadNativeModule` (API 12+) by its OHM URL (a bare `lib….so` name is refused at run time unless oh-package.json5 lists it) and types it from `cpp/types/libacpira_mobile_ohos/index.d.ts` by relative path. Without `entry/libs/` (git-ignored) `net()` is undefined, and the app keeps the demo and the engine by address.
- The public SDK has no ScanKit: camera preview frames go through an `ImageReceiver`, whose JPEG component holds NV21, and the luma plane is decoded by the library (rqrr). Camera calls must sit lexically inside `if (canIUse('SystemCapability.Multimedia.Camera.Core'))`, or the SysCap check warns for `2in1`; `syscap.json` cannot list `2in1`.
- The link is QUIC (UDP), so `hdc rport` and SSH `-L` tunnels cannot carry it. QEMU's user network NATs outbound UDP, so an emulator reaches a gateway with relays off (`apps/ios/scripts/gateway.sh`) at the Mac's LAN address. mDNS does not cross that NAT: `scripts/build.sh DEV_NEARBY=<id>@<host:port>` pins the computer in the add sheet.
- `acpira://pair/…` opens the add sheet (`module.json5` skill; `EntryAbility` reads `want.uri` at launch and `onNewWant` after, through an emitter event to `pages/Index`); so does the launch parameter `pair` (`aa start … --ps pair <link>`), and `aa start -A ohos.want.action.viewData -U <link>` drives the deep link. A build with `DEV_ENGINE` never sets up pairing.
- An emulator on another machine reaching the Mac's gateway crosses the macOS firewall, which matches its allow rule by code signature: a rebuilt ad-hoc `acpira` is dropped silently (a Python UDP relay on another port, pinned with `DEV_NEARBY`, passes since Python is Apple-signed). The loopback paths of the iOS and Android emulators never meet it.
- `PasteButton` grants the clipboard read for its tap; the "READ_PASTEBOARD" warning on that read is static and expected.
