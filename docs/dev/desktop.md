# Desktop app

`desktop/` is a standalone Electron shell: the webview bundle (`dist/webview`) and the Rust engine outside any IDE, with the session column on the left over every project as its baseline. It is a shell like the VS Code extension and the IntelliJ plugin; all engine behaviour stays in `rust/`. The plan lives outside the repository (`~/.agents/plans/acpira-desktop-client_7d50b6df.plan.md`); this file records what is built and verified.

## Layout and commands

- Own package with its own lockfile (`desktop/package.json`, pnpm), so the root `pnpm install` never downloads Electron. `src/shared` and `src/host/shell` (`SidecarClient`, `engine.ts`, `sidecarLocator.ts`) come from the repository through the `@shared` alias and relative imports; esbuild bundles `src/main.ts` → `dist/main.cjs` and `src/preload.ts` → `dist/preload.cjs` (`desktop/build.mjs`).
- `cd desktop && pnpm install && pnpm typecheck && pnpm test`; `pnpm start` builds and launches; `pnpm smoke` and `pnpm package` are below. The page needs the root `pnpm build` (dist/webview) and an engine: `ACPIRA_SIDECAR_BIN=rust/target/debug/acpira`, else `dist/sidecar/<os>-<arch>/acpira` from `pnpm build:sidecar`.
- Electron 45.0.0 (Chromium, Node 24). With pnpm 10.28.2 the electron package installed without its binary (its postinstall did not run although `onlyBuiltDependencies` lists it, 2026-10-22); `node node_modules/electron/install.js` fetches it.
- A terminal inside VS Code exports `ELECTRON_RUN_AS_NODE=1`, which makes the Electron binary run as plain Node (`protocol` is undefined at startup). Launch with `env -u ELECTRON_RUN_AS_NODE`.
- Development / smoke switches: `ACPIRA_HOME` (data root; use a temp one, a real `~/.acpira` gets `categories.json` `projects` seeded), `ACPIRA_DESKTOP_USER_DATA` (Electron's userData: settings, window state, browser history, and the log as `logs/desktop.log`, which otherwise goes to `~/Library/Logs/Acpira`), `ACPIRA_DESKTOP_PICK` (folders, path-delimiter separated, that answer the folder dialog in turn without showing it), `ACPIRA_DESKTOP_SHOT=<png>` with `ACPIRA_DESKTOP_SHOT_DELAY_MS` (capture the first window after it loaded, then quit).

## How it fits together

- Main process (`src/main.ts`): single-instance lock, one `SidecarClient` to the persistent engine (`acpira serve`, socket key with `shell: 'desktop'` so no IDE window shares it; Windows keeps the attached stdio child), any number of `ChatWindow`s. Quitting only disconnects; macOS keeps the app and its connection when the last window closes.
- Hello: `env.projects: true` and no `cwd` (the engine's project-shell rule, `docs/dev/host-architecture.md` "Project shells"), `blobBase: acpira-app://app/blobs`, the settings snapshot, the capabilities in `src/platform.ts`.
- Each window is an engine view with host `editor`. Page traffic goes preload → `ipcMain('acpira:webview')` → `client.send`; host messages come back as `webContents.send('acpira:host')` and the preload reposts them with `window.postMessage`, a structured clone into the page's world (context isolation keeps the preload's objects out of it). `viewFocus` stays in the shell, as in `src/host/bridge.ts`.
- `acpira-app://app/` (registered privileged: standard, secure, fetch, CORS, stream): `/index.html` is generated (`src/page.ts`: the VS Code page's CSP with `acpira-app:` as the source, `window.__acpira = { host, font, sessionLinkBase: 'acpira://session/', shell: 'desktop' }`, the body scheme class from `nativeTheme`), `/desktop.css` the `--vscode-*` variables, `/webview/*` and `/blobs/*` files through `confine` (decoded, realpath inside the root, so `..`, `%2e%2e` and symlinks out are refused) and `net.fetch` of the file URL.
- Preload (`src/preload.ts`, sandboxed): `window.__acpiraApi` with `postMessage`, `getState` / `setState` (sessionStorage) and `pathForFile` (`webUtils.getPathForFile`; `File.path` is gone). Theme changes toggle the body class.
- Settings (`src/settings.ts`): `userData/settings.json` holds only the settings that follow the window (`SHELL_SETTING_KEYS`: session list side and scope, editor selection), flat keys without `acpira.`, tmp + rename; a first launch writes `sessionListPosition: left` and `sessionScope: all`; a file that does not parse is moved to `settings.json.broken`. `writeSetting` writes there and the change goes back as `settingsChanged`. Every other setting is shared with the IDE shells in `<ACPIRA_HOME>/settings.json` (2026-10-23, see the shared settings entry in `host-architecture.md`): the engine writes it, the shell reads it for the menu language, the browser window's look, the page font and "open files with" (`src/host/shell/sharedSettings.ts`, polled once a second).
- Login shell environment (`src/loginEnv.ts`): `$SHELL -i -l -c` printing `env -0` between marks, 10 s timeout (process group killed), `PWD` / `OLDPWD` / `SHLVL` / `_` / `ELECTRON_*` dropped; merged into the engine's `SidecarCommand.env`. It runs while the first window loads, before `client.start()`.
- Platform actions (`CAPABILITIES` in `src/platform.ts`): `writeSetting`, `openExternal`, `revealInOS`, `openResolvedFile` and `openPlanDocument` (through "Open files with", below; a plan sent only as markdown is written to a temp file first), `openInEditor` (the session in a new window; the session menu says "Open in new window"), `openBrowser` and `runInTerminal` (below), `toast` (into the page, below), `notify` (quiet while a focused window shows the session; chime to the last focused page; a notification whose click brings the session up). `searchFiles` is not declared: the engine walks the session's project.

## The page's desktop layout (2026-10-23)

`window.__acpira.shell === 'desktop'` makes `App` pass `desktop` to `Shell` (`src/webview/desktop.ts` `DesktopContext`, read by `SessionList` and `Header`). Styles in `src/webview/styles/desktop.css`: tokens unlayered, so they beat the density's `--hdr`; rules in `@layer components`; anything that collides with a call-site utility is switched at that call site.

- Frame. The column lies on a darker window canvas (`--canvas`, `--bg-0` mixed 78% with black; 55% read as a hole beside the page) with no fill or rule of its own. Below `--session-dock-min` the column becomes a page over the whole window, on the canvas as well (Narrow window, below); as the first drawer it had no fill, and its list was drawn straight over the conversation (until 2026-10-23). The chat is a sheet (`data-sheet`) inset `--sheet-inset` 8 px from the window's top, right and bottom edges, `--r-lg` corners. The window's title row (`chat/DesktopFrame.tsx` `TitleRow`: back, forward, then the column's toggle, as Codex orders them) is pinned at the window's top-left, absolute over the column or the sheet's header, so it never moves when the column folds or a page changes; the column leaves an empty strip under it (`TitleSpace`). It and the sheet's header (title plus the project's name, no rule) share one 44 px line (`--hdr` pinned) and are the window's drag regions (`data-drag-region`). Before 2026-10-23 the toggle lived in the column and a second one appeared in the header once it folded, which read as the button jumping.
- Traffic lights. macOS: `titleBarStyle: 'hiddenInset'` with `trafficLightPosition { x: 17, y: 23 }` (`desktop/src/chatWindow.ts`). Measured on macOS 27 with an AppKit window: the buttons are 14 × 14 pt, 23 pt apart (9 pt gaps), so the lights span x 17–77. Their centre line is y 30, which is the title row's (8 + 44 / 2). The first light's centre is x 24, which is the column's row icons at the default (airy) density. `--lights-w: 84px` leaves about 15 px to the first button's icon. With no column beside the sheet (hidden, or a narrow window), the header starts after the title row (`--title-w`, `--sheet-lead`).
- Column. The title row's toggle folds the column away and brings it back (in a narrow window it opens the list page, `data-session-toggle`). It is kept in webview state `desktopColumnHidden`, which only the docked column reads: a narrow window's list page and ⌘K open whatever it says (until 2026-10-23 a column folded in a wide window left the drawer zero wide and inert once the window narrowed, and ⌘K unfolded the absent column instead of opening the drawer). The VS Code drawer's scrim is `bg-scrim/45`: the theme clears Tailwind's own palette, so the `bg-black/20` it had generated no CSS and dimmed nothing; the desktop page dims the sheet instead. Its width eases only while it moves (`data-moving` on the column itself: React writes a child's attributes before its parent's, so a flag only on the root landed after the width had changed and the opening jumped). The content keeps its open width (`--column-w`) and is clipped instead of re-wrapped. New session (⌘N) and search (⌘K) are rows on top. Categories are hidden. Each project lists its latest 5 sessions (the active one always among them), and the rest sit behind one row that names how many, their agents and the most urgent state. Project rows have no count and no "current" badge; their hover shows the pen (new session there) and "…" (reveal, copy path, remove from list), and right-click opens the same menu. A gear at the foot holds settings, appearance and help, built like a row's lead so it stands under the row icons; its glyph is a size up (`--foot-icon` 18 px) and its hover fill square (36 px), since at the rows' 14 px it looked lost. Back / forward walk the sessions this window showed (`useSessionHistory`).
- Projects. The "Projects" label's folder+ and ⌘O open the system folder dialog: `WebviewMsg pickFolder`, answered by `HostMsg pickedFolder`, both handled by `ChatWindow` and never sent to the engine. A folder dragged from Finder onto the column also joins (`pathForFile`). A new folder is appended (`addProject`), flashes and scrolls into view, and its start page opens. With no project at all (init without `active`, or `noSession`) the sheet shows the open-folder state.
- Start page: an empty session with nothing queued (`chat/StartPage.tsx`). There is no greeting. The composer stays where a conversation keeps it, two lines tall. Above it sits a segmented agent picker (rounded-lg frame, rounded-md segments, the picked one spelling its name). The project is a dropdown on the sheet header after the title (`ProjectPick`: search, `~` paths, the current one ticked, "Open another folder… ⌘O"); importing an agent's own sessions is an icon on the column's Projects label beside add-folder and the filter. Until 2026-10-23 both sat in a bar under the composer, whose small second dropdown under the composer's own read as clutter. Picking an agent or project starts the empty session over there (`newSession { agent, cwd }`; the engine drops the empty one it leaves), and the typed text moves with it (`moveDraft`). The first message folds the picker away while the field eases to one line.
- Settings (`SettingsShell` with `desktop`): the same frame. The rail lies on the canvas under the same pinned title row, without the column's toggle; its back returns to the chat and forward stays disabled, and the rail has no "back to chat" row. The page is a sheet. In the desktop frame the rail's widths come from `desktop.css`, so the narrow icon rail stays as wide as the title row over it. The session list position (Appearance) and scope (General) are not offered: the shell always passes `left` and `all`, so a value written before cannot strand the column. General offers "Open files with" in the scope's place. "Share selections" stays: its copy names any tool, and the browser panel's page context goes out through it. The language's `auto` reads "Follow system" (`settings.language.system`): the hello's `hostLanguage` is `app.getLocale()`.
- The gear menu opens with no collision padding: the gear sits nearer the window's edge than the shell's `--pad`, which had pushed the menu off its button.
- Page and column motion (2026-10-23). Chat and settings replace each other in `App`; the canvas, sheet and title row are the same on both, and what sits in the column or rail and on the sheet fades in as it mounts (`desktop.css`, `acp-fade-in` 220 ms). The settings rail takes the chat column's stored width (`sessionPaneW`), so the sheet's edge stays put. The header's new-session and settings buttons, there while the column is folded, stay mounted and ease their width and opacity with the column (`data-column-act`; a fixed-width button as the grid item held the 0fr track open, so a clip box sits between). The list fades under the top action rows once it scrolled (`list-fade` with `useScrollFade`), as it does at its foot.
- Popovers line up with what opened them: the project row's "…" menu is `sm` wide, so it can end at its button (at `md` the collision padding shifted it right of it); the session column's own menus (the view menu, a project's or a section's "…", a group label's menu, their submenus) open to the right of their trigger over the chat (`side="inline-end" align="start"`, Cursor's placement, 2026-10-23), so a column dragged narrow never squeezes or flips them; the IDE lists keep `bottom` / `end` with submenus opening `inline-start`.
- With the column folded: opening settings opens its rail from nothing (`data-opening`, `acp-rail-open` 320 ms), and coming back mounts the column open at the rail's place and folds it once painted (`Shell` `fromSettings`), so the sheet's edge never jumps. The folded flag is webview state `desktopColumnHidden` (`COLUMN_HIDDEN_KEY` in `src/webview/desktop.ts`).
- The gear menu carries the theme, the language and the layout (below) as quick switches (submenus, the current value named on the row and ticked inside), writing the same settings as the settings page; a pick leaves both menus open, since a language change re-renders the page in place (`docs/dev/webview.md`); their `auto` reads "Follow system" on desktop (`settings.theme.system`, `settings.language.system`): nativeTheme and `app.getLocale()`.
- A project's "more" row adds ten sessions per click, one fold per page so only the added page opens; once all are out it reads "show less" and folds them all away.
- Narrow window (2026-10-23; picked in the local LAB `lab/portrait.preview.html` as `nav=page&bar=toggle&head=center&frame=inset`, which stays for the PWA, phone and Swift versions). Below `--session-dock-min` (760 px) `Shell` sets `data-narrow` on the root, and `data-drawer-open` while the list is open. The list is a page over the whole window (`absolute inset-0`). Closed, it stays laid out at `translateX(-100%)`, hidden and inert, so it can slide. - Shortcuts: ⌘N new session, ⌘K search, ⌘O open folder, ⌘, settings, ⌘[ / ⌘] back / forward through the sessions this window showed, ⌘[ on the settings page back to the chat (Ctrl elsewhere).   - Widths: explorer `--explorer-min` 180 to `--explorer-max` 480 (default `--pop-w-md`); chat `--files-chat-min` 360 to `--files-chat-max` 960 (default 460, its splitter over the stage's rim); the stage keeps `--stage-min` 320. The dragged widths persist in `toolPanel` (`explorerW`, `chatW`). The stage takes what the others leave, as an editor area does, so at the window's default 1180 px it sits at its narrowest (explorer 228, stage 320, chat 404, column 228 under the smoke); folding the column gives it the column's width.
  - Tabs: open files per project are kept in memory (`opened`, `panel.showView` / `closeView`); closing a tab shows its neighbour. With nothing open the stage shows the new-tab page, this session's changed files on top. Browser tabs on the stage keep the plain surface (`&stage` in the frame URL); terminal tabs lie on the sheet, the view moving over from the panel.
  - Fallback: below `--files-layout-min` 1080 px, without a project or for an external session the window keeps the conversation layout (with the tool panel if it was open), and below 760 px the narrow one.

- Shell toasts. `HostMsg toast { level, text, open? }` is shell-made, like `pickedFolder` (the engine never sends it, so Rust does not mirror it). It goes to the focused window's page, waiting in `ChatWindow` until that page has `init`, and joins the page's toast stack (`pushShellToast` in `src/webview/desktop.ts`, shown by `ShellToastItems`). Errors carry an alert icon and stay 15 s; `open` adds a button that reveals the file (`openPath`). The start page has a stack of its own, since the thread's stack is hidden with the thread (an unknown link on the start page showed nothing until then), and the settings page shows them as well. With no window open a toast becomes a system notification.
- Menu bar (`src/menu.ts`, rebuilt when the language changes): the app menu (about, settings ⌘,, services, hide, quit), File (new session ⌘N, new window ⇧⌘N, open folder ⌘O, connect ChatGPT, close), Edit (the roles; without them macOS sends no ⌘C / ⌘V / ⌘Z to the page), View (search ⌘K, tool panel ⌥⌘B (the session list in the files layout), layout, browser tab, reload, devtools, zoom, full screen), Window and Help (help and feedback, show log). A macOS menu item's key equivalent takes the key before the page sees it, so these arrive at the menu and go to the page as `HostMsg shellCommand` (`newSession` / `search` / `openFolder` / `settings` / `toolPanel` / `browser` / `layoutChat` / `layoutFiles`), which runs what the page's own shortcut does (`useShellCommands`, queued until `Shell` mounts). Every role item carries a label in the app's language: macOS adds items of its own (tiling, Quit and Keep Windows) in the system's language, and Electron's English defaults stood out among them. Connect ChatGPT opens a window on a new ChatGPT mirror and copies its connection prompt once the view carries it, with a toast.
- Windows (`src/windowState.ts`): `userData/windows.json` keeps each open window's bounds, maximized flag and session (saved 500 ms after a move, resize or session change, and at quit) plus the last closed one, and a launch reopens them all. A saved place whose top edge is off every display keeps only its size, capped to the largest display. `window.close()` from a page emits no native close event, so a per-window cache keeps the entry that becomes `last`.
- Session links (`acpira://session/<id>`, the page's `sessionLinkBase`). The packaged app declares the scheme (`protocols` in `electron-builder.yml`) and registers itself as its handler when it starts (development runs leave the registration alone). macOS delivers links as `open-url`, listened for before the app is ready; Windows and Linux pass them in a second instance's arguments (forwarded by the single-instance lock) or the first launch's. A link to a session the store has, or a window shows, brings it up: in the window showing it, else in the focused one, else in a new window. Any other id gets the "not here" toast.
- System terminal (`src/terminal.ts`, `runInTerminal`: logins, installs and keychain unlocks; the tool panel's terminal tabs are the engine's, above): on macOS a temp `.command` script removes itself and its folder, names the window, applies the environment edits and runs the line; `open -a Terminal` runs it under the user's login shell and needs no Automation permission, which an AppleScript `do script` would. Linux hands the same script to `x-terminal-emulator`, then `xterm`. Windows starts the engine's prepared invocation (`powershell.exe -NoExit -EncodedCommand …`) in a console of its own.
- Seeding from the IDE (`src/vscodeSettings.ts`): while no engine has created the shared settings file, the hello carries the shared `acpira.*` keys of VS Code's user `settings.json`, else Cursor's (JSONC: comments, trailing commas, a BOM), so the first engine starts the file from the IDE's agents and look. Until 2026-10-23 a first launch copied them into the app's own store once; a profile created by an earlier build never got them and listed every agent as on while VS Code had four. It skips `sessionListPosition` and `sessionScope` (the app's own) and `agents`: Settings Sync had carried the Windows machine's agent commands into the Mac's `settings.json` (seen 2026-10-23), and the engine seeds `agents.json` from that legacy key once.
- Open files with (`openFilesWith`, in both sanitizers; `src/editors.ts`): file links and plan documents open in the system's default application (`system`, the default) or at the line in an editor: VS Code, Cursor or Windsurf (`-g path:line`), Zed or Sublime Text (`path:line`), IntelliJ IDEA (`--line N path`). The editor's command line comes from PATH as the login shell sets it, then from the app bundle under `/Applications` or `~/Applications` (Toolbox), since many installs skip putting `code` on PATH. On Windows only `.exe` files on PATH count: the `.cmd` launchers would need a shell, which a file path must not pass through. An editor that is not found or does not start leaves the file to the system's default application, with a toast naming the editor. The IDE shells never read the key.
- Engine failure: once `SidecarClient` gives up restarting the engine, a dialog offers Retry (`client.retry()`), Show Log and Close.
- Browser panel (`src/browserWindow.ts`): a window of its own per site running the bundle with host `browser` (default title bar, 1200 × 860). The shell holds the engine's preview-proxy lease (`SidecarClient.preview`, asked again after a reconnect) and relays the same messages as the VS Code `BrowserPanel` in `src/host/bridge.ts`. The frame or error waits for `browserReady`; page titles name the window and feed the address bar's history (`userData/browser-history.json`, 20 pages); picked elements and the page's own `window.acpira.context` calls go to the chat focused last (`addContext`, source `browser`), and the page's live context leaves with the page. `openBrowser` is declared, so agents get `open_browser`: a loopback page opens in a browser tab of the chat used last (the tab already on that site navigates, `panelOpenBrowser`), or in a window of its own with no chat page ready, without taking the focus; any other http(s) URL goes to the system browser. The page's CSP adds `frame-src http://127.0.0.1:* http://localhost:*` for host `browser`.

## Packaging (macOS)

- `cd desktop && pnpm package` (`scripts/package.mjs`) checks for the root `dist/webview`, `dist/picker.js` and `dist/sidecar/mac-arm64/acpira` (`pnpm build`, `pnpm build:sidecar`) and prints their ages, builds `dist/main.cjs`, then runs electron-builder 26.15.3 (`electron-builder.yml`; a devDependency of `desktop/` only) for an arm64 dmg in `desktop/release/`. The app's resources hold `webview/`, `picker.js` and `bin/acpira`, where `sidecarLocator` finds the engine. Electron is taken from `node_modules/electron/dist` (`electronDist`), with no native module rebuild.
- Signing is ad hoc (`identity: '-'`, no hardened runtime, no notarization), which runs on the machine that built it; another Mac refuses a downloaded copy until it carries a Developer ID signature.
- Locale: macOS hands an app the user's language only among the localizations its bundle declares, and Electron keeps its `*.lproj` folders inside the framework. The packaged app therefore read English from `app.getLocale()` on a Chinese system until `extendInfo` declared `CFBundleLocalizations` (the app's nine languages); `electronLanguages` keeps Chromium's locales to the same nine.
- Icon: `build/icon.svg` → `build/icon.icns` and `icon.png` with `pnpm icon` (`rsvg-convert`, `iconutil`).
- An editor's terminal exports `ELECTRON_RUN_AS_NODE=1`, which also turns the packaged executable into Node (`bad option: --remote-debugging-port`); launching from Finder or with `open` is unaffected.
- Measured 2026-10-23 (Electron 45.0.0, release engine 1.10.8): dmg 128 MB, app 282 MB, an incremental release engine build 1 min 36 s; `dist/main.cjs` is 1.1 MB, most of it the nine i18n dictionaries.

## Smoke

`cd desktop && pnpm smoke [--app <Acpira.app>] [--engine <bin>] [--keep] [--shots DIR]` (`scripts/smoke.mjs`, macOS / Linux, needs a desktop session; run on macOS only so far) runs the real app on a temp `ACPIRA_HOME`, userData and HOME. Its only agent is `test/fake-agent.ts`, bundled into the temp folder so that only this run's processes match its path, and its settings are written beforehand (no VS Code import, English copy, the built-in agents disabled). It drives the window over the DevTools protocol: `--remote-debugging-port=0` with the port read from `DevToolsActivePort`, focus emulation, and no background throttling, so a window behind others still renders. Checks:

- a fresh home shows the open-folder state and writes no session record;
- the empty state's button and the column's "Add project" (answered by `ACPIRA_DESKTOP_PICK`) each add a project and open a session there, and one prompt in each gets the fake agent's reply;
- `@notes` lists only the shown session's project file, in both projects;
- a second launch with `acpira://session/<first>` brings the first session back;
- a language change re-renders in place: the column and the selected row stay the same nodes, and the transcript's memo rows ("Done", "To-do plan") take the new language;
- a language picked in the gear menu's submenu leaves both menus open, the page in the new language under them (picked there and back);
- the gear's layout switch, at the window's default size, lays out explorer, stage, chat and column from left to right, with the file opened in the tool panel as a stage tab, and the corner toggle folds and unfolds the column (`--shots DIR` saves `layout-files.png`); the switch closes the menus itself (the gear moves to the explorer's foot), so the step presses no Esc;
- a narrow window (an emulated 480 px viewport, `Emulation.setDeviceMetricsOverride`) drops back / forward from the title row and shows the header's second line; the toggle opens the list as a page as wide as the window, Esc (focus on the body) and a picked session close it, and widened again right after a close the column docks with no transform transition running;
- the tool panel starts closed; its toggle opens it on the project's tree, a file opens in the viewer, a switch to session B and back to A keeps alpha's tree painted in every frame (sampled by `requestAnimationFrame` for 1.5 s), "+" then Browser runs the browser page in its frame, and a loopback page sent to that tab (`panelBrowserOpen`) shows in the tab's sheet with the tab named after it (`--shots DIR` saves `panel-files.png` / `panel-browser.png`);
- "+" offers Files, Terminal and Browser in that order; Terminal opens a terminal tab that takes the focus, a line typed into it through xterm (`printf %s $$ > terminal.txt`) runs in the project folder, the tab takes the shell's name, and closing the tab ends the shell (its pid gone within 5 s; `--shots DIR` saves `panel-terminal.png`);
- "Remove from list" on a project's right-click menu (real CDP mouse events) takes the project off the column while its session's record stays;
- after SIGTERM the engine ends within its idle grace and no process runs the run's fake-agent copy.

Without `--app` it builds `dist/main.cjs` and the debug engine first; with `--app` the packaged app runs on its bundled engine unless `--engine` is given. A run takes about 35 s after the builds (34.5 s on the packaged app, 2026-10-23), most of it the engine's 30 s grace.

A mouse step fails when its point misses the element: covered by something else, or off the page (an element still sliding in). The Esc it presses carries the Mac's own native key code (`kVK_Escape` 53) on macOS. Electron 45 hands a key the page leaves alone (not `preventDefault`ed) to the macOS menu bar, and a CDP Esc carrying 27 (`kVK_ANSI_Minus` there) crashed the app with SIGSEGV in HIToolbox's input method code (2026-10-23). With 53 it crashed the same way once no menu was left to take the key (2026-10-24: two Esc after the layout switch had closed the gear menu; `NSMenu performKeyEquivalent` → `TSMProcessIronwoodSessionAction`), so the smoke presses Esc only where the page consumes it. The page's own Esc handlers consume the key for the same reason.
