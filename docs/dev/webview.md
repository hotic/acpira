# Webview

The React UI in `src/webview`: stylesheet layering, file links, slash commands and the transcript render budget.

- Host theme colors: `styles/palette.css` maps automatic mode to native widget / menu / suggestion / input roles, including their paired foregrounds. Custom card and code surfaces derive opaque tonal steps from the shell background. `tokens.css` declares defaults on both `:root` and `.acp-shell`: CSS variable references resolve at their declaration scope, so fixed themes and per-shell palettes must resolve there rather than inherit already-resolved root colors. `Popover.Popup` defaults to the widget palette; model pickers select `menu`, completion lists select `suggest`, and `DropdownMenu` always uses `menu`. Shared option state utilities carry the foreground through nested labels without tinting generic switch tracks. Menu and suggestion rows keep neutral tonal hover / selection fills derived from the popup foreground, and the composer focus ring is a neutral step above the input border: the hosts' `menu.selectionBackground`, `editorSuggestWidget.selectedBackground` and `focusBorder` are saturated accents (`#0078d4` in Dark Modern) that break the quiet palette. High-contrast themes add explicit boundaries, keyboard outlines and the `focusBorder` composer ring. Verified in the real-component LAB with injected VS Code bundled theme colors, live switching with a mounted popup, fixed schemes, inverted foreground/background roles and 380 / 1100 px layouts (2026-10-02); installed IDE behavior remains a separate host check.

- Question receipts: `chat/planSections.ts` suppresses a tool row when a `QuestionBlock.toolCallId` explicitly matches it, before any folding mode groups the turn. The pending composer card and resolved `QuestionRecord` own the interaction and answer history; the original transcript remains intact. Unlinked tools and failed-tool diagnostics remain visible. Verified with the existing LAB question fixture (2026-09-30; no new CLI wire behavior) and `test/planSections.test.ts`.

- Edited file names (`chat/ToolCall.tsx`, `chat/ToolGroup.tsx`) reuse `FileRef` and `OpenToolFileContext`, independently of earlier reads or searches. `processGroups.editReference` resolves an unambiguous location / diff source / legacy target and the first changed line; multi-file summaries remain fold labels. `ui/DisclosureRow` places the fold trigger behind the row and the file opener beside it in the DOM, avoiding nested buttons: file activation opens the editor, while the rest of the row toggles the diff. Hover / keyboard focus underlines only the filename. Validation: `test/processGroups.test.ts` and `lab/edit-file-links.preview.html` (800px / 360px; no new CLI wire behavior).

- `src/webview/` — React UI: `ui/` primitives (Row / Disclosure / Button / Chip / Card / Popover / DropdownMenu / Command / Collapsible / RadioGroup / Switch / Dialog / Toast), `chat/` conversation components, `effects/` visual effects, `styles/` stylesheets (`index.css` entry → `tokens.css` design tokens + `@theme` map, `base.css` shell defaults, `prose.css` markdown, `motion.css` animation, `chat.css` conversation shapes Tailwind cannot express at one call site). Layering: single-element styles go in the TSX className; shared shapes are `@utility`; descendant rules sit in `@layer components` so a call-site utility still wins. Only rules that must beat the unlayered host webview stylesheet or `katex.min.css` stay unlayered (`base.css` code / kbd / focus, all of `prose.css`) — a layered rule loses to them regardless of specificity; `motion.css` is also unlayered because its rail / stream rules never compete with a utility. `ui/` primitives carry their own skins (`Switch` geometry lives in the `@theme` map, not in `settings.css`); wrappers that keep an internal ref merge the caller's with `ui/mergeRefs`
- Agent markdown typography and fenced code (`chat/Prose.tsx`, `chat/CodeBlock.tsx`, `src/webview/chat/Prose.test.ts`): streamdown 2.6.0 renders `**bold**` as `<span data-streamdown="strong">`, not `<strong>`, so `styles/prose.css` matches both. The `@streamdown/cjk` plugin (remark-cjk-friendly) is on because CommonMark refuses a closing `**` preceded by punctuation and followed by a letter: `**…。**范围` stayed literal, a pattern agents write constantly in Chinese (2026-10-03). A fence is coloured only when its info string names a grammar `codeSyntax.fenceLanguage` knows (grammar id, file extension or alias); an unlabelled or `text` fence stays plain. The earlier regex highlighter painted every fence as JavaScript, so commit messages got keyword / type colours and an apostrophe in `turn's` opened a string that ran across lines. Tokens come from the same inline worker as diffs (`chat/diffHighlight.ts` `requestCodeHighlight`); the first pass is immediate, later passes wait 120 ms for a streaming fence to pause, and in between the lines already tokenized keep their colours while only the growing tail is plain. Checked in `lab/prose-code.preview.html`, dark and light
- Thought text is Markdown too (`chat/Thought.tsx` → `Prose tone="thought"`): GPT's reasoning summaries open every section with a `**Title**` line and use lists / inline code, which the former plain-text body (`whitespace-pre-wrap` + `StreamText`) showed as literal asterisks (2026-10-05). The thought tone keeps `text-2 text-fg-2`, headings at body size and bold one shade up (`.acp-thought` in `prose.css`); single newlines now fold into the paragraph like reply text. The bounded scrollport follows the paced tail through a `MutationObserver` while `Prose` reports `onBusy`. Checked in `lab/thought.preview.html` → `gpt` / `trailing`
- File links in agent markdown (`chat/fileLinks.ts`, DOM-free, `test/fileLinks.test.ts`): anchors get their href rewritten to `#acpira-file:<path>[:line]` by `rewriteFileHrefs` after rehype-raw and before sanitize / harden (a `file:` href is a hard block there and would paint ` [blocked]`), and `chat/Link.tsx` turns both anchors (`Link`) and inline code that is a workspace path (`InlineFileCode`, `parseFileLink`: relative / absolute / `C:\` paths, `:line`, `#Lline`, `file://` URIs) into `openFile` clicks. GPT also wraps whole links in backticks — `` `[Shell.tsx:240](file:///…/Shell.tsx)` `` — which reaches the inline-code path as text; `parseWrappedLink` unwraps it so the label shows and the target opens (line from the target, else the label). Anything that is not a path stays plain code; http(s) targets are not touched
- Agent images (`chat/AgentImage.tsx`) open in the shell's Lightbox on click, the same preview a dropped attachment gets (opening them as an editor tab took the reader out of the conversation); the right-click menu holds Copy image and Open in editor (the session blob through `OpenBlobContext`, else the agent's own `uri`). The `uri` caption under the image is dropped for show_image calls (`caption={false}` from `GeneratedImages`), whose row already names the files. `chat/copyImage.ts` fetches the session blob and hands `ClipboardItem` a pending PNG so the right-click gesture does not expire while it loads. Bytes with a PNG signature go through as-is (the declared MIME type is not trusted: Chromium rejects a PNG entry that does not decode); other raster types decode from the fetched bytes with `createImageBitmap` (an `<img>` on the resource URL would taint the canvas, since VS Code serves webview resources from another origin) and SVG, which `createImageBitmap` rejects, through a `data:` URL `<img>` (the CSP allows `data:` images, not `blob:`), then re-encode to PNG on a canvas. The copied / failed status shares `ui/useCopied` (`useCopyAction`) and is announced through an `sr-only` status only: a visible line under the image shifted the transcript. Generated-image results use the same component after their reveal finishes
- Slash commands are the agents' own: `available_commands_update` → `normalize.rs` (`SlashCommand { name, description, input?: { hint } }`, each update replaces the whole list, an empty one clears it) → `SessionView.commands` → `App` → `ShellProps.commands` → `composerProps.commands` (so the inline history / queue editors get the same list) → `chat/Slash.tsx` (list + hook; the pure `commandAt` / `completeCommand` / `matchCommands` / `commandHint` / `commandMarks` live in `chat/slashCommands.ts`, DOM-free so the host tsconfig can type-check their test). A `/` at the start or after whitespace with the caret inside its token (`commandAt`, the same shape as `mentionAt`, so a command / skill can also be called up mid-sentence like Cursor's `/`) opens the list (`matchCommands`: name prefix, then name substring / description word start, agent order within each tier) in the `chat/Completion.tsx` shell the `@` mention list also uses; ↑↓ move, Tab completes that token in place to `/name ` (`completeCommand`), Enter completes unless the token already is the active command (then it sends), Esc parks it by the token's `start`. Picking only edits the text — the command goes out through the ordinary `send` → `preparePrompt` → `session/prompt` and the agent runs it; the list is discovery, never a whitelist: no hit means the slash is plain text (`/tmp/file.ts` sends as typed), and nothing is rewritten, expanded or intercepted host-side (Acpira has no slash commands of its own; `/compact` for auto-compaction is the agent's). `commandHint` shows `input.hint` as a faint line under the text while the command the text ends with still has empty arguments. `PromptInput`'s mirror paints every advertised `/name` token with the command pill (`COMMAND_MARK`: the `--command` token, one blue for every agent and independent of the accent axis — it used `accent` until the pill was found transparent for every agent but Devin / Grok, since `[data-accent="agent"]` only defines those two; that axis now falls back to `--brand` for the rest) — leading or mid-sentence alike (`commandMarks`, the same boundary rules as `commandName`, so a path / partial name / punctuated tail never lights up; Cursor and Codex paint mid-sentence commands the same way) — while `turn.command` in the transcript stays a leading-token receipt. `@name` of an enabled subagent persona (settings → Subagents, what the `@` list's summon writes) gets the same pill in its own colour (`SUMMON_MARK`, the `--summon` token: violet, so a summon never reads as a command) in the composer mirror and the sent message alike (`summonMarks` / `promptMarks` in `chat/slashCommands.ts`: `@` at the start or after whitespace, exact name, longest name first since names may hold spaces, ending at whitespace / end / punctuation, so `@审查，` lights up and `@审查员` or `a@审查` do not; `Shell` hands the persona names down `Thread` → `HistoryMessage` → `UserMessage`, memoized on `personas`). A persona disabled or renamed later loses its pill in old messages (2026-10-06). `AcpSession.openSession` clears `state.commands` before `session/new` (never after — Devin advertises during the request), resume / load keep the persisted list until the peer replaces it; `sessionEdit` does the same for its fresh session. Skills the CLIs expose show up here under their own naming (Grok `/release`, Kimi / Pi `/skill:release`, Codex `/$release` — names may lead with one `$`, in `commandName` / `commandMarks` and Rust `command_name` alike — Devin `/agents:release` / `/claude:release`; `matchCommands` folds Devin's `agents:` / `claude:` copies of one skill into the first-ranked row after matching, so typing `/claude:` keeps the claude copy, and the picked name is sent verbatim — marks still paint both); the settings inventory scan (`inventory.ts`) is a read-only listing and is not turned into commands. Verify with `test/slash.test.ts`, the resume / gone cases in `tests/engine/acp_session/lifecycle.rs`, and `pnpm probe <agent> --wait 4000`
- Command / summon pills (`chat/PromptInput.tsx` `commandSegments`, `.prompt-mark` in `styles/chat.css`): the pill's background overhangs its text by a margin and padding that cancel out, because the composer mirror must keep every glyph where the textarea draws it. A full `--mark-overhang` (4 px) on both sides of a single space (about 3.6 px at 13 px) made neighbouring pills overlap and a pill touch the plain text beside it. `markRoom` (`chat/slashCommands.ts`) caps each pill at the whitespace beside it (`--mark-space` per character) minus `--mark-clear`, halved when another mark shares that whitespace. The pill uses its smaller side on both, so a run of marks reads as even pills with even gaps. A text edge or a line break keeps the full overhang; a soft wrap is not detected. Checked in `lab/prompt-marks.preview.html` (sent message and composer mirror, 2026-10-05; LAB only, not inside VS Code)
- Transcript quotes and editor context: `chat/QuoteToolbar.tsx` is mounted once per `Shell` (not in external mirrors) and watches the document selection; a non-empty selection wholly inside the thread content raises a Base UI popover anchored to the range (virtual anchor) with "Add to chat". Clicking appends a `quote` draft to the main composer through `updateMainComposer` (`chat/useComposerDraft.ts`, a module-level sink the main composer registers; updates made before it mounts are queued) and turns the popover into the optional comment field (`Quotes.tsx` `CommentEditor`: Enter saves onto that quote by identity, Esc closes); the quoted range stays painted through the CSS Custom Highlight API (`::highlight(acpira-quote)`, `base.css`) because focusing the field drops the real selection. Quotes render as one `QuoteChip` ("N annotations"; hover opens the numbered list with edit / remove per entry, and the chip's ✕ removes all) in `DraftChips`, in sent turns and in the inline editors. The editor's live selection is a module store (`chat/editorContext.ts`, `useSyncExternalStore`) fed by `App` from `editorSelection`; only the main composer, with `shareEditorSelection` on and no edit open, shows it as the toolbar `SelectionChip` (click toggles it out for this range; it collapses to its icon below the `sm` tier and splits free width with the model side so the model name stays readable). A sent selection is marked consumed and hidden until the editor reports a different one or clears it (reselecting the same range offers it again); drafts count as duplicates only when range and text both match, so two excerpts of one line are kept. Checked in `lab/history.preview.html` (headless Chrome over CDP: select → toolbar → comment → chip → hover card, a live selection chip, a paste turned into a selection chip; 2026-09-28)
- Transcript render budget: every stream chunk pushes the session view (fresh objects from `postMessage`), so `App` merges it with `shared/reuse.ts` — deep-equal subtrees keep their previous reference — and `AgentMessage` / `HistoryMessage` / `ToolCall` / `ToolGroup` / `Thought` / `Prose` / `Plan` are `memo`ized on those references; the live turn's fold states reach its rows through a per-row store subscription (`chat/autoFold.ts`), not a context value that would re-render them all. Anything that would defeat this must stay out: context values above `Thread` must not change per push (`HistoryContext` carries an `editable` flag, the composer props ride `HistoryComposerContext` only while an editor is open; `OpenToolFileContext` / `PlanDocumentContext` values are memoized, lists through `ui/useStableList`), and per-turn derived work caches by turn object. Without this a 700-block session spent ~45 ms per frame on re-rendering during streaming and every fold toggle stuttered. Verify with `scripts/probe-fold-perf.ts --stream --cpu` against the LAB server (`lab/performance.preview.html`, profile `large`): streaming must hold ~16 ms frames with no long tasks. The live-thought case needs `--stream --live` (thoughts now stream through `Prose` like replies; not re-measured since). Streamed glyph fades must not use a forwards fill: `both` kept one `CSSAnimation` per streamed character in effect (3497 at 4000 characters), and toggling a fold during a streaming thought took 280 ms frames. `StreamText` keeps only the fading tail as spans (`chat/streamGlyphs.ts`); its settled prefix is one text node. Settled turns mount fold bodies lazily (`ui/Collapsible` `LazyPanelContext`, provided `!running` by `AgentMessage`): a panel renders its body only while open, and a closed body is released after the close transition (`--dur-close` + 80 ms). Time tokens are read with their unit (`ui/cssTime.ts`): the shipped stylesheet is minified and `320ms` becomes `.32s`, so the bare `parseFloat` of 1.8.6–1.8.7 released the body 80 ms into the close and every fold snapped shut in the installed extension while the unminified LAB stayed smooth (reproduced in `performance.preview.html` with the tokens set to `.32s` on `.acp-shell`: 1681 px → 0 in one frame at 100 ms; 2026-10-06). The same read cut `ConnectedRail`'s retract and growth and the history editor's return animation. Kept-mounted closed folds held 98% of a 700-block session's 31.5k nodes, so every session switch laid all of it out (production build: one ~310 ms task, 153 ms of it `Layout`); now ~25 ms, and the cost moves to each open of an old fold (~110 ms for the largest). Until 2026-10-05 a body once opened stayed mounted, so expanding and collapsing a long history pinned its DOM for the page's lifetime: LAB `performance.preview.html` (profile `large`), every fold opened then closed, went 772 → 35.9k → 35.6k nodes with the GC'd heap 81 → 162 MB; with the release it returns to 737 nodes / 84.5 MB (headless Chrome over CDP, dev build). Hand-toggled state of folds nested inside a released body (`Disclosure`'s own `useState`) is lost with it; the turn's per-row fold memory (`useProcessFolds`) lives above the panel and survives. A live turn keeps its bodies mounted so a closed thought still streams in step. `ConnectedRail` reads no geometry while disabled or inert. Measure switches with `scripts/probe-fold-perf.ts --switch`. That probe only sees the main-thread JS cadence; the paint side needs a CDP `Tracing` run (`devtools.timeline` + `disabled-by-default-devtools.timeline{,.frame,.invalidationTracking}`) against `pnpm harness --home <copy>` with a real multi-MB session, summing `Paint` / `PrePaint` / `UpdateLayoutTree` per second and counting `DroppedFrame`. Two findings from a 64k-node session: the running-verb shimmer used to animate `background-position` on a `background-clip: text` gradient, a paint property, so one shimmering span re-painted the whole document layer every frame (~455 ms of `Paint` per idle second, ~3 ms a frame before any click) — `ui/Shimmer` now draws the label twice and slides a masked copy with transforms only (`Paint` ≈ 3 ms/s, same as no shimmer; `will-change` on the span does not help, the walk is the scroller's). And each exchange `section` carries `contain-paint` (with `-mx-hit -mb-hit px-hit pb-hit` so row hit areas and card shadows are not clipped, top edge untouched for the stuck sentinel): paint containment gives the section its own paint offset, so a fold opening mid-thread no longer re-walks every later exchange in `PrePaint` each frame (dropped frames per toggle 16–21 → 1–5). What remains is one ~60 ms frame when a fold with hundreds of rows first opens (`inert` flip → subtree style recalc + React commit), not a per-frame cost. streamdown's animate plugin wraps every character of an animated block in a `[data-sd-animate]` span and keeps a plugin per block, so while a turn streams every block it ever animated stays one span per character: reported 2026-10-07 on Windows VS Code (extension 1.8.8) during a long Claude Opus thinking run, the window's webview renderer held a core at ~100% and grew to 3.3 GB; reproduced in `pnpm harness` with a fake agent streaming one thought at ~400 chars/s (headless Chrome over CDP): after 60 s the thought held 13.8k spans and 4 s of trace spent 2.8 s on the main thread (style recalc, PrePaint, compositing inputs, layout, script, all scaling with the span count). `Prose` now passes streamdown a `BlockComponent` (`SettlingBlock`) that strips the animate plugin from every block more than one behind the streaming tail (the block counter rides a per-instance `parseMarkdownIntoBlocksFn`), so those render as plain text again: same run, ~1.3k DOM nodes after 90 s and a flat main-thread cost instead of one that climbs to saturation. Not re-checked inside VS Code
- Session patches (`shared/sessionPatch.ts`, `acpira-shared/src/session_patch.rs`): a page that posts `ready` with `patches: true` (the real webview always does; tests and scripts that omit it keep getting whole views) gets `sessionPatch` instead of `session` once it holds a view. `view_msg` encodes every visible turn on its own, the last agent turn also block by block, and splices the whole view from the same fragments, so the transcript is still serialized once per change; `BridgeCore::deliver` diffs that encoding against what the page was sent last (after the 30 ms batch, under one lock) and sends the turns from the first changed one, or for the same last agent turn only its head plus the blocks from the first changed one. A resync and a view without fragments (ChatGPT mirrors) reset the base, so the next push is whole. `init` resets it to the view it carries: the next push of the session on screen is a patch against init's copy. A page's first `ready` posts init once the session on screen has a view (its record is read), not after its agent has started and resumed, and pushes before that init are dropped since init carries them. Measured 2026-10-09 in `pnpm harness` (debug sidecar, headless Chrome) on a copy of an 8.4 MB, 4591-block Claude session whose agent could not sign in: opening it sent the 7 MB view three times (`session`, `init`, `session` again, 21 MB) and init arrived ~3.4 s after `ready`, the page blank until then; now one 7 MB init ~0.9 s after `ready`, the agent's later status as 26 KB patches. The same week a Windows VS Code window reported an LCP of 19.6 s for the panel, not re-measured there; a snapshot older than the base (a batch flushed after a resync answered with a newer view) is dropped instead of becoming the base. The live turn is encoded once: its whole encoding is the head with the encoded blocks spliced in at `"blocks":[]`. The page applies a patch only on the exact `base` rev it holds; anything else posts `resync` once and the host answers with the whole view. Kept turns stay the same objects, so `reuse` returns at once on them. Measured before the change with the fake agent on a 4 MB view: one model switch = one 4 MB push, one effort pick = 8 MB, ~2 s of streaming = 17 pushes / 68 MB plus 17 copies of the session list; `test/sessionPatch.test.ts` streams into a 400 KB history with every later message under 50 KB and checks that the rebuilt view equals a whole-view page's. Reported 2026-10-04 on VS Code 1.140.0 over Remote-SSH (sidecar 1.8.4, linux-x64): after a long Codex turn the model chip took ~20 s to change and the transcript jumped as the backlog of whole views drained; the remote host's logs were not available, so the backlog is inferred from the code path and the measurement above. The VS Code shell adds the second half (`host/outbox.ts`): one `postMessage` in flight per webview, and while it waits a whole view replaces the queued pushes of its own session and the queued whole views of other sessions together with the patches chained after them (patches of another session that rest on a view the page keeps stay, the page cache below needs them), a patch folds into the push queued before it (`mergeSessionPatches`) and the session list keeps its latest copy, never across another message type. A session push the webview refuses (`postMessage` answers false or fails) makes the shell post `resync` itself, once until a whole view or `init` is delivered; `clear()` on a page reload drops what the old page still had in flight. A post slower than 2 s is logged (`webview post of … took …`, at most every 30 s), the first thing to look for when a remote window lags. The manager also skips a session list identical to the one it pushed last, which is every streamed chunk; after posting `init`, `ready` queues the current list once more through `sessions_in_order` (under the same lock as the manager's list pushes), since a batched list that reached the page around init could lose to init's older copy and never be repeated
- Session view cache (`SentViews` in `acpira-shared/src/session_patch.rs`, `webview/sessionViews.ts`, 2026-10-06): the bridge keeps the last view it sent of each of the 8 most recently shown sessions (`SENT_VIEWS_MAX`, and at most 32 MiB of encoded views, the view on screen always kept), the page keeps the same views (`VIEW_CACHE_ENTRIES`, never fewer than the host's), so switching back to a session is a patch against the copy the page already holds (only what changed meanwhile) instead of the whole transcript again. Every `AcpSession` instance has its own view `epoch` (`next_view_epoch`; a mirror's poll copies share one per chain), and no patch is computed across epochs, since a reopened instance counts its revs from 0 again. The stale check applies to the view on screen only; a whole view of another session is taken at any rev. `init` clears both caches, a `resync` forgets the active session's entry on the host, and a patch the page cannot apply drops its kept copy before posting `resync`. Diff file texts never reach the page (`DiffSource.omitted`, `docs/dev/transcript-pipeline.md`), which keeps the cached views small. Reported 2026-10-06 on VS Code Remote-SSH to gen1 (sidecar 1.8.7, linux-x64): switching between two sessions, or into an empty one queued behind a long one, took seconds; the host log showed single whole-view posts of 2–3.7 s, and the 8.6 MB view was 7.3 MB of edit `oldText` / `newText`. Verify with `test/sessionViews.test.ts`, `test/outbox.test.ts` and the `SentViews` tests in `session_patch.rs`
- Interface languages (`src/shared/i18n/`, 2026-10-04): `LOCALES` ships zh-CN, zh-TW, en, ja, ko, es, de, fr and ru; en and zh-CN stay complete (`satisfies Record<MsgKey, string>`), the others are `LocaleDict` (`Partial` plus plural variants), so a key missing there falls back to en and strings identical to en (brand names, units, MCP) are left out. Counted strings take CLDR plural variants as `<key>#one` / `#few` / `#many` next to the plain key (the fallback form), picked from the `n` / `count` param by `pluralCategory`; the Rust `plural_category` mirrors it and both are pinned by the same table in `test/i18n.test.ts` and `acpira-shared` unit tests. Russian is the only locale using `#few` / `#many`; avoid plural-sensitive wording where a colon form works (`файлов: 3`). `resolveLocale` maps `zh-Hant` / `TW` / `HK` / `MO` to zh-TW, other `zh` to zh-CN and the rest by primary subtag; `scripts/export-rust-i18n.ts` writes one JSON per locale for the engine. zh-TW was produced from zh-CN with OpenCC (cn → twp) and reviewed by hand; the other dictionaries are machine translations without native review. Per-locale extras: `commandPresentation.ts` (slash-command descriptions for zh-CN / zh-TW only), the `permissionOptions.ts` wrapper regex built from every locale's `host.needApprovalFor`, and the CJK compact-time separator in `ui/QuotaBars.tsx`. `.vscodeignore` ships every `package.nls.*.json`.
