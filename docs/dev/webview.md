# Webview

The React UI in `packages/ui`: how to check it, stylesheet layering, markdown and links, slash commands, and the render budget every stream chunk depends on. Component rules are in `ui-conventions.md`, motion and layout in `ui-motion-layout.md`.

## Checking visual work

- Browser harness (`pnpm harness [port]`, `acpira --ws` from a cargo release build, page in `test/host-preview/`): the real webview bundle against the real sidecar and CLIs, no IDE. Open the URL printed on stderr (`http://127.0.0.1:7357/?token=…`); the handshake token is required. Query parameters: `host=editor`, `agent=<id>`, `theme=light`, `cwd=/abs/path`. Data lives under `~/.acpira/harness` unless `--home` is given, the page's own hello `agents` is ignored, and its settings live in `localStorage`. Run `pnpm build` first.
- LAB (`lab/`, local only): `lab/*.preview.html` pages render the real components with fake data; it serves unminified CSS, so anything that parses stylesheet values must also be checked in a production build (see time tokens below). If Vite's watcher misses an edit, restart the LAB server.
- Performance: `scripts/probe/fold-perf.ts` (`--stream`, `--switch`) and `scripts/probe/startup.ts` against the LAB / harness, `lab/session-list-perf.run.mjs` for the list, `lab/perf/run.sh` and `lab/tauri-shell/bench.mjs` for WebKit. These time the main thread only; paint and compositor gaps need a CDP `Tracing` run or a screencast.

## Structure and stylesheets

- `packages/ui/`: `ui/` primitives, `chat/` conversation, `settings/`, `panel/` (desktop tool panel), `browser/` (browser panel), `effects/`, `styles/` (`index.css` → `tokens.css`, `base.css`, `prose.css`, `motion.css`, `chat.css`, …).
- Layering: single-element styles go in the TSX className, shared shapes are `@utility`, descendant rules sit in `@layer components` so a call-site utility still wins.
- An unlayered rule beats every utility regardless of specificity, so only rules that must beat the unlayered host webview stylesheet or `katex.min.css` stay unlayered (`base.css` code / kbd / focus / scrollbars, all of `prose.css`), plus `motion.css`. Enforced by `packages/ui/test/css-layers.test.ts`.
- Custom properties resolve where they are declared, so `tokens.css` declares defaults on both `:root` and `.acp-shell`; fixed themes and per-shell palettes must redeclare there instead of inheriting resolved root colours.
- Host theme colours map to native roles in `styles/palette.css`. Hover, selection and the composer focus ring are neutral tonal steps: the hosts' `menu.selectionBackground`, `editorSuggestWidget.selectedBackground` and `focusBorder` are saturated accents. High-contrast themes add explicit boundaries.
- Wrappers that keep an internal ref merge the caller's with `ui/mergeRefs`.

## Markdown and prose

- streamdown 2.6 renders `**bold**` as `<span data-streamdown="strong">`, so `prose.css` matches both. `@streamdown/cjk` stays on: CommonMark refuses a closing `**` after punctuation followed by a letter, which Chinese replies write constantly.
- Fenced code (`chat/CodeBlock.tsx`) is coloured only when its info string names a grammar `codeSyntax.fenceLanguage` knows; an unlabelled fence stays plain.
- Every fence line is its own block (`.code-line`): WebKit lays a whole block out again when text changes beside an inline box and parks the old layout (`desktop.md`, page memory). Lines keep their newline so a selection copies the source.
- The `<code>` carries the `<pre>`'s end padding itself (`base.css`): neither WebKit nor Blink adds a scroller's end padding after block children.
- Thoughts render through `Prose tone="thought"` (GPT reasoning summaries are Markdown).
- Task notices (`chat/taskNotes.ts`): Claude sometimes imitates a `<task-notification>` in its own reply. Each is moved into its own HTML block first (the HTML parser closes a `<p>` at `<summary>`), then rewritten before sanitize into one quiet `Row` saying the model wrote it.
- File links (`chat/fileLinks.ts`, `chat/Link.tsx`): hrefs become `#acpira-file:<path>[:line]` after rehype-raw and before sanitize / harden, where a `file:` href would paint ` [blocked]`. Inline code that is a path opens too, backtick-wrapped links are unwrapped, and the engine expands `~` (`resolve_open_path`). The parser percent-encodes non-ASCII and spaces in an href, so a plain path target is decoded after its line suffix is read, as a `file:` URL already is; a name that really holds `%XX` cannot be told apart.
- Session links (`shared/sessionLinks.ts`): `acpira://session/<id>` and `vscode://hotic.acpira/session/<id>` become `#acpira-session:<id>` the same way and open in the page itself through `OpenSessionContext`. Bare links in prose are not linkified.
- Image copy (`chat/copyImage.ts`) hands `ClipboardItem` a pending PNG so the gesture does not expire. PNG-signature bytes go as-is (Chromium rejects an entry that does not decode).
- A GIF copy goes to the shell instead (`hostImageCopy`): the web clipboard takes PNG only, so a GIF would paste as one frame. The shell writes the bytes to a temp file and puts that file on the system clipboard (macOS adds the GIF data). The desktop app answers through `acpira_copy_image`; VS Code through the shell-only `copyImage` / `copiedImage` messages, offered only on a local macOS / Windows extension host (`imageCopy` boot flag). IntelliJ and VS Code on Linux keep the one-frame PNG. The choice is made from the declared type and names before any await, so the PNG path stays inside the click.
- Other rasters decode from fetched bytes with `createImageBitmap`: an `<img>` on the resource URL taints the canvas, since VS Code serves resources from another origin. SVG goes through a `data:` `<img>` (the CSP allows `data:`, not `blob:`).
- Copy feedback under an image is an `sr-only` status: a visible line shifted the transcript.
- HTML widgets (`chat/AgentWidget.tsx`, `chat/widgetDoc.ts`; details in `transcript-pipeline.md`): `App.tsx` drops messages from widget frames.

## Slash commands and pills

- Slash commands are the agents' own (`SessionView.commands` → `chat/Slash.tsx`, pure logic in `chat/slashCommands.ts`). The list is discovery, never a whitelist: nothing is rewritten, expanded or intercepted host-side, and an unmatched `/tmp/x` sends as typed. Acpira has no slash commands of its own.
- A `/` or `@` sigil also opens after CJK text and full-width punctuation (`SIGIL_LEAD`): Chinese puts no space before `然后/review`.
- `AcpSession.openSession` clears the commands before `session/new`, never after: Devin advertises during the request.
- Skill naming differs per CLI (Grok `/release`, Kimi `/skill:release`, Codex `/$release`, Devin `/agents:release` and `/claude:release`); `matchCommands` folds Devin's two copies into one row. Tests: `packages/ui/test/slash.test.ts`.
- Command / summon pills (`chat/PromptInput.tsx`, `.prompt-mark`): the composer mirror must keep every glyph where the textarea draws it, so a pill's overhang is margin and padding that cancel, capped by `markRoom` at the whitespace beside it. The command pill uses `--command`, not the accent axis, which defines only some agents.

## Render budget

- **Transcript render budget**: every stream chunk pushes a fresh view, so `App` merges it with `shared/reuse.ts` (deep-equal subtrees keep their reference) and `AgentMessage` / `HistoryMessage` / `ToolCall` / `ToolGroup` / `Thought` / `Prose` / `Plan` are `memo`ized on those references. Nothing may defeat this.
- Context values above `Thread` must not change per push (memoize them, lists through `ui/useStableList`); per-turn derived work caches by turn object; fold state reaches rows through a per-row store subscription (`chat/autoFold.ts`), never a context value.
- Fold bodies mount lazily (`ui/Collapsible` `LazyPanelContext`) and a closed body is released after the close transition; only running or streaming items keep a closed body mounted. State of folds nested inside a released body is lost; the turn's fold memory lives above it.
- Trap: time tokens are read with their unit (`ui/cssTime.ts`). The shipped stylesheet is minified (`320ms` → `.32s`); a bare `parseFloat` snapped every fold shut in the installed extension while the LAB stayed smooth.
- A live turn opened mid-turn renders its tail first and mounts earlier items in idle slices (`chat/tailWindow.ts`); long transcripts mount the last exchanges first (`useExchangeWindow` in `chat/Shell.tsx`). The thread has `overflow-anchor: none`, so a slice keeps the view itself, reading "at bottom" from geometry, not `FollowState`. Both windows share `chat/sliceScroll.ts`: WebKit rounds scroll offsets but not layout, so the content's subpixel top margin absorbs the measured scroll error after each slice; measuring the content's edge also works under page zoom, where `scrollTop` hides a fractional physical offset. That margin belongs to slice anchoring.
- Rows mounted by the first commit or a slice skip their entrance (`QuietEntranceContext`) and streaming text shows at once. A switch back to a kept session stays quiet until the host's catch-up reply lands (`SessionViews.catchingUp`), otherwise every row run meanwhile replays its entrance.
- `ui/Collapsible.Panel` reads `OpenContext` directly rather than mounting Base UI's height-measuring panel; closed `ProcessBlocks` defer grouping until opened.
- Streamed glyph fades never use a forwards / `both` fill: each glyph's animation stays in effect. Blocks more than one behind the tail drop streamdown's animate plugin (`SettlingBlock`), whose per-character spans otherwise grow without bound.
- The tail blocks use `chat/glyphRuns.ts`: one span per fading run; a finished run keeps its span and only loses the class. Removing spans from a live paragraph makes WebKit discard and park its line layout (`desktop.md`, page memory).
- streamdown 2.6 caches its processors by the plugins' function names, so the glyph-run plugin needs a name of its own per block.
- Paint: shimmer must move transforms only (`ui/Shimmer` draws the label twice); a `background-position` shimmer on `background-clip: text` repainted the whole document layer every frame.
- Each exchange `section` carries `contain-paint` so an opening fold does not re-walk later exchanges; its clip is pushed out by `--hit` (left, bottom) and `--hit-end` (right) for hit areas and shadows.
- **Session list render budget**: list pushes merge with `reuseById`; rows (`Item`) are memoized on plain flags plus one `RowActions` ref, and per-project menu slices come from per-cwd caches (`useReused`), so no inline closure or filtered array defeats the memo.
- Session rows use `content-visibility: auto` to skip off-screen rows and keep `.mark-flip` 3D layers out of compositing. WebKit opts out (`chat.css`, `-webkit-nbsp-mode` feature query): the desktop list can paint a row's hover fill while its entire contents stay blank. The workaround keeps those rows in the paint tree; the exact compositor trigger is unverified.
- WebKit parity: `.scroll-fade` applies its mask only while `data-more-above` / `data-more-below` is set; `WorkingBeam` is an overlay sibling (`contain: strict`), not a wrapper around the composer; `[data-thread]` has no `container-type: size`, and the sticky prompt cap reads the viewport: a custom property takes its `var()`s where it is declared, so a height set on the thread never reached `--user-message-max` on the root.
- WebKit restyles every element when a `<style>` element is removed or the `@property` registry changes. border-beam writes per-instance `@property` rules (`useId`), so the composer frame and its `WorkingBeam` stay mounted across session switches and only the field remounts (`Composer` `resetKey`); remounting the beam with the field restyled the whole document on every switch.
- Layout rules for the desktop tool panel key off the shell's direct children (`:has(> [data-tool-panel-wrap][data-shown])`) so panel state never re-renders `Shell`. The docked subagent pane is the exception (`data-subagent-docked` on the root): a `:has()` for it kept matching in the desktop app after it closed.
- A `:has()` sits on the element it styles or looks only at direct children (`:has(> …)`). Tailwind's `group-has-*` (`.group:has(…) *`) left Chromium unable to narrow it: every node inserted anywhere, a streamed chunk or a viewer block coming near, restyled the whole shell.
- Long panel lists (file viewer, tree, review diff) render in `content-visibility: auto` chunks inside `contain: strict` scrollports; line numbers turn sticky only after a horizontal scroll (`[data-scrolled-x]`), and highlight commits wait for scroll idle (`diffHighlight.ts`) or the end of a resize (`markShellResize` in `panel/api.ts`).
- The file viewer's and the tree's chunks get their rows only once near the scroller (`panel/nearBlocks.ts`): `content-visibility` skips layout and paint but still creates and styles every node, which froze WebKit on a large JSON file or folder. A chunk out of sight holds an estimate: its rows' wrapped lines at the measured column count (`FileViewer` `rowLines`; one line a row came out a few times short, so a drag to the end stopped short), and jumps beyond a screen still go at once and re-centre while the chunks around the target settle (`centerRow`). Scroll anchoring does not reliably hold the view when the measured column count changes every estimate (a jump made while the viewer grew in beside the tree ended far off its target), so the viewer puts the row in the middle of the view back itself. A selection across chunks without rows has none of their text, so the viewer builds that copy from its rows, also for the file's part of a selection dragged on past the viewer.
- A long Markdown file previews in parts mounted a frame apart (`panel/previewParts.ts`), since one Streamdown parse of a large file held a long frame. The invariant is that the parts render exactly as the whole: a part only starts where both CommonMark and the HTML parser have closed everything, link definitions are copied in front of the parts that name them, and whatever the line scan cannot place keeps the rest in one part (a definition it cannot place keeps the document whole when a part above may name it: by its label's words, or for a footnote by any footnote mark, since footnotes number in document order). The scan models the parser's stack, table cells and scopes included; an element opened by a tag that may be text counts as open but in doubt, and a sure tag whose effect it would change stops the scan. Traps it encodes (micromark 4.0, micromark-extension-gfm-table 2.1, hast-util-raw 9.1): after indented code (past blank lines too) or a definition, a list numbered past 1 cannot start; a GFM table's one-cell delimiter row needs only a colon (`:-`), its body takes rows without a bar and setext underlines, and ends at a tag alone on its line, indented code or any list item; over a delimiter row a tag alone on its line breaks into a paragraph as an HTML block and a definition becomes the header; a tag in a cell reaches nothing open before its line; a line without markers is a lazy one only after a paragraph in a list item or quote, and otherwise stands past the list or quote; an item with nothing on its marker's line takes nothing past a blank line; an unquoted attribute value ends at `/`, which must then close the tag; only a byte order mark at the very start is dropped; a table opened in inline content takes in the end of an emphasis or link around it, which then reopens past the table; the adoption agency moves a formatting element down through eight special elements at most, so past that a copy reopens later; it drops the ordinary elements in between, and formatting ones past the third; three alike formatting elements at most wait to reopen; an `a` closes an `a` still open, and so does a Markdown link; the elements Markdown makes (emphasis, strikethrough, links) go through the same tree building as tags, so around a tag after one closed the paragraph or heading, or in a heading's line, they leave elements open or closed otherwise; a heading's start closes a heading only as the current node once the paragraph is closed, without reopening formatting elements; a bare URL takes in a backtick or `$`; a section's end tag in a cell does nothing unless that section is open; the whole is parsed as a template-context fragment like each part, so only later parts read a leading table part or `</p>` otherwise (that part joins the one above). Check a rule change by rendering whole against parts, over differential fuzzers that build one construct family's transitions each (random tag soup misses them) and a large corpus of real Markdown, not only the unit cases. A heading that opens a later part gets its gap back in `prose.css`. A part skips layout and paint out of sight (`content-visibility`) only after its first layout, so its remembered size keeps the document's height exact; skipped from the start, it would stand at an estimate until scrolled to. Without it, every relayout of the panel in WebView2 went through the whole document.
- Highlighting runs in one worker (`chat/codeDiff.worker.ts`), for the scheme on screen only: each scheme is a whole grammar pass, so a switch asks again and the code shows plain until then. `tokenizeCode` slices a long source by characters, at most twice the last slice (sized by lines, a run of blank lines sized the next slice to a whole dense file), and lines it does not tokenize (blank, or past its length cap) leave the rate alone, with the grammar state carried over, and the runs take turns, so a short request never waits for a long one; an aborted request is cancelled in the worker. The file viewer's requests (its text, and its removed hunks as one more) skip the in-flight cap and get colours in parts from the top; so do fences in sight (`CodeBlock`, one shared `IntersectionObserver`), and a waiting one the reader scrolls to, since in page order the end of a long answer, the part on screen, coloured last. A streaming fence keeps one pass with the worker: text it has since extended does not withdraw it, and the next pass follows its landing. Withdrawn on every reveal tick, no pass landed before the fence stopped. JavaScriptCore compiles shiki's default `v`-flag regexes slowly (each rule's first use stalls), so WebKit hosts build ES2018 regexes, which give the same tokens; V8 runs those slower, so Chromium hosts keep the default (chosen from the worker's `userAgent`).
- The UI face loads at bundle start (`fontPreload.ts`, from `window.__acpira.font`); otherwise the first transcript frames draw in the fallback and re-wrap.
- Startup: `main.js` / `main.css` keep fixed names; mermaid, the highlighting worker with shiki, img-fx and xterm load as `import()` chunks under `assets/`. Chunks import `../main.js` back, so hosts must load the entry by that plain URL (a query string evaluates a second copy). Modulepreload links are off (no nonce); all CSS stays in `main.css`.
- Dates format through `i18n.ts` `dateFormat` (one cached `Intl.DateTimeFormat` per locale and options), never one per row.

## Session patches and view cache

- **Session patches** (`shared/sessionPatch.ts`, `acpira-shared/src/session_patch.rs`): a page that posts `ready` with `patches: true` (the real webview always does) gets `sessionPatch` once it holds a view. `BridgeCore::deliver` diffs against what that page was sent last: turns from the first changed one, or the live turn's changed blocks.
- The page applies a patch only on the exact `base` rev it holds, otherwise posts `resync` once and gets the whole view.
- Revs are compared only within one epoch (per session instance or follow subscription), and the page takes every whole view without comparing revs (`sessionViews.ts` `adopt`). Comparing across epochs once froze a page after another engine took the session over (`test/sidecarEngine.test.ts`).
- The VS Code shell keeps one `postMessage` in flight per webview (`apps/vscode/src/outbox.ts`): a whole view replaces queued pushes of its session, patches fold together, and a refused post makes the shell post `resync`. A post slower than 2 s is logged (`webview post of … took …`), the first thing to check when a remote window lags.
- **Session view cache** (`SentViews`, `packages/ui/sessionViews.ts`): host and page keep the last view of recently shown sessions, so a switch back is a patch and `SessionViews.select` shows the kept view at once. `init` clears both caches. Diff file texts never reach the page (`DiffSource.omitted`), which keeps views small.

## Other surfaces

- First run and interface tour (`welcome/`; shell side in `desktop.md` and `host-architecture.md`): the layer is a fixed sibling of whatever shell is under it, never a portal, so it survives the swap from the sample shell to the real one at `init` and fades out over the real one. The sample is the real `Shell` with `sample` (column docked, no tool panel) inside an `inert` wrapper. Steps find their targets by DOM queries into it (`STEPS` in `Welcome.tsx`): renaming a class or icon there silently drops a step. Target visibility ignores only the outer sample wrapper's `inert`; internal inert branches (closed drawers, folded header actions) are not targets even if their SVG still has a box. Narrow layouts light the visible list toggle; settings use the session menu only on desktop, while IDEs keep a separate gear. The controls follow the shell's actual dock/drawer state, not a second CSS breakpoint, and their measured row stays clear of captions and leader paths. Before `init` the locale comes from the boot config (`firstRun` / `tourPage`).
- Browser panel (`browser/BrowserPanel.tsx`; host side in `host-architecture.md`): the same bundle with `window.__acpira.host === 'browser'`, no `App` and no session state. Shapes and URL redaction in `packages/shared/picker.ts`, the in-page side in `packages/picker/`.
- The panel takes messages only from `window.parent` in their declared shape (`hostMsgOf`): frames inside the page can post to it too.
- Pinning the same context again replaces the earlier chip (`addContext` in `App.tsx`); dropping it as a duplicate lost comments on re-picked elements.
- Desktop tool panel (`panel/`, behaviour in `desktop.md`): `store.ts` is a module store so links and menus reach it without props; `ToolPanelDock` stays mounted after the first open so browser pages survive a close.
- Transcript quotes (`chat/QuoteToolbar.tsx`, once per `Shell`): the quoted range stays painted through the CSS Custom Highlight API (`::highlight(acpira-quote)`), because focusing the comment field drops the selection. A quote inside a nested scrollport hides its button once the selection leaves that scrollport.
- `ui/useMorph` (quote and pick popovers) sizes through a `ResizeObserver` on a callback ref, because Base UI mounts the popup on its own render; it only grows and is skipped under the motion kill switch.
- Editor and tool selections (`chat/editorContext.ts`) show as live chips that never make an empty composer sendable.
- Session list: the row hover cluster is move / pin only, everything else is in the context menu (`RowContextMenu` in `chat/SessionMenu.tsx`). Its menu root mounts on the row's first right-click: a root per row was most of the cost of mounting a long list, so other long lists follow the same pattern. The view menu (`chat/ViewMenu.tsx`, logic in `chat/sessionView.ts`) reads the stored view value by value (`readView`), so a view from another build never breaks the list.
- The docked session column keeps its scrollbar gutter (`scroll-stable`) so a fold that ends the overflow moves nothing sideways, and sizes through CSS `clamp()` so a window resize re-renders nothing. Project rows cross-fade their trailing actions on one grid cell so nothing moves on hover.
- Copy submenu (`SessionMenu` → `Shell.copySession`): link, Markdown, working directory. The Markdown is fetched, so `ui/useCopied.ts` `writeClipboardLater` writes a `ClipboardItem` holding the pending text inside the click (user activation would expire), falling back to `writeText`. Unverified under JCEF.
- Fork boundary (`chat/ForkBoundary.tsx`) is a `Row` of its own after the exchange, never inside it (exchange spacing keys off an exchange ending in an action row), and carries the reply inset itself: a bare interactive `Row`'s `-mx-hit` pushed out a horizontal scrollbar.
- Interface languages (`packages/shared/i18n/`): en and zh-CN are complete, the rest are `Partial` and fall back to en. Plurals use `<key>#one` / `#few` / `#many`, mirrored by Rust `plural_category` against one test table; `scripts/export/rust-i18n.ts` writes the engine's JSON.
- A language change re-renders in place: every `memo` component that prints strings, or whose element a parent caches in `useMemo` (the desktop gear menu), calls `useLocale()` and string caches take the locale as a dependency. Never remount on `key={locale}`: it replayed every entrance, closed open menus and reset scroll.
