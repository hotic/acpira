# Webview

The React UI in `packages/ui`: stylesheet layering, file links, slash commands and the transcript render budget.

- Host theme colors: `styles/palette.css` maps automatic mode to native widget / menu / suggestion / input roles, including their paired foregrounds. Custom card and code surfaces derive opaque tonal steps from the shell background. `tokens.css` declares defaults on both `:root` and `.acp-shell`: CSS variable references resolve at their declaration scope, so fixed themes and per-shell palettes must resolve there rather than inherit already-resolved root colors. `Popover.Popup` defaults to the widget palette; model pickers select `menu`, completion lists select `suggest`, and `DropdownMenu` always uses `menu`. Shared option state utilities carry the foreground through nested labels without tinting generic switch tracks. Menu and suggestion rows keep neutral tonal hover / selection fills derived from the popup foreground, and the composer focus ring is a neutral step above the input border: the hosts' `menu.selectionBackground`, `editorSuggestWidget.selectedBackground` and `focusBorder` are saturated accents (`#0078d4` in Dark Modern) that break the quiet palette. High-contrast themes add explicit boundaries, keyboard outlines and the `focusBorder` composer ring. Verified in the real-component LAB with injected VS Code bundled theme colors, live switching with a mounted popup, fixed schemes, inverted foreground/background roles and 380 / 1100 px layouts (2026-10-02); installed IDE behavior remains a separate host check.

- Question receipts: `chat/planSections.ts` suppresses a tool row when a `QuestionBlock.toolCallId` explicitly matches it, before any folding mode groups the turn. The pending composer card and resolved `QuestionRecord` own the interaction and answer history; the original transcript remains intact. Unlinked tools and failed-tool diagnostics remain visible. Verified with the existing LAB question fixture (2026-09-30; no new CLI wire behavior) and `packages/ui/test/planSections.test.ts`.

- Edited file names (`chat/ToolCall.tsx`, `chat/ToolGroup.tsx`) reuse `FileRef` and `OpenToolFileContext`, independently of earlier reads or searches. `processGroups.editReference` resolves an unambiguous location / diff source / legacy target and the first changed line; multi-file summaries remain fold labels. `ui/DisclosureRow` places the fold trigger behind the row and the file opener beside it in the DOM, avoiding nested buttons: file activation opens the editor, while the rest of the row toggles the diff. Hover / keyboard focus underlines only the filename. Validation: `packages/ui/test/processGroups.test.ts` and `lab/edit-file-links.preview.html` (800px / 360px; no new CLI wire behavior).

- `packages/ui/` — React UI: `ui/` primitives (Row / Disclosure / Button / Chip / Card / Popover / DropdownMenu / Command / Collapsible / RadioGroup / Switch / Dialog / Toast), `chat/` conversation components, `effects/` visual effects, `styles/` stylesheets (`index.css` entry → `tokens.css` design tokens + `@theme` map, `base.css` shell defaults, `prose.css` markdown, `motion.css` animation, `chat.css` conversation shapes Tailwind cannot express at one call site). Layering: single-element styles go in the TSX className; shared shapes are `@utility`; descendant rules sit in `@layer components` so a call-site utility still wins. Only rules that must beat the unlayered host webview stylesheet or `katex.min.css` stay unlayered (`base.css` code / kbd / focus, all of `prose.css`) — a layered rule loses to them regardless of specificity; `motion.css` is also unlayered because its rail / stream rules never compete with a utility. `ui/` primitives carry their own skins (`Switch` geometry lives in the `@theme` map, not in `settings.css`); wrappers that keep an internal ref merge the caller's with `ui/mergeRefs`
- Agent markdown typography and fenced code (`chat/Prose.tsx`, `chat/CodeBlock.tsx`, `packages/ui/chat/Prose.test.ts`): streamdown 2.6.0 renders `**bold**` as `<span data-streamdown="strong">`, not `<strong>`, so `styles/prose.css` matches both. The `@streamdown/cjk` plugin (remark-cjk-friendly) is on because CommonMark refuses a closing `**` preceded by punctuation and followed by a letter: `**…。**范围` stayed literal, a pattern agents write constantly in Chinese (2026-10-03). A fence is coloured only when its info string names a grammar `codeSyntax.fenceLanguage` knows (grammar id, file extension or alias); an unlabelled or `text` fence stays plain. The earlier regex highlighter painted every fence as JavaScript, so commit messages got keyword / type colours and an apostrophe in `turn's` opened a string that ran across lines. Tokens come from the same inline worker as diffs (`chat/diffHighlight.ts` `requestCodeHighlight`); the first pass is immediate, later passes wait 120 ms for a streaming fence to pause, and in between the lines already tokenized keep their colours while only the growing tail is plain. Checked in `lab/prose-code.preview.html`, dark and light

- File links in agent markdown (`chat/fileLinks.ts`, DOM-free, `packages/ui/test/fileLinks.test.ts`): anchors get their href rewritten to `#acpira-file:<path>[:line]` by `rewriteFileHrefs` after rehype-raw and before sanitize / harden (a `file:` href is a hard block there and would paint ` [blocked]`), and `chat/Link.tsx` turns both anchors (`Link`) and inline code that is a workspace path (`InlineFileCode`, `parseFileLink`: relative / absolute / `C:\` paths, `:line`, `#Lline`, `file://` URIs) into `openFile` clicks. GPT also wraps whole links in backticks — `` `[Shell.tsx:240](file:///…/Shell.tsx)` `` — which reaches the inline-code path as text; `parseWrappedLink` unwraps it so the label shows and the target opens (line from the target, else the label). Anything that is not a path stays plain code; http(s) targets are not touched. The engine resolves a clicked path against the session cwd, except `~` / `~/…`, which it expands to the engine user's home (`resolve_open_path` in `bridge_core.rs`): agents cite `~/.agents/plans/…`, and a plain join opened a missing `<cwd>/~/…`
- Session links in agent markdown (2026-10-16): `rewriteFileHrefs` first rewrites an anchor whose href is a session link (`acpira://session/<id>`, `vscode://hotic.acpira/session/<id>`, `shared/sessionLinks.ts`) to `#acpira-session:<id>`, before sanitize / harden would paint it ` [blocked]`. `Link` and `InlineFileCode` (a bare link or a whole `[title](link)` in backticks, `parseCodeSessionLink`) open it through `OpenSessionContext`, which the Shell provides: select that session in this view and close the drawer, like a history row. Bare links in prose are not linkified, as with file links. The shell's `showSession` HostMsg (a link opened from outside, a notification's Open) selects the session and leaves the settings page. `packages/ui/chat/Prose.test.ts` and `packages/ui/test/fileLinks.test.ts` cover the rewrite and the clickable forms.
- Agent images (`chat/AgentImage.tsx`) open in the shell's Lightbox on click, the same preview a dropped attachment gets (opening them as an editor tab took the reader out of the conversation); the right-click menu holds Copy image and Open in editor (the session blob through `OpenBlobContext`, else the agent's own `uri`). The `uri` caption under the image is dropped for show_image calls (`caption={false}` from `GeneratedImages`), whose row already names the files. `chat/copyImage.ts` fetches the session blob and hands `ClipboardItem` a pending PNG so the right-click gesture does not expire while it loads. Bytes with a PNG signature go through as-is (the declared MIME type is not trusted: Chromium rejects a PNG entry that does not decode); other raster types decode from the fetched bytes with `createImageBitmap` (an `<img>` on the resource URL would taint the canvas, since VS Code serves webview resources from another origin) and SVG, which `createImageBitmap` rejects, through a `data:` URL `<img>` (the CSP allows `data:` images, not `blob:`), then re-encode to PNG on a canvas. The copied / failed status shares `ui/useCopied` (`useCopyAction`) and is announced through an `sr-only` status only: a visible line under the image shifted the transcript. Generated-image results use the same component after their reveal finishes

- Slash commands are the agents' own: `available_commands_update` → `normalize.rs` (`SlashCommand { name, description, input?: { hint } }`, each update replaces the whole list, an empty one clears it) → `SessionView.commands` → `App` → `ShellProps.commands` → `composerProps.commands` (so the inline history / queue editors get the same list) → `chat/Slash.tsx` (list + hook; the pure `commandAt` / `completeCommand` / `matchCommands` / `commandHint` / `commandMarks` live in `chat/slashCommands.ts`, DOM-free so the host tsconfig can type-check their test). A `/` at the start or after whitespace with the caret inside its token (`commandAt`, the same shape as `mentionAt`, so a command / skill can also be called up mid-sentence like Cursor's `/`) opens the list (`matchCommands`: name prefix, then name substring / description word start, agent order within each tier) in the `chat/Completion.tsx` shell the `@` mention list also uses; ↑↓ move, Tab completes that token in place to `/name ` (`completeCommand`), Enter completes unless the token already is the active command (then it sends), Esc parks it by the token's `start`. Picking only edits the text — the command goes out through the ordinary `send` → `preparePrompt` → `session/prompt` and the agent runs it; the list is discovery, never a whitelist: no hit means the slash is plain text (`/tmp/file.ts` sends as typed), and nothing is rewritten, expanded or intercepted host-side (Acpira has no slash commands of its own; `/compact` for auto-compaction is the agent's). `commandHint` shows `input.hint` as a faint line under the text while the command the text ends with still has empty arguments. `PromptInput`'s mirror paints every advertised `/name` token with the command pill (`COMMAND_MARK`: the `--command` token, one blue for every agent and independent of the accent axis — it used `accent` until the pill was found transparent for every agent but Devin / Grok, since `[data-accent="agent"]` only defines those two; that axis now falls back to `--brand` for the rest) — leading or mid-sentence alike (`commandMarks`, the same boundary rules as `commandName`, so a path / partial name / punctuated tail never lights up; Cursor and Codex paint mid-sentence commands the same way) — while `turn.command` in the transcript stays a leading-token receipt. `@name` of an enabled subagent persona (settings → Subagents, what the `@` list's summon writes) gets the same pill in its own colour (`SUMMON_MARK`, the `--summon` token: violet, so a summon never reads as a command) in the composer mirror and the sent message alike (`summonMarks` / `promptMarks` in `chat/slashCommands.ts`: `@` at the start or after whitespace, exact name, longest name first since names may hold spaces, ending at whitespace / end / punctuation, so `@审查，` lights up and `@审查员` or `a@审查` do not; `Shell` hands the persona names down `Thread` → `HistoryMessage` → `UserMessage`, memoized on `personas`). A persona disabled or renamed later loses its pill in old messages (2026-10-06). `AcpSession.openSession` clears `state.commands` before `session/new` (never after — Devin advertises during the request), resume / load keep the persisted list until the peer replaces it; `sessionEdit` does the same for its fresh session. Skills the CLIs expose show up here under their own naming (Grok `/release`, Kimi / Pi `/skill:release`, Codex `/$release` — names may lead with one `$`, in `commandName` / `commandMarks` and Rust `command_name` alike — Devin `/agents:release` / `/claude:release`; `matchCommands` folds Devin's `agents:` / `claude:` copies of one skill into the first-ranked row after matching, so typing `/claude:` keeps the claude copy, and the picked name is sent verbatim — marks still paint both); the settings inventory scan (`inventory.ts`) is a read-only listing and is not turned into commands. Verify with `packages/ui/test/slash.test.ts`, the resume / gone cases in `tests/engine/acp_session/lifecycle.rs`, and `pnpm probe <agent> --wait 4000`
- Command / summon pills (`chat/PromptInput.tsx` `commandSegments`, `.prompt-mark` in `styles/chat.css`): the pill's background overhangs its text by a margin and padding that cancel out, because the composer mirror must keep every glyph where the textarea draws it. A full `--mark-overhang` (4 px) on both sides of a single space (about 3.6 px at 13 px) made neighbouring pills overlap and a pill touch the plain text beside it. `markRoom` (`chat/slashCommands.ts`) caps each pill at the whitespace beside it (`--mark-space` per character) minus `--mark-clear`, halved when another mark shares that whitespace. The pill uses its smaller side on both, so a run of marks reads as even pills with even gaps. A text edge or a line break keeps the full overhang; a soft wrap is not detected. - Transcript render budget: every stream chunk pushes the session view (fresh objects from `postMessage`), so `App` merges it with `shared/reuse.ts` — deep-equal subtrees keep their previous reference — and `AgentMessage` / `HistoryMessage` / `ToolCall` / `ToolGroup` / `Thought` / `Prose` / `Plan` are `memo`ized on those references; the live turn's fold states reach its rows through a per-row store subscription (`chat/autoFold.ts`), not a context value that would re-render them all. Anything that would defeat this must stay out: context values above `Thread` must not change per push (`HistoryContext` carries an `editable` flag, the composer props ride `HistoryComposerContext` only while an editor is open; `OpenToolFileContext` / `PlanDocumentContext` values are memoized, lists through `ui/useStableList`), and per-turn derived work caches by turn object. Without this a 700-block session spent ~45 ms per frame on re-rendering during streaming and every fold toggle stuttered. Verify with `scripts/probe/fold-perf.ts --stream --cpu` against the LAB server (`lab/performance.preview.html`, profile `large`): streaming must hold ~16 ms frames with no long tasks. The live-thought case needs `--stream --live` (thoughts now stream through `Prose` like replies; not re-measured since). Streamed glyph fades must not use a forwards fill: `both` kept one `CSSAnimation` per streamed character in effect (3497 at 4000 characters), and toggling a fold during a streaming thought took 280 ms frames. `StreamText` keeps only the fading tail as spans (`chat/streamGlyphs.ts`); its settled prefix is one text node. Settled turns mount fold bodies lazily (`ui/Collapsible` `LazyPanelContext`, provided `!running` by `AgentMessage`): a panel renders its body only while open, and a closed body is released after the close transition (`--dur-close` + 80 ms). Time tokens are read with their unit (`ui/cssTime.ts`): the shipped stylesheet is minified and `320ms` becomes `.32s`, so the bare `parseFloat` of 1.8.6–1.8.7 released the body 80 ms into the close and every fold snapped shut in the installed extension while the unminified LAB stayed smooth (reproduced in `performance.preview.html` with the tokens set to `.32s` on `.acp-shell`: 1681 px → 0 in one frame at 100 ms; 2026-10-06). The same read cut `ConnectedRail`'s retract and growth and the history editor's return animation. Kept-mounted closed folds held 98% of a 700-block session's 31.5k nodes, so every session switch laid all of it out (production build: one ~310 ms task, 153 ms of it `Layout`); now ~25 ms, and the cost moves to each open of an old fold (~110 ms for the largest). Until 2026-10-05 a body once opened stayed mounted, so expanding and collapsing a long history pinned its DOM for the page's lifetime: LAB `performance.preview.html` (profile `large`), every fold opened then closed, went 772 → 35.9k → 35.6k nodes with the GC'd heap 81 → 162 MB; with the release it returns to 737 nodes / 84.5 MB (headless Chrome over CDP, dev build). Hand-toggled state of folds nested inside a released body (`Disclosure`'s own `useState`) is lost with it; the turn's per-row fold memory (`useProcessFolds`) lives above the panel and survives. In a live turn only items still running or streaming keep a closed body mounted, so a closed thought still streams in step; a finished item's bodies mount on open like a settled turn's (`ProcessBlocks` / `Lines` narrow `LazyPanelContext` per item with `itemSettled` / `blockSettled`). Opening a session mid-turn is the case that needs it: a live turn opened with more than `TAIL_THRESHOLD` items (`chat/tailWindow.ts`) renders its last `TAIL_SIZE` items first and mounts the earlier ones in idle slices (`requestIdleCallback`, at most 250 ms apart, each slice committed with `flushSync`); item ids, keys and fold memory still come from the whole list. The thread has `overflow-anchor: none`, so a slice keeps the reader's view itself: at the bottom (read from the geometry, not `FollowState`, since a scroll may not have dispatched yet) it stays pinned, otherwise `scrollTop` moves by the added height.
