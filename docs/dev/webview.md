# Webview

The React UI in `src/webview`: stylesheet layering, file links, slash commands and the transcript render budget.

- Question receipts: `chat/planSections.ts` suppresses a tool row when a `QuestionBlock.toolCallId` explicitly matches it, before any folding mode groups the turn. The pending composer card and resolved `QuestionRecord` own the interaction and answer history; the original transcript remains intact. Unlinked tools and failed-tool diagnostics remain visible. Verified with the existing LAB question fixture (2026-09-30; no new CLI wire behavior) and `test/planSections.test.ts`.

- `src/webview/` — React UI: `ui/` primitives (Row / Disclosure / Button / Chip / Card / Popover / DropdownMenu / Command / Collapsible / RadioGroup / Switch / Dialog / Toast), `chat/` conversation components, `effects/` visual effects, `styles/` stylesheets (`index.css` entry → `tokens.css` design tokens + `@theme` map, `base.css` shell defaults, `prose.css` markdown, `motion.css` animation, `chat.css` conversation shapes Tailwind cannot express at one call site). Layering: single-element styles go in the TSX className; shared shapes are `@utility`; descendant rules sit in `@layer components` so a call-site utility still wins. Only rules that must beat the unlayered host webview stylesheet or `katex.min.css` stay unlayered (`base.css` code / kbd / focus, all of `prose.css`) — a layered rule loses to them regardless of specificity; `motion.css` is also unlayered because its rail / stream rules never compete with a utility. `ui/` primitives carry their own skins (`Switch` geometry lives in the `@theme` map, not in `settings.css`); wrappers that keep an internal ref merge the caller's with `ui/mergeRefs`
- File links in agent markdown (`chat/fileLinks.ts`, DOM-free, `test/fileLinks.test.ts`): anchors get their href rewritten to `#acpira-file:<path>[:line]` by `rewriteFileHrefs` after rehype-raw and before sanitize / harden (a `file:` href is a hard block there and would paint ` [blocked]`), and `chat/Link.tsx` turns both anchors (`Link`) and inline code that is a workspace path (`InlineFileCode`, `parseFileLink`: relative / absolute / `C:\` paths, `:line`, `#Lline`, `file://` URIs) into `openFile` clicks. GPT also wraps whole links in backticks — `` `[Shell.tsx:240](file:///…/Shell.tsx)` `` — which reaches the inline-code path as text; `parseWrappedLink` unwraps it so the label shows and the target opens (line from the target, else the label). Anything that is not a path stays plain code; http(s) targets are not touched
- Agent images (`chat/AgentImage.tsx`) open in the shell's Lightbox on click, the same preview a dropped attachment gets (opening them as an editor tab took the reader out of the conversation); the right-click menu holds Copy image and Open in editor (the session blob through `OpenBlobContext`, else the agent's own `uri`). The `uri` caption under the image is dropped for show_image calls (`caption={false}` from `GeneratedImages`), whose row already names the files. `chat/copyImage.ts` fetches the session blob and hands `ClipboardItem` a pending PNG so the right-click gesture does not expire while it loads. Bytes with a PNG signature go through as-is (the declared MIME type is not trusted: Chromium rejects a PNG entry that does not decode); other raster types decode from the fetched bytes with `createImageBitmap` (an `<img>` on the resource URL would taint the canvas, since VS Code serves webview resources from another origin) and SVG, which `createImageBitmap` rejects, through a `data:` URL `<img>` (the CSP allows `data:` images, not `blob:`), then re-encode to PNG on a canvas. The copied / failed status shares `ui/useCopied` (`useCopyAction`) and is announced through an `sr-only` status only: a visible line under the image shifted the transcript. Generated-image results use the same component after their reveal finishes
- Slash commands are the agents' own: `available_commands_update` → `normalize.rs` (`SlashCommand { name, description, input?: { hint } }`, each update replaces the whole list, an empty one clears it) → `SessionView.commands` → `App` → `ShellProps.commands` → `composerProps.commands` (so the inline history / queue editors get the same list) → `chat/Slash.tsx` (list + hook; the pure `commandAt` / `completeCommand` / `matchCommands` / `commandHint` / `commandMarks` live in `chat/slashCommands.ts`, DOM-free so the host tsconfig can type-check their test). A `/` at the start or after whitespace with the caret inside its token (`commandAt`, the same shape as `mentionAt`, so a command / skill can also be called up mid-sentence like Cursor's `/`) opens the list (`matchCommands`: name prefix, then name substring / description word start, agent order within each tier) in the `chat/Completion.tsx` shell the `@` mention list also uses; ↑↓ move, Tab completes that token in place to `/name ` (`completeCommand`), Enter completes unless the token already is the active command (then it sends), Esc parks it by the token's `start`. Picking only edits the text — the command goes out through the ordinary `send` → `preparePrompt` → `session/prompt` and the agent runs it; the list is discovery, never a whitelist: no hit means the slash is plain text (`/tmp/file.ts` sends as typed), and nothing is rewritten, expanded or intercepted host-side (Acpira has no slash commands of its own; `/compact` for auto-compaction is the agent's). `commandHint` shows `input.hint` as a faint line under the text while the command the text ends with still has empty arguments. `PromptInput`'s mirror paints every advertised `/name` token with the command pill (`COMMAND_MARK`: the `--command` token, one blue for every agent and independent of the accent axis — it used `accent` until the pill was found transparent for every agent but Devin / Grok, since `[data-accent="agent"]` only defines those two; that axis now falls back to `--brand` for the rest) — leading or mid-sentence alike (`commandMarks`, the same boundary rules as `commandName`, so a path / partial name / punctuated tail never lights up; Cursor and Codex paint mid-sentence commands the same way) — while `turn.command` in the transcript stays a leading-token receipt. `AcpSession.openSession` clears `state.commands` before `session/new` (never after — Devin advertises during the request), resume / load keep the persisted list until the peer replaces it; `sessionEdit` does the same for its fresh session. Skills the CLIs expose show up here under their own naming (Grok `/release`, Kimi / Pi `/skill:release`, Codex `/$release` — names may lead with one `$`, in `commandName` / `commandMarks` and Rust `command_name` alike — Devin `/agents:release` / `/claude:release`; `matchCommands` folds Devin's `agents:` / `claude:` copies of one skill into the first-ranked row after matching, so typing `/claude:` keeps the claude copy, and the picked name is sent verbatim — marks still paint both); the settings inventory scan (`inventory.ts`) is a read-only listing and is not turned into commands. Verify with `test/slash.test.ts`, the resume / gone cases in `tests/engine/acp_session/lifecycle.rs`, and `pnpm probe <agent> --wait 4000`
- Transcript quotes and editor context: `chat/QuoteToolbar.tsx` is mounted once per `Shell` (not in external mirrors) and watches the document selection; a non-empty selection wholly inside the thread content raises a Base UI popover anchored to the range (virtual anchor) with "Add to chat". Clicking appends a `quote` draft to the main composer through `updateMainComposer` (`chat/useComposerDraft.ts`, a module-level sink the main composer registers; updates made before it mounts are queued) and turns the popover into the optional comment field (`Quotes.tsx` `CommentEditor`: Enter saves onto that quote by identity, Esc closes); the quoted range stays painted through the CSS Custom Highlight API (`::highlight(acpira-quote)`, `base.css`) because focusing the field drops the real selection. Quotes render as one `QuoteChip` ("N annotations"; hover opens the numbered list with edit / remove per entry, and the chip's ✕ removes all) in `DraftChips`, in sent turns and in the inline editors. The editor's live selection is a module store (`chat/editorContext.ts`, `useSyncExternalStore`) fed by `App` from `editorSelection`; only the main composer, with `shareEditorSelection` on and no edit open, shows it as the toolbar `SelectionChip` (click toggles it out for this range; it collapses to its icon below the `sm` tier and splits free width with the model side so the model name stays readable). A sent selection is marked consumed and hidden until the editor reports a different one or clears it (reselecting the same range offers it again); drafts count as duplicates only when range and text both match, so two excerpts of one line are kept. Checked in `lab/history.preview.html` (headless Chrome over CDP: select → toolbar → comment → chip → hover card, a live selection chip, a paste turned into a selection chip; 2026-09-28)
- Transcript render budget: every stream chunk pushes the whole `SessionView` (fresh objects from `postMessage`), so `App` merges it with `shared/reuse.ts` — deep-equal subtrees keep their previous reference — and `AgentMessage` / `HistoryMessage` / `ToolCall` / `ToolGroup` / `Thought` / `Prose` / `Plan` are `memo`ized on those references; the live turn's fold states reach its rows through a per-row store subscription (`chat/autoFold.ts`), not a context value that would re-render them all. Anything that would defeat this must stay out: context values above `Thread` must not change per push (`HistoryContext` carries an `editable` flag, the composer props ride `HistoryComposerContext` only while an editor is open; `OpenToolFileContext` / `PlanDocumentContext` values are memoized, lists through `ui/useStableList`), and per-turn derived work caches by turn object. Without this a 700-block session spent ~45 ms per frame on re-rendering during streaming and every fold toggle stuttered. Verify with `scripts/probe-fold-perf.ts --stream --cpu` against the LAB server (`lab/performance.preview.html`, profile `large`): streaming must hold ~16 ms frames with no long tasks. The live-thought case needs `--stream --live`; without `--live` the thought has already settled to plain text and no glyph spans exist. Streamed glyph fades must not use a forwards fill: `both` kept one `CSSAnimation` per streamed character in effect (3497 at 4000 characters), and toggling a fold during a streaming thought took 280 ms frames. `StreamText` keeps only the fading tail as spans (`chat/streamGlyphs.ts`); its settled prefix is one text node. Settled turns mount fold bodies lazily (`ui/Collapsible` `LazyPanelContext`, provided `!running` by `AgentMessage`): a panel that was never open renders no body, a body mounted once stays. Kept-mounted closed folds held 98% of a 700-block session's 31.5k nodes, so every session switch laid all of it out (production build: one ~310 ms task, 153 ms of it `Layout`); now ~25 ms, and the cost moves to the first open of each old fold (~110 ms for the largest). A live turn keeps its bodies mounted so a closed thought still streams in step. `ConnectedRail` reads no geometry while disabled or inert. Measure switches with `scripts/probe-fold-perf.ts --switch`. That probe only sees the main-thread JS cadence; the paint side needs a CDP `Tracing` run (`devtools.timeline` + `disabled-by-default-devtools.timeline{,.frame,.invalidationTracking}`) against `pnpm harness --home <copy>` with a real multi-MB session, summing `Paint` / `PrePaint` / `UpdateLayoutTree` per second and counting `DroppedFrame`. Two findings from a 64k-node session: the running-verb shimmer used to animate `background-position` on a `background-clip: text` gradient, a paint property, so one shimmering span re-painted the whole document layer every frame (~455 ms of `Paint` per idle second, ~3 ms a frame before any click) — `ui/Shimmer` now draws the label twice and slides a masked copy with transforms only (`Paint` ≈ 3 ms/s, same as no shimmer; `will-change` on the span does not help, the walk is the scroller's). And each exchange `section` carries `contain-paint` (with `-mx-hit -mb-hit px-hit pb-hit` so row hit areas and card shadows are not clipped, top edge untouched for the stuck sentinel): paint containment gives the section its own paint offset, so a fold opening mid-thread no longer re-walks every later exchange in `PrePaint` each frame (dropped frames per toggle 16–21 → 1–5). What remains is one ~60 ms frame when a fold with hundreds of rows first opens (`inert` flip → subtree style recalc + React commit), not a per-frame cost
