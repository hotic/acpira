# Transcript pipeline

How ACP updates become transcript blocks: prompt staging, tool content, native import, subagents, JetBrains AIR extensions, empty completions, attachments, per-turn usage, forking and export.

- Prompt staging follows the agent's advertised `promptCapabilities` (`attachments.rs` `PromptCaps` / `promptCapsOf(init, def)`, threaded into every `preparePrompt` call: live prompt, queue staging, edit rebuild, `historyContext`): `embeddedContext: false` turns a dropped text attachment into a `text` block bracketed by `[Attachment: <name>]` / `[End of attachment: <name>]` (the blob is still saved); `image: false` drops image drafts and image files with a `host.imageUnsupported` problem unless the agent declares `imagesRegardless`. DSH and pi-acp advertise `embeddedContext: false` and reject embedded `resource` blocks. Verify with `test/pastedText.test.ts` and the `FAKE_PROMPT_CAPS=strict` cases in `tests/engine/acp_session/prompts.rs` and `edit.rs`
- Tool content is a list: `ToolCallBlock.contents?: ToolContent[]` holds every renderable item of a `tool_call_update` in wire order (a diff per `diff` item, one merged text per run of `content` items) whenever there is more than one; `content` stays the primary item (a diff wins over text) so records written before the field render unchanged, and `diffStat` sums every diff. `ToolCall.tsx` stacks `contents` with each diff under its own `source.path`; `Terminal.tsx` joins the texts. `terminal` items carry no body of their own: pi-acp streams bash output through `_meta.terminal_output.data` deltas and `_meta.terminal_exit.exit_code` (a non-zero code appends `exit code N`), codex-acp/claude-agent-acp use `_meta.terminal_output_delta` + `terminal_exit` the same way (the host advertises `clientCapabilities._meta.terminal_output_delta`), all of which `mergeTool` folds into the text content; codex-acp's completion `rawOutput { formatted_output, exit_code }` renders as its plain text instead of JSON, and a bare terminal item from an agent that expects a client terminal keeps the `host.terminalNotWired` note (replaced the moment real output arrives). `image` items (a `content` item carrying an image content block) become image contents whose base64 payloads `NormalizeState.saveImage` parks in the session blob store under the content-hash name (`AcpSession.saveImage`, capped by `MAX_OUT_IMAGE_BYTES`, mime allowlist png/jpeg/gif/webp; a refused payload degrades to a `[image: <mime>, not shown]` note), and a `resource_link` to a local image file (codex-acp's `view_image` preview) is read through `saveImageFile` into the same blob store, the link's uri kept as the caption; `agent_message_chunk` images become standalone transcript blocks that split the text run. The webview renders them via `chat/AgentImage.tsx` (blobBase URL, click to the Lightbox, Open in editor on right-click, `uri` as an openable caption). Permission requests are low-fidelity: OpenCode's `session/request_permission` embeds a `toolCall` with `kind: 'other'`, the parent directory as `title`, and both the file and its directory as `locations`, racing the real `tool_call_update`; `permissions.ts` `permissionToolUpdate` applies it only as an upgrade to an existing block (never `other` over a specific kind, locations only when there are none, title / rawInput only without a target), the whole thing when no block exists yet (Devin / Kimi plan approvals). OpenCode's `write` completes with text only (`rawOutput.output` "Wrote file successfully.", `metadata.exists: false`); `NormalizeState.pendingWrites` remembers the in_progress `rawInput.content` per tool id and, on that evidence of a new file, synthesizes an all-add diff as the primary content (an overwrite keeps the receipt text — an all-add diff would lie). Verify with `tests/engine/normalize.rs` and the `tool-downgrade` / `tool-downgrade-late` cases in `tests/engine/acp_session/permissions.rs`
- Diff sources stay out of page views (2026-10-06): the record keeps every diff's `source { path, oldText, newText }`, but `view_encoded` and `subagent_transcript` serialize inside `encode_for_view`, which writes `source` as `{ path, omitted: true }` (an edit of a large file carried both whole texts into every view; one 8.6 MB session view was 7.3 MB of them). The visible `lines` are unchanged, so expanding and scrolling render from what the view already has; `highlightDiff` falls back to tokenizing the visible segments (no whole-file grammar state). Copying the file asks the host for the full source on click: `WebviewMsg.diffSource { sessionId, toolCallId, nth, subagentId?, seq }` (nth is the diff's index among the tool call's diff items, `toolDetails.ts` `diffIndex`) is answered by `HostMsg.diffSource { seq, source? }` from `AcpSession.diff_source` (newest match first, live sessions and mirrors). Only the transcript the diff was shown in is searched: the session's visible turns, or with `subagentId` (set by the subagent inspector's `DiffSourceContext`) that child's transcript alone, since ACP keeps tool call ids unique per session only and a child may reuse its parent's (2026-10-06, `a_root_call_reusing_a_native_childs_tool_id_stays_on_the_root`), and `useCopied` hands the clipboard a `ClipboardItem` whose text is that pending promise, inside the click's user activation; a missing answer (10 s) copies the visible text. Verify with the omitted cases in `test/code-diff.test.ts`, `diff_source_tests` in `acpira-shared/src/transcript.rs` and `permission_card_approve…` in `tests/engine/acp_session/permissions.rs`
- Image generation calls: `normalize.rs` names a tool `verbKey: 'verb.imagegen'` by identity: the `Image generation` title (codex-acp), `image_gen` / `image_edit` in `_meta["x.ai/tool"].name`, or an `imagine:` / `imagine-edit:` title (Grok). The key survives later title-less packets, and the title never becomes the target (`rawInput.prompt` / `description` does when present). A completed call with no image item gets the absolute image paths in its text results or `rawOutput` read into the blob store (`attach_saved_images`, same saver and 20 MB cap as `resource_link` images, relative paths ignored). In the webview, `shared/imageTools.ts` (`isImageGenTool` / `toolImages` / `toolTexts`) drives the row: `ImagePlus` icon, the revised prompt as its disclosure body, and `chat/GeneratedImage.tsx` renders the images. In the shared Codex-style process fold, images stay below their tool row while the fold is open, and move outside the panel only while it is closed so a collapsed history keeps the result visible; this applies to every agent, including Claude. In cursor mode they sit under the row. A call first seen running in this view gets a square `--agent-image` inset card (`bg-chip`, `--image-gen-card-shadow`) with img-fx's `ImageGeneration` mosaic in it, recoloured from the theme (`effects/imageGen.ts` / `imageGenPalette.ts`, parameters in `effects/presets.ts` `IMAGE_GEN`): `cardBg` is the opaque colour actually painted behind the card (translucent layers composited), the palette mixes `--fg-1` into it per slot with the `--image-gen-peak` colour in the highlight slot, and light paper takes lighter steps. The preset palettes shipped a fixed `#0f0f0f` card and near-white light colours, which read as a black hole on the `#181818` / `#1f1f1f` bases and vanished on light themes (with the former `strength: 0.4` on top); img-fx's default 10 fps stuttered at card size, so the frame rate is 30. On completion the card decodes the blob, takes the image's aspect ratio (--dur-open width transition), fades the mosaic out and dissolves the image in on a canvas cell by cell from the centre (`dissolveIn`, 1.2 s), then (or after a 6 s timeout) hands over to `AgentImage`, whose `box-content` border keeps the layout still. The look was picked in `lab/image-gen-fx.preview.html` (frame / loader / reveal / tone axes, with a long-task readout). The hitch when the card appeared was img-fx building its shared WebGL renderer and three linking the shader synchronously on first use (a 137 ms long task in headless Chrome 2026-09, against 0 ms for Canvas 2D loaders); img-fx also disposes that renderer with its last instance, so every card paid it again. The mosaic therefore mounts on the next idle slot rather than with the row, and `keepImageGenRenderer` parks a paused 1 px instance that keeps the renderer alive for later cards (paused instances are skipped by the render loop and the GL canvas sizing). The first card in a webview still pays the one-time build. History, replay, a remount after completion, `motion: none`, reduced motion and no WebGL (`effects/webgl.ts`, shared with metal-fx) all render the static image (placeholder: a plain / pulsing chip square). img-fx injects its own unlayered `<style>`, so its root needs `block!`; the webview CSP already allows inline styles. `three` is its peer dependency and makes up most of the bundle cost (~600 KB). - Images an agent shows the reader. (1) Reply markdown: `normalize.rs` `resolve_markdown_images` scans each `agent_message_chunk` append (from 1 KB before the new text, so syntax split across chunks is caught) for `![alt](src)` / `![alt](<src>)`, resolves file:// URLs, absolute paths and paths relative to the session cwd (`ToolCtx.cwd`), and reads image files through the same `save_image_file` saver into `TextBlock.images` (`ImageRef.uri` = the source as written; each source is tried once, an unreadable one is kept without `blob`). In the webview `fileLinks.ts` `rewriteFileHrefs` turns local `img` sources into `/__acpira-image__/<encoded>` (rehype-harden accepts `#` fragments for links only; a path-relative image URL survives sanitize and harden) and a paragraph holding one into a `div`; `Prose.tsx` `MarkdownImage` matches the decoded source against the block's images (the parser percent-encodes spaces / non-ASCII) and renders `AgentImage`, or the named no-pixels card before the file is read. (2) Acpira's MCP tool: `session_request` hands every session/new, load and resume `mcpServers: [{ name: "acpira", command: <sidecar exe>, args: ["mcp"], env: [] }]` (`host_mcp.rs`, `HostMcp` built from the runtime's executable path; no `type` field — claude-agent-acp treats only a type-less entry as stdio). `acpira mcp` is a stdio MCP server with one tool, `show_image { path | paths, caption? }`: it validates absolute, existing, image, ≤ 20 MB and answers a text receipt; the pixels never go back to the model. The tool description (not only the optional server `instructions`, which a CLI may drop) also names the Markdown route, `![caption](/abs/path.png)`, with "one or the other for a given image, never both", since doing both shows the image twice. `normalize.rs` recognizes the call by name (`SHOW_IMAGE`: claude-agent-acp 0.83.0 `name` / `title` `mcp__acpira__show_image` with the arguments as rawInput; codex-acp 1.13.0 title `mcp.acpira.show_image`, kind `execute`, rawInput `{ server, tool, arguments }`; OpenCode-style `acpira_show_image`; a bare `show_image`), sets `verbKey: 'verb.showImage'`, kind `other`, keeps the paths as `locations`, and on `completed` reads them into image contents ahead of the receipt text (`attach_shown_images`; a failed call shows none). The webview (`shared/imageTools.ts` `isShowImageTool` / `isImageResultBlock`) renders a plain row and keeps its images below that row while the process fold is open, lifting them outside only while it is closed, without the generation placeholder and without the path caption (the row names the files). A session/new that fails with the server is retried once without it and the agent is remembered per manager (`HostMcp::refuse`). Both adapter namings were read from the installed adapter sources (2026-09-30); no real CLI has called the tool yet. Verify with the `local_images_in_reply_markdown…` and `the_host_show_image_tool…` cases in `tests/engine/normalize.rs`, `session_new_hands_the_agent_the_host_mcp_server…` in `tests/engine/acp_session/lifecycle.rs`, the `host_mcp` unit tests, `test/fileLinks.test.ts` and `lab/show-image.preview.html`
- Native session import: the history list's Import button (`chat/SessionList.tsx` `ImportSessions`, `Import` icon on the filter row) asks the host for an agent's own sessions (`WebviewMsg listNativeSessions` → `SessionManager.listNativeSessions` → `acp/agents/native_sessions.rs`: a throwaway spawn runs `initialize` + paged `session/list { cwd }` and dies — never `session/new`, since OpenCode / DSH / Pi all persist a session on creation; empty pages are paged through while a `nextCursor` exists (codex-acp filters each 25-thread page by cwd string, so a foreign-project page is `[]` with a cursor, capped at 40 pages / 200 sessions) and an empty listing for a symlinked cwd is retried once with its `realpath` (codex-acp stores the canonicalized thread cwd — macOS `/var` → `/private/var`) and answers `HostMsg nativeSessions` with `NativeSessionInfo[]`, `localId` set for sessions a record already holds (`SessionSummary.acpSessionId`; summaries written before the field are back-filled from their record once and marked `touched` so the index write keeps it). `importNativeSession` creates a record with `acpSessionId`, `importPending: true`, `importedFrom`, and starts it: `openSession` then tries `session/load` before `session/resume` so the native history replays into the empty transcript (`sealReplay` closes the streamed blocks and stamps `stop: 'end_turn'`), a 'gone' answer becomes `host.importGone` (error + Retry, never a silent `session/new`), and an import that resumed without replay (DSH has no `load`) gets the `host.importNoHistory` toast. Picking an already-imported row selects its record. - Subagents are first-class nodes, never mixed into the parent transcript: `src/shared/subagents.ts` (`SubagentSummary` on `SessionView.subagents`, `SubagentRecord` with the child's own `turns` on `SessionRecord.subagents`) and `src/host/acp/subagents/` (`SubagentTree` per `AcpSession`: nodes with their own `NormalizeState`, peer-id indexes, orphan buffer 8 ids × 64 updates, lifecycle; `wire.rs` the extension decode). Three visibility tiers, each verified on the wire with `scripts/probe-subagents.ts` (raw ndjson, nothing validated away) and `scripts/probe-subagents-host.ts` (the `SessionManager` path): `session` — claude-agent-acp 0.78/0.79 streams the child's own updates under its own session id after `subagent_spawned` / `subagent_state_update` on the parent (the RFD #1992 `subagent_update` upsert is decoded too; the RFD is still open and its wire shape changed 2026-09-15), gated by `_meta.jetbrains.air = { version: 1, capabilities: ['nativeSubagentSessions'] }` because the adapter's SDK strips the draft `clientCapabilities.subagents` field (both are advertised at `initialize` unless `AgentDef.subagents === false`; Devin / Kimi / Grok / OpenCode accept the unknown key and ignore it); `nested` — Devin 3000.11.1 announces with `tool_call_update` `_meta['cognition.ai/subagent_started'] { agentId, title, task, profile, model, depth, isBackground }` whose `toolCallId` is the agentId (never a root tool row), ends with `subagent_completed { agentId, success, summary }`, and marks the child's own tool calls and `usage_update`s with `subagent_context.parentAgentId` (a child usage must never land on the root ring); `run_subagent` rows link by title+task and get `subagentId`, `read_subagent` rows stay visible as `verb.awaitSubagent`; Claude without AIR uses `claudeCode.subagent` + `parentToolUseId` the same way; `receipt` — Kimi 0.41.0's `Agent` tool with `rawInput { prompt, description, subagent_type }`, result text only. Claude dynamic-workflow agents (ultracode) are receipt nodes too, fed by the raw `task_progress` frames instead of a tool call (`agent-quirks.md`, Orchestration levels); they have no delegation row, so they trail the announcing turn's content, and they outlive the prompt until the workflow's async task ends. SDK 1.4.0's `zSessionUpdate` is a closed union, so `AgentProcess` rewrites extension kinds into `session_info_update._meta['acpira/extension']` before the SDK parses them (same handler ⇒ wire order kept; a custom method would dispatch through another handler index). Lifecycle follows the RFD: a child still `running` when the parent prompt returns, the connection ends or the session is disposed becomes `disconnected` / `stateSource: 'local'` (never failed / cancelled); a later agent terminal replaces it, nothing revives a terminal node, and content that arrives after the terminal word drops (usage metadata still applies); `session/cancel` with the child id only when `controls.cancel`. Permission / elicitation requests route by `sessionId` into the owning transcript (`PermissionGate` / `QuestionGate` `stateFor`, which answers `cancelled` for a terminal node), mirrored on `SubagentSummary.permissions` / `question` so the root view shows them with provenance; a child going terminal (`SubagentTreeDeps.onTerminal`) or being cancelled — descendants included — answers its pending requests `cancelled`, and `QuestionGate.settle` pins a card to its owning transcript because block ids restart at `q-1` on every reopen. Routing invariants: `toolOwner` indexes only nested / receipt children (a `session` child's updates arrive under its own session id; registering them would hijack a same-named root call), Devin `subagent_started` / `subagent_completed` read before `subagent_context` routing (a nested child's spawn carries its own parent link), and updates naming a not-yet-announced owner buffer under `agent:<id>` / `tool:<id>` orphan keys rather than leaking onto the root. A launch receipt links through three paths (`toolResponse.isAsync`, `pendingLaunches`, the child's `parentToolUseId`) that share `sealLaunchReceipt`, and a nested / receipt node already sitting on the same root call is upgraded in place (`adoptCallNode`) rather than duplicated. `SubagentRecord.rev` persists so a restore never hands the webview a lower revision than it holds. - Cross-harness subagents (`acp/session/relay.rs`, `relay/`; personas and the hub in `host-architecture.md`): a root agent's `ask_agent` call (or one from a summoned child, whose entry's grant names its thread and depth) becomes `AcpSession::relay_ask` on the session that owns it. One call = one round = one `session` node (`SubagentTree::relay_open`, `SubagentSummary.harness { agent, persona, mode, thread, round, sessionId }`, `role` = the persona name, `title` = the call's `title` or the prompt's first line, `task` = the prompt); a thread is the run of rounds talking to one native session, its id the first round's node id. Whether a round may start (the thread idle, fewer than `MAX_RUNNING` 6 summoned rounds running in the session, nested ones included, the session not closing), the node and the round's end channel are all decided under one lock, so two prompts on one thread never both start. A new round on a thread takes its persona's current settings but refuses when the persona is gone, disabled or now runs in another CLI; waiting on a thread or reading its last round goes by the node alone. The round spawns (or reuses) the persona's CLI as a process of the parent session (`Relays.procs` by thread, registered the moment it is spawned so a failed open or the close ends it, and ended before it is unregistered; a start counts in `Relays.starting` from the round's opening until its process is registered or ended, and the close future waits for that count to reach zero; `AgentProcess::spawn` with the CLI's own credentials, no warm pool, no account hand-off). A new thread opens with `session/new` (shared MCP servers for that agent + Acpira's entry one level deeper; `MAX_DEPTH` 2); a thread whose process is gone reopens its native session with `session/resume`, else `session/load` with its replay muted, and when neither works the round fails with that reason (never a silent fresh session under the old thread). On open the persona's model is applied by matching a `configOptions` value or name (category `model`), then the effort from the option list that switch answered (`thought_level` / `reasoning_effort` / `effort`, grouped selects included); the node's `model` is the select's current value afterwards, not the configured one. A live thread whose persona's model / effort changed since gets them applied again. Every round applies its mode (a refused switch is not taken as set, the next round tries again): a consult switches to the first of `read-only` / `plan` / `ask` among `modes.availableModes` (else a `mode` config option with that value); a work round in a read-only mode switches back to the mode the session opened in (else its first writable one). A model, effort or read-only mode the CLI lacks or refuses is logged and kept with the round's node (`Relays.notes`), appended to every read of that round as an `(Acpira: …)` note; without a read-only mode the CLI's own permission settings apply. The brief is the prompt + the persona's standing instructions + for a consult "do not modify any file" + a line that the caller reads only the final reply; codex-acp's `read-only` mode still lets in-workspace writes through without a card (`docs/acp-agents-compat.md`, Codex read-only approval scope), so the brief line is what holds a Codex consult. `RelayHandlers` stamp every update and request of the child with the routing key `relay:<thread>` before handing it to the parent's own `on_update` / `on_permission` / `on_elicitation` (two CLIs, the parent included, may mint the same session id), and `relay_bind` registers that key as the node's `peer.sessionId` (the native id is `harness.sessionId`), so the child's stream, approval and question cards route exactly like a native child's (updates before the bind buffer as orphans under the key). The round ends with the prompt's stop reason (`relay_end`: completed / cancelled, a request error → failed with the error as result); the call answers the child's last reply plus `thread: <id>`, or after its deadline "still working" — a call with the thread and an empty prompt waits again (it is `ask_agent` itself, there is no separate await tool), a new prompt on a busy thread is refused, one on a finished thread starts the next round on the same native session. A finished round is read back from its node the same way live or later (`round_result`): completed → the reply, cancelled / failed → an error naming why. `settle("prompt-returned")` leaves running summoned nodes alone (the call may return before the round). The user's stop (`cancel`) also cancels every running summoned round, whatever state the root turn is in; `cancel_subagent` on a summoned node sends `session/cancel` with the native id to its thread's process, and every summoned descendant gets its own; a round still connecting skips its prompt. Closing the session marks the relays closed and hands every thread process to the close future (`relay_close`), so a host shutdown waits for them and hard-kills them with the agent's own. Root rows: `relay_annotate` recognizes the call per adapter naming (`mcp__acpira__ask_agent`, `mcp.acpira.ask_agent` with `{ server, tool, arguments }`, `acpira_ask_agent`) and ties it to the round's node by its prompt, `agent` (persona id or name) and `thread` arguments within the same turn (`relay_link_call` → `subagentId`, so the row hides behind the node; two personas asked the same thing never swap rows), remembering a row that arrives before its round in `Relays.calls` (dropped once a later turn starts, or when the call ends without a round, so a retry with the same arguments gets the node); a wait call (thread, no prompt) stays visible as `verb.awaitSubagent`. Webview: `SubagentGroup` draws the CLI's `AgentMark` on the state mark's corner, the title, the model faintly and `subagents.round` from round 2; a summoned child's approval sits under its row as `Permission compact` (`Turns.tsx` `SummonedApproval`: one titled line with the full card's choices, deny-by-default emphasis and "more" menu, the command and description below; plan approvals keep the full card); the composer's @ list leads with the enabled personas and the toolbar's summon chip (`SummonMenu`) — both write `@name ` into the text, which the tool description tells the model to honour. Verified with the fake agent only (`tests/engine/relay.rs`: rounds and threads, deadline and wait, a failure collected after the deadline, per-round mode switches, two prompts on one thread, the running cap, cancel and close ending every child process, a child approval, refusals, the hub's grants, row linking per persona and past a failed call, a close during a start, a nested cancel, a session that cannot be reopened; `test/relay.test.ts`); no real CLI has run a round yet. Not handled: a summoned child's own `ask_agent` row inside its transcript is not tied to the grandchild's node (`relay_annotate` reads root updates only), and the children's native sessions show up in the import list
- JetBrains AIR `sessionFailure` / `asyncTasks` (codex-acp, claude-agent-acp; advertised in `_meta.jetbrains.air.capabilities` next to `nativeSubagentSessions`, see `docs/acp-agents-compat.md`). `session/failure.rs` `failureOf` strictly decodes `_meta.jetbrains.air.sessionFailure` (id, positive-integer revision, severity, title, actions filtered to `retry` / `login` / `new_session`, unknown category → `unknown`). `normalize.rs` `applySessionFailure` keeps one `NoticeBlock` per id across the whole transcript: a higher revision rewrites it in place, a same or lower one is ignored, a different id is a new row even with identical text — except retry warnings (`is_retry_warning`: severity warning, no actions, category connection / service / limit), which are never rows: claude-agent-acp 0.81.0 `api_retry` mints a new session-scoped id per attempt (`…:session-error:<epoch>:<n>`, seen in stored transcripts 2026-09-26), so they set the live turn's `AgentTurn.retry` instead (attempt / max parsed from "attempt N of M", the title as tooltip) and `Turns.tsx` `liveActivity` shows "Retrying (attempt N/M)" on the working row; streamed text / thought / tool call, an error-severity failure or the end of the turn clears it, and a warning with no live turn is dropped; it lands on the last agent turn or a synthesized `end_turn` agent turn. It runs for `session_info_update` in root and child states alike, and is skipped during a restore replay. A turn-ending failure arrives on a successful `end_turn` `PromptResponse._meta`: `AcpSession.prompt` upserts the notice, settles the turn with `failureTurnError` (`failureId`, `actions` always present — empty means no remedy), skips the empty-response check, and a `login` action moves the session to `auth_required`. `Turns.tsx` suppresses the notice whose id matches `turn.error.failureId` (the Alert card shows it); a turn that ended on its own session/prompt error without a `failureId` absorbs its error-severity notices (`turnOutcome.ts` `absorbedNotices`): they render as quiet detail lines under the outcome row, without their actions, since the turn error and the Notice / Alert cards own the remedy (claude-agent-acp, stored transcript 2026-10-04: "The connection to Claude was lost." offering `new_session`, then `-32000` Authentication required); a turn holding nothing but notices gets no copy / fork / stats row (`hasTurnContent`); `Alert.tsx` renders only the declared actions. `asyncTasks`: `wire.rs` decodes `async_task_spawned` / `_progress` / `_state_update` into `AsyncTaskEvent`; `AcpSession.asyncTaskUpdate` routes by the carrying session id (root state or the child node's state via `SubagentTree.taskState`) and `normalize.rs` `applyAsyncTask` attaches `ToolCallBlock.asyncTask` to the `toolCallId` row (a later toolCallId adopts a synthesized `async:<id>` row instead of duplicating it; a task without a row is synthesized only when `showInTranscript`). A row with `asyncTask` takes its status from the task state only (`tool_call_update` statuses no longer overwrite it), is `background`, and `endTurn` leaves it alone while running / paused. Terminal states are final except that `completed` / `failed` supersede `stopped` (claude-agent-acp sends a best-effort `stopped` and its correction in the same millisecond). Only a command that keeps its own shell running becomes a Codex task; one Codex detached itself with `… >file 2>&1 &` returns at once and yields none, which is why `probe-agent-host.ts --background` spells the command out. `stopAsyncTask` (WebviewMsg) sends `_session/async_task/stop { sessionId: <carrying session>, asyncTaskId }` only for `canStop` running / paused tasks; `stopRequested` is optimistic and the adapter's state update settles the row. Process exit, reconnect, dispose and `restoreInterruptedTurns` mark live task rows `observation: 'unknown'` with `canStop: false`, keeping the last known state. - Empty ACP prompt completions: a normal message acknowledged with `end_turn` but no blocks or only whitespace text becomes a persisted, retryable `empty_response` turn error. The message explicitly says the CLI supplied neither a reply nor error details; no upstream cause or JSON-RPC code is invented. Slash-command receipts, automatic compaction, thought/tool output, refusal and cancellation retain their existing handling. - Attachments: the webview turns pastes / drops / `@` picks into `Draft`s (`webview/chat/drafts.ts`, `Mention.tsx`) and sends them with the prompt; workbench drags are read from `application/vnd.code.uri-list` (every dragged URI; `fillEditorsDragData` in VS Code 1.140 puts only the first into `text/uri-list`), then `text/uri-list`, `CodeFiles` / `ResourceURLs` / `CodeEditors` (`workbenchUris`; `CodeFiles` paths become `file:` URIs, a UNC `\\server\share\…` with the server as authority, which `file_url_to_path` resolves only on Windows) because a drag from an extension tree view whose `TreeDragAndDropController.dragMimeTypes` lists `text/uri-list` arrives with that type and `ResourceURLs` blanked (`CustomTreeViewDragAndDrop.addExtensionProvidedTransferTypes` writes `''` for every declared type; read from VS Code `main` source 2026-09 and the 1.140 bundle 2026-10). Live, a Shift-drag from the Asgard extension tree (`asgard.explorer`, VS Code 1.140, Acpira 1.8.2, macOS) still attached nothing although the source says `CodeFiles` / `CodeEditors` survive; what reaches the webview is unconfirmed, so a workbench drag (any `application/vnd.code.*` type) with no readable format is accepted without the highlight and its drop raises `attach.noPaths` listing the received types (`pathlessWorkbenchDrag`). Any workbench drag reaches a webview only while Shift is held (`webviewElement.ts` sets `pointer-events: none` on every webview at window `dragstart`), so a drop hint can only show once Shift is down; `acp/session/attachments.rs` (`preparePrompt`) writes images and dropped text to the session's blob dir and builds the `ContentBlock[]` — text → inline `image` → embedded `resource` (uri = blob path) → `resource_link` (Explorer / `@` files; image files among them are read and sent as `image`). An OS file pasted or dropped from Finder exists only as bytes in the webview: small text without NUL is embedded as a `text` draft, anything else (video, archives, text over `MAX_TEXT_BYTES`) up to `MAX_FILE_BYTES` (50 MB) becomes a `file` draft with base64 `data` and a placeholder `attachment:///<name>` uri; `preparePrompt` stages it as `<hash>.<own ext>` in the blob dir and links that path, which also becomes the persisted `Attachment::File.uri`. The turn keeps `Attachment`s (blob name / uri only); the webview loads blobs from `InitState.blobBase` (the sessions dir as a webview URI, added to `localResourceRoots`). `@` search is `host/files.ts` (`findFiles` cached 15 s, fuzzy-scored host-side) answered over `searchFiles` → `files`. Inline editors (history / queue) pass their kept attachments as bare `EditAttachments` items through `ComposerProps.edit.attachments`; `DraftChips` renders them at the head of its own wrapping row (`before`), so kept and newly pasted attachments share one row instead of stacking two
- Editor selections and transcript quotes are two more `Draft` / `Attachment` kinds. `selection` (`uri`, `name`, 1-based inclusive `startLine` / `endLine`, `text`) comes from the composer's live-selection chip, the `addSelection` command, or a paste whose text equals the last `editorCopy` (`chat/editorContext.ts` `copiedSelection`: line endings normalized, multi-line copies only, so a single copied word stays text); `preparePrompt` stages the text as a `.txt` blob and sends an embedded `resource` whose uri is the file's with a `#L<start>:<end>` fragment (Zed's form), or without `embeddedContext` a `[Selection: name (a-b)]` … `[End of selection: …]` text block; the turn's `Attachment` keeps the blob, so an edit / retry restores the exact text sent, not the file's current lines. `quote` (`text`, optional `comment`) comes from selecting text in the transcript; each quote becomes one text block — `[Quoted from the conversation]`, the text as a `>` blockquote, then `[Comment on this quote]` and the comment when there is one — placed ahead of the typed text and of every other block. Quotes are not listed as named attachments (export renders them as blockquotes above the prompt, `compact_turn` / `describe_drafts` show the first quoted line). - Per-turn statistics, forking, and export: `AgentTurn.usage?: TurnUsage` carries the token accounting a peer puts on the `session/prompt` response (`acp/session/turn_usage.rs` `turnUsageOf` — standard `usage` fields, Grok's `_meta` token / `modelId` / `requestId` fields, Devin's `_meta['cognition.ai/userMessageId']`; all are per prompt, not cumulative, and fields the peer did not report stay absent — Kimi 0.41.0 reports none). `usage_update` also stamps `{ used, size }` onto `usage.context` of the last turn when it is an agent turn (the last overwrite is the end-of-turn snapshot; Kimi's late idle notification lands on the finished turn; Grok's `session/info` poll stamps the same field). Forking (`WebviewMsg` `forkSession { sessionId, turnIndex }` → `SessionManager.forkSession`) copies the transcript prefix through a chosen agent turn into a fresh record (`historyPending: true`, `forkedFrom` provenance, attachment blobs re-saved under the new id, copied turns stripped of live state); the fork's first prompt prepends `historyContext` (`FORK_HISTORY_LEAD`) the way an edit rebuild does and marks the user turn `edited: true` so `retryTurn` rebuilds the prefix the same way — native `session/fork` is deliberately unused (whole-session, not turn-addressed). Agent-generated `session_info_update` titles are ignored while a prompt carrying injected history context is in flight and always for a forked session (`AcpSession.agentTitleMuted`) — the observed cause: Kimi 0.41.0 titles a session from the first content block, which there is the history resource, and Grok re-titles from the prompt; the `Fork: …` title stays provenance the user can rename. Export (`exportSession { id, format }` → `SessionManager.exportSession` → `shared/exportTranscript.ts` `exportMarkdown` / `exportFileName` → `TranscriptStore.writeExport` under `~/.acpira/exports`) writes the file without opening it: the toast names the path and carries an Open button (`PlatformRequest` `toast.open { label, path }`; VS Code shows it as a notification action, IDEA as a `NotificationAction`, the file opens only on click).
