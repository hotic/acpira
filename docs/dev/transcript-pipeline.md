# Transcript pipeline

How ACP updates become transcript blocks: prompt staging, tool content, native import, subagents, JetBrains AIR extensions, empty completions, attachments, per-turn usage, forking and export.

- Prompt staging follows the agent's advertised `promptCapabilities` (`attachments.rs` `PromptCaps` / `promptCapsOf(init, def)`, threaded into every `preparePrompt` call: live prompt, queue staging, edit rebuild, `historyContext`): `embeddedContext: false` turns a dropped text attachment into a `text` block bracketed by `[Attachment: <name>]` / `[End of attachment: <name>]` (the blob is still saved); `image: false` drops image drafts and image files with a `host.imageUnsupported` problem unless the agent declares `imagesRegardless`. DSH and pi-acp advertise `embeddedContext: false` and reject embedded `resource` blocks. Verify with `test/pastedText.test.ts` and the `FAKE_PROMPT_CAPS=strict` cases in `tests/engine/acp_session.rs`
- Tool content is a list: `ToolCallBlock.contents?: ToolContent[]` holds every renderable item of a `tool_call_update` in wire order (a diff per `diff` item, one merged text per run of `content` items) whenever there is more than one; `content` stays the primary item (a diff wins over text) so records written before the field render unchanged, and `diffStat` sums every diff. `ToolCall.tsx` stacks `contents` with each diff under its own `source.path`; `Terminal.tsx` joins the texts. `terminal` items carry no body of their own: pi-acp streams bash output through `_meta.terminal_output.data` deltas and `_meta.terminal_exit.exit_code` (a non-zero code appends `exit code N`), codex-acp/claude-agent-acp use `_meta.terminal_output_delta` + `terminal_exit` the same way (the host advertises `clientCapabilities._meta.terminal_output_delta`), all of which `mergeTool` folds into the text content; codex-acp's completion `rawOutput { formatted_output, exit_code }` renders as its plain text instead of JSON, and a bare terminal item from an agent that expects a client terminal keeps the `host.terminalNotWired` note (replaced the moment real output arrives). `image` items (a `content` item carrying an image content block) become image contents whose base64 payloads `NormalizeState.saveImage` parks in the session blob store under the content-hash name (`AcpSession.saveImage`, capped by `MAX_OUT_IMAGE_BYTES`, mime allowlist png/jpeg/gif/webp; a refused payload degrades to a `[image: <mime>, not shown]` note), and a `resource_link` to a local image file (codex-acp's `view_image` preview) is read through `saveImageFile` into the same blob store, the link's uri kept as the caption; `agent_message_chunk` images become standalone transcript blocks that split the text run. The webview renders them via `chat/AgentImage.tsx` (blobBase URL + Lightbox, `uri` as an openable caption). Permission requests are low-fidelity: OpenCode's `session/request_permission` embeds a `toolCall` with `kind: 'other'`, the parent directory as `title`, and both the file and its directory as `locations`, racing the real `tool_call_update`; `permissions.ts` `permissionToolUpdate` applies it only as an upgrade to an existing block (never `other` over a specific kind, locations only when there are none, title / rawInput only without a target), the whole thing when no block exists yet (Devin / Kimi plan approvals). OpenCode's `write` completes with text only (`rawOutput.output` "Wrote file successfully.", `metadata.exists: false`); `NormalizeState.pendingWrites` remembers the in_progress `rawInput.content` per tool id and, on that evidence of a new file, synthesizes an all-add diff as the primary content (an overwrite keeps the receipt text — an all-add diff would lie). Verify with `tests/engine/normalize.rs` and the `tool-downgrade` / `tool-downgrade-late` cases in `tests/engine/acp_session.rs`
- Image generation calls: `normalize.rs` names a tool `verbKey: 'verb.imagegen'` by identity: the `Image generation` title (codex-acp), `image_gen` / `image_edit` in `_meta["x.ai/tool"].name`, or an `imagine:` / `imagine-edit:` title (Grok). The key survives later title-less packets, and the title never becomes the target (`rawInput.prompt` / `description` does when present). A completed call with no image item gets the absolute image paths in its text results or `rawOutput` read into the blob store (`attach_saved_images`, same saver and 20 MB cap as `resource_link` images, relative paths ignored). In the webview, `shared/imageTools.ts` (`isImageGenTool` / `toolImages` / `toolTexts`) drives the row: `ImagePlus` icon, the revised prompt as its disclosure body, and `chat/GeneratedImage.tsx` renders the images. In the Codex fold those images sit outside the process fold (`CodexMessage`, after notices) so a collapsed history never hides a result; in cursor mode they sit under the row. A call first seen running in this view gets a square `--agent-image` inset card (`bg-chip`, `--image-gen-card-shadow`) with img-fx's `ImageGeneration` mosaic in it, recoloured from the theme (`effects/imageGen.ts` / `imageGenPalette.ts`, parameters in `effects/presets.ts` `IMAGE_GEN`): `cardBg` is the opaque colour actually painted behind the card (translucent layers composited), the palette mixes `--fg-1` into it per slot with the `--image-gen-peak` colour in the highlight slot, and light paper takes lighter steps. The preset palettes shipped a fixed `#0f0f0f` card and near-white light colours, which read as a black hole on the `#181818` / `#1f1f1f` bases and vanished on light themes (with the former `strength: 0.4` on top); img-fx's default 10 fps stuttered at card size, so the frame rate is 30. On completion the card decodes the blob, takes the image's aspect ratio (--dur-open width transition), fades the mosaic out and dissolves the image in on a canvas cell by cell from the centre (`dissolveIn`, 1.2 s), then (or after a 6 s timeout) hands over to `AgentImage`, whose `box-content` border keeps the layout still. The look was picked in `lab/image-gen-fx.preview.html` (frame / loader / reveal / tone axes, with a long-task readout). The hitch when the card appeared was img-fx building its shared WebGL renderer and three linking the shader synchronously on first use (a 137 ms long task in headless Chrome 2026-09, against 0 ms for Canvas 2D loaders); img-fx also disposes that renderer with its last instance, so every card paid it again. The mosaic therefore mounts on the next idle slot rather than with the row, and `keepImageGenRenderer` parks a paused 1 px instance that keeps the renderer alive for later cards (paused instances are skipped by the render loop and the GL canvas sizing). The first card in a webview still pays the one-time build. History, replay, a remount after completion, `motion: none`, reduced motion and no WebGL (`effects/webgl.ts`, shared with metal-fx) all render the static image (placeholder: a plain / pulsing chip square). img-fx injects its own unlayered `<style>`, so its root needs `block!`; the webview CSP already allows inline styles. `three` is its peer dependency and makes up most of the bundle cost (~600 KB). Verify with `test/imageTools.test.ts`, the `image-gen-codex` golden case, the two image generation cases in `tests/engine/normalize.rs` and `lab/image-gen.preview.html`
- Native session import: the history list's Import button (`chat/SessionList.tsx` `ImportSessions`, `Import` icon on the filter row) asks the host for an agent's own sessions (`WebviewMsg listNativeSessions` → `SessionManager.listNativeSessions` → `acp/native_sessions.rs`: a throwaway spawn runs `initialize` + paged `session/list { cwd }` and dies — never `session/new`, since OpenCode / DSH / Pi all persist a session on creation; empty pages are paged through while a `nextCursor` exists (codex-acp filters each 25-thread page by cwd string, so a foreign-project page is `[]` with a cursor, capped at 40 pages / 200 sessions) and an empty listing for a symlinked cwd is retried once with its `realpath` (codex-acp stores the canonicalized thread cwd — macOS `/var` → `/private/var`) and answers `HostMsg nativeSessions` with `NativeSessionInfo[]`, `localId` set for sessions a record already holds (`SessionSummary.acpSessionId`; summaries written before the field are back-filled from their record once and marked `touched` so the index write keeps it). `importNativeSession` creates a record with `acpSessionId`, `importPending: true`, `importedFrom`, and starts it: `openSession` then tries `session/load` before `session/resume` so the native history replays into the empty transcript (`sealReplay` closes the streamed blocks and stamps `stop: 'end_turn'`), a 'gone' answer becomes `host.importGone` (error + Retry, never a silent `session/new`), and an import that resumed without replay (DSH has no `load`) gets the `host.importNoHistory` toast. Picking an already-imported row selects its record. Verified end to end against OpenCode 1.18.15 with `scripts/probe-opencode-host.ts`; `tests/engine/session_manager.rs` covers list / import / dedupe with the fake's `FAKE_SESSION_DIR` store
- Subagents are first-class nodes, never mixed into the parent transcript: `src/shared/subagents.ts` (`SubagentSummary` on `SessionView.subagents`, `SubagentRecord` with the child's own `turns` on `SessionRecord.subagents`) and `src/host/acp/subagents/` (`SubagentTree` per `AcpSession`: nodes with their own `NormalizeState`, peer-id indexes, orphan buffer 8 ids × 64 updates, lifecycle; `wire.rs` the extension decode). Three visibility tiers, each verified on the wire with `scripts/probe-subagents.ts` (raw ndjson, nothing validated away) and `scripts/probe-subagents-host.ts` (the `SessionManager` path): `session` — claude-agent-acp 0.78/0.79 streams the child's own updates under its own session id after `subagent_spawned` / `subagent_state_update` on the parent (the RFD #1992 `subagent_update` upsert is decoded too; the RFD is still open and its wire shape changed 2026-09-15), gated by `_meta.jetbrains.air = { version: 1, capabilities: ['nativeSubagentSessions'] }` because the adapter's SDK strips the draft `clientCapabilities.subagents` field (both are advertised at `initialize` unless `AgentDef.subagents === false`; Devin / Kimi / Grok / OpenCode accept the unknown key and ignore it); `nested` — Devin 3000.11.1 announces with `tool_call_update` `_meta['cognition.ai/subagent_started'] { agentId, title, task, profile, model, depth, isBackground }` whose `toolCallId` is the agentId (never a root tool row), ends with `subagent_completed { agentId, success, summary }`, and marks the child's own tool calls and `usage_update`s with `subagent_context.parentAgentId` (a child usage must never land on the root ring); `run_subagent` rows link by title+task and get `subagentId`, `read_subagent` rows stay visible as `verb.awaitSubagent`; Claude without AIR uses `claudeCode.subagent` + `parentToolUseId` the same way; `receipt` — Kimi 0.41.0's `Agent` tool with `rawInput { prompt, description, subagent_type }`, result text only. SDK 1.4.0's `zSessionUpdate` is a closed union, so `AgentProcess` rewrites extension kinds into `session_info_update._meta['acpira/extension']` before the SDK parses them (same handler ⇒ wire order kept; a custom method would dispatch through another handler index). Lifecycle follows the RFD: a child still `running` when the parent prompt returns, the connection ends or the session is disposed becomes `disconnected` / `stateSource: 'local'` (never failed / cancelled); a later agent terminal replaces it, nothing revives a terminal node, and content that arrives after the terminal word drops (usage metadata still applies); `session/cancel` with the child id only when `controls.cancel`. Permission / elicitation requests route by `sessionId` into the owning transcript (`PermissionGate` / `QuestionGate` `stateFor`, which answers `cancelled` for a terminal node), mirrored on `SubagentSummary.permissions` / `question` so the root view shows them with provenance; a child going terminal (`SubagentTreeDeps.onTerminal`) or being cancelled — descendants included — answers its pending requests `cancelled`, and `QuestionGate.settle` pins a card to its owning transcript because block ids restart at `q-1` on every reopen. Routing invariants: `toolOwner` indexes only nested / receipt children (a `session` child's updates arrive under its own session id; registering them would hijack a same-named root call), Devin `subagent_started` / `subagent_completed` read before `subagent_context` routing (a nested child's spawn carries its own parent link), and updates naming a not-yet-announced owner buffer under `agent:<id>` / `tool:<id>` orphan keys rather than leaking onto the root. A launch receipt links through three paths (`toolResponse.isAsync`, `pendingLaunches`, the child's `parentToolUseId`) that share `sealLaunchReceipt`, and a nested / receipt node already sitting on the same root call is upgraded in place (`adoptCallNode`) rather than duplicated. `SubagentRecord.rev` persists so a restore never hands the webview a lower revision than it holds. The webview keeps the parent light (`chat/subagents/SubagentGroup` two-line rows in the announcing turn, delegation rows with `subagentId` hidden from the process fold), opens `SubagentInspector` docked at ≥ `--subagent-dock-min` or as a full-width overlay over the inert thread (scroll + draft survive), and subscribes to one child transcript at a time (`observeSubagent` → `HostMsg subagent`, per viewer, `msgBatch` keyed per child); the inspector never offers prompt / edit / retry / fork, and the child's Working row uses a static icon — the root turn owns the only Orb. `lab/subagents.preview.html` holds the five acceptance scenarios; `tests/engine/subagents.rs` + `test/subagentState.test.ts` cover routing, lifecycle, persistence and the pure UI helpers. Observed, not yet explained: one claude-agent-acp run left the launch receipts unlinked (no `toolResponse`, node without model) — the `parentToolUseId` link path exists for that case; capture the wire with `probe-subagents.ts --air` if it recurs.
- JetBrains AIR `sessionFailure` / `asyncTasks` (codex-acp, claude-agent-acp; advertised in `_meta.jetbrains.air.capabilities` next to `nativeSubagentSessions`, see `docs/acp-agents-compat.md`). `session_failure.rs` `failureOf` strictly decodes `_meta.jetbrains.air.sessionFailure` (id, positive-integer revision, severity, title, actions filtered to `retry` / `login` / `new_session`, unknown category → `unknown`). `normalize.rs` `applySessionFailure` keeps one `NoticeBlock` per id across the whole transcript: a higher revision rewrites it in place, a same or lower one is ignored, a different id is a new row even with identical text — except retry warnings (`is_retry_warning`: severity warning, no actions, category connection / service / limit), which are never rows: claude-agent-acp 0.81.0 `api_retry` mints a new session-scoped id per attempt (`…:session-error:<epoch>:<n>`, seen in stored transcripts 2026-09-26), so they set the live turn's `AgentTurn.retry` instead (attempt / max parsed from "attempt N of M", the title as tooltip) and `Turns.tsx` `liveActivity` shows "Retrying (attempt N/M)" on the working row; streamed text / thought / tool call, an error-severity failure or the end of the turn clears it, and a warning with no live turn is dropped; it lands on the last agent turn or a synthesized `end_turn` agent turn. It runs for `session_info_update` in root and child states alike, and is skipped during a restore replay. A turn-ending failure arrives on a successful `end_turn` `PromptResponse._meta`: `AcpSession.prompt` upserts the notice, settles the turn with `failureTurnError` (`failureId`, `actions` always present — empty means no remedy), skips the empty-response check, and a `login` action moves the session to `auth_required`. `Turns.tsx` suppresses the notice whose id matches `turn.error.failureId` (the Alert card shows it); `Alert.tsx` renders only the declared actions. `asyncTasks`: `wire.rs` decodes `async_task_spawned` / `_progress` / `_state_update` into `AsyncTaskEvent`; `AcpSession.asyncTaskUpdate` routes by the carrying session id (root state or the child node's state via `SubagentTree.taskState`) and `normalize.rs` `applyAsyncTask` attaches `ToolCallBlock.asyncTask` to the `toolCallId` row (a later toolCallId adopts a synthesized `async:<id>` row instead of duplicating it; a task without a row is synthesized only when `showInTranscript`). A row with `asyncTask` takes its status from the task state only (`tool_call_update` statuses no longer overwrite it), is `background`, and `endTurn` leaves it alone while running / paused. Terminal states are final except that `completed` / `failed` supersede `stopped` (claude-agent-acp sends a best-effort `stopped` and its correction in the same millisecond). Only a command that keeps its own shell running becomes a Codex task; one Codex detached itself with `… >file 2>&1 &` returns at once and yields none, which is why `probe-agent-host.ts --background` spells the command out. `stopAsyncTask` (WebviewMsg) sends `_session/async_task/stop { sessionId: <carrying session>, asyncTaskId }` only for `canStop` running / paused tasks; `stopRequested` is optimistic and the adapter's state update settles the row. Process exit, reconnect, dispose and `restoreInterruptedTurns` mark live task rows `observation: 'unknown'` with `canStop: false`, keeping the last known state. Verify with `tests/engine/failures.rs`, the failure / async cases in `tests/engine/acp_session.rs` and `tests/engine/subagents.rs`
- Empty ACP prompt completions: a normal message acknowledged with `end_turn` but no blocks or only whitespace text becomes a persisted, retryable `empty_response` turn error. The message explicitly says the CLI supplied neither a reply nor error details; no upstream cause or JSON-RPC code is invented. Slash-command receipts, automatic compaction, thought/tool output, refusal and cancellation retain their existing handling. Verify with the empty-completion cases in `tests/engine/acp_session.rs`.
- Attachments: the webview turns pastes / drops / `@` picks into `Draft`s (`webview/chat/drafts.ts`, `Mention.tsx`) and sends them with the prompt; `acp/attachments.rs` (`preparePrompt`) writes images and dropped text to the session's blob dir and builds the `ContentBlock[]` — text → inline `image` → embedded `resource` (uri = blob path) → `resource_link` (Explorer / `@` files; image files among them are read and sent as `image`). The turn keeps `Attachment`s (blob name / uri only); the webview loads blobs from `InitState.blobBase` (the sessions dir as a webview URI, added to `localResourceRoots`). `@` search is `host/files.ts` (`findFiles` cached 15 s, fuzzy-scored host-side) answered over `searchFiles` → `files`. Inline editors (history / queue) pass their kept attachments as bare `EditAttachments` items through `ComposerProps.edit.attachments`; `DraftChips` renders them at the head of its own wrapping row (`before`), so kept and newly pasted attachments share one row instead of stacking two
- Per-turn statistics, forking, and export: `AgentTurn.usage?: TurnUsage` carries the token accounting a peer puts on the `session/prompt` response (`acp/turn_usage.rs` `turnUsageOf` — standard `usage` fields, Grok's `_meta` token / `modelId` / `requestId` fields, Devin's `_meta['cognition.ai/userMessageId']`; all are per prompt, not cumulative, and fields the peer did not report stay absent — Kimi 0.41.0 reports none). `usage_update` also stamps `{ used, size }` onto `usage.context` of the last turn when it is an agent turn (the last overwrite is the end-of-turn snapshot; Kimi's late idle notification lands on the finished turn; Grok's `session/info` poll stamps the same field). Forking (`WebviewMsg` `forkSession { sessionId, turnIndex }` → `SessionManager.forkSession`) copies the transcript prefix through a chosen agent turn into a fresh record (`historyPending: true`, `forkedFrom` provenance, attachment blobs re-saved under the new id, copied turns stripped of live state); the fork's first prompt prepends `historyContext` (`FORK_HISTORY_LEAD`) the way an edit rebuild does and marks the user turn `edited: true` so `retryTurn` rebuilds the prefix the same way — native `session/fork` is deliberately unused (whole-session, not turn-addressed). Agent-generated `session_info_update` titles are ignored while a prompt carrying injected history context is in flight and always for a forked session (`AcpSession.agentTitleMuted`) — the observed cause: Kimi 0.41.0 titles a session from the first content block, which there is the history resource, and Grok re-titles from the prompt; the `Fork: …` title stays provenance the user can rename. Export (`exportSession { id, format }` → `SessionManager.exportSession` → `shared/exportTranscript.ts` `exportMarkdown` / `exportFileName` → `TranscriptStore.writeExport` under `~/.acpira/exports`) writes the file and opens it through `platform.openResolvedFile`. Verify with `tests/engine/failures.rs`, `test/exportTranscript.test.ts`, and the usage / fork / export cases in `tests/engine/acp_session.rs`, `tests/engine/session_manager.rs`, `tests/engine/normalize.rs`, and `test/sidecarRuntime.test.ts`
- Automatic user turns: `UserTurn.auto` marks a prompt Acpira sent itself and never renders as a bubble; `autoReason` tells them apart (absent / `compact` = the over-threshold `/compact`, `accountSwitch` = the hidden continue after an automatic account switch, whose visible trace is the `NoticeBlock` on the exhausted turn). Both exporters (`shared/exportTranscript.ts`, `acpira-shared/src/export_transcript.rs`) write a note line per reason (`export.label.autoCompact` / `export.label.autoContinue`)
