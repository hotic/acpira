# iOS app

The native iOS client under `apps/ios/` (since 2026-10-09): a SwiftUI control surface for the engine running on the user's Mac. Agents, sessions, approvals and keys stay on the Mac; the phone is one more client of the engine, never a mirror of a desktop window. Status: the chat, the session list and every transcript block render from synthetic fixtures, matched against the webview at phone width; there is no engine connection yet. The phased plan with its open decisions is `docs/ios-app-plan.md` (local only, may be absent).

## Layout

- `apps/ios/Acpira.xcodeproj` — the app target `Acpira` (iPhone only, iOS 26.0+, Swift 6 with complete concurrency checking, approachable concurrency and main-actor default isolation as in Xcode 27's template, bundle id `com.hotic.acpira`, marketing version 0.1.0) and its hosted Swift Testing bundle `AcpiraTests`. Both folders are synchronized groups (Xcode 27, `objectVersion = 90`): a file added under `apps/ios/Acpira/` or `apps/ios/AcpiraTests/` joins its target without editing `project.pbxproj`. No signing team is set: simulator builds need none; a device run needs a team picked under Signing & Capabilities, which Xcode writes into the project
- `apps/ios/Packages/AcpiraKit` — nearly all code, one library product `AcpiraKit` linked by the app, which imports the modules one by one:
  - `AcpiraModels` — Codable mirrors of the subset of `packages/shared` the app renders (`SessionView`, `HostMsg` / `WebviewMsg`, the sidecar envelopes). Decoding is tolerant: an unknown kind decodes into a placeholder, because the engine on the Mac updates faster than the App Store ships the app
  - `AcpiraSync` — the envelope client, session patches applied with stable identity (`packages/shared/sessionPatch.ts` and `reuse.ts` are the reference), transports behind one protocol; no SwiftUI or UIKit
  - `AcpiraDesign` — tokens and motion parameters generated from `packages/ui/styles`, Metal ports of the webview's WebGL effects
  - `AcpiraMarkdown` — Markdown → block AST, plus `Remend` (a port of remend, which streamdown runs on a streaming reply to close its unfinished tail)
  - `AcpiraFixtures` — the synthetic sessions (`synthetic/*.json`: showcase, running, streaming, question, queued, stopped, empty, agents, sessions, accounts, clock) the app and the LAB reference page both render, written by `lab/ios-fixtures.gen.ts` (local only; `pnpm exec tsx --tsconfig lab/tsconfig.json lab/ios-fixtures.gen.ts`). `clock.json` is the fixtures' "now": quota resets and timestamps are written relative to it and the app reads it through `\.now` in place of the real time; from launch the app's clock runs on from it (`\.clockOffset`, `AppModel.now`), which a running turn's live counter reads, so a fixture's running turn starts before it (one after it reads a negative time and its counter stays hidden)
  - `AcpiraUI` — screens and components, main-actor by default (`.defaultIsolation(MainActor.self)`); `Logic/` ports the webview's pure transcript logic (processGroups, folding, toolDetails, commandDuration, turnOutcome, `shared/models.ts` + `composerControls.ts` as `ModelCatalog` / `ComposerControls`, `streamMotion.ts` pacing as `StreamPacer`) under the TypeScript names, `Prose/` the markdown views with the KaTeX-metric math typesetter and the mermaid flowchart port (`Mermaid/Dagre.swift` follows dagre-d3-es)
  - `AcpiraKitTests` — the package's Swift Testing suites; `ContractTests` pins Swift mirrors to the TypeScript sources by reading them from the repository (skipped where the source tree is not readable)
- Generated, committed, each with a drift test under `test/`: `AcpiraDesign/LucideIcons.generated.swift` (`scripts/export/ios-icons.ts`), `AcpiraDesign/KaTeXMetrics.generated.swift` + the KaTeX fonts (`scripts/export/ios-katex.ts`), `AcpiraUI/Resources/i18n/*.json` (`scripts/export/ios-i18n.ts`), `AcpiraKitTests/RemendCases.generated.swift` (`scripts/export/ios-remend.ts`: remend's own output for every prefix of a few streamed documents plus edge cases, replayed by `RemendTests`), `AcpiraUI/Resources/shiki/` (`scripts/export/ios-shiki.ts`: shiki's core and JavaScript regex engine as one script for JavaScriptCore, the webview's grammars and themes as JSON, codeLanguage.ts's tables as `languages.json`). Regenerate with `pnpm exec tsx scripts/export/ios-<name>.ts` after bumping the package
- `apps/ios/scripts/check.sh`, `apps/ios/scripts/shot.sh`, `apps/ios/scripts/render.sh`, `apps/ios/scripts/record.sh` — see Commands
- `apps/ios/Fixtures/local/` (git-ignored) — fixtures exported from real sessions; only synthetic fixtures are committed

## Rules

- Every `AcpiraKit` module also builds for macOS, because `swift test` builds all of them: UIKit-only code goes behind `#if canImport(UIKit)`
- The package uses the app target's concurrency dialect (`MemberImportVisibility`, `NonisolatedNonsendingByDefault`, `InferIsolatedConformances` in `Package.swift`), so code reads the same on both sides of the package boundary
- Views take sizes, spacing, radii, type and motion from `AcpiraDesign`, never raw numbers (the webview's token rule); rows share one row component, as `ui/Row` does on the web
- Comments in English; Swift is indented with two spaces (`apps/ios/.editorconfig`, also set on the project's main group)
- The phone must never join a persistent engine as an ordinary shell. A `hello` on a running engine calls `platform.rebind` with that wire's env, settings snapshot and capabilities, and `hello`, view messages and `windowFocus` make the wire the target of IDE actions (file opens, terminals, toasts; `rust/crates/acpira-host/src/sidecar/server.rs`). Remote access needs its own wire role that never rebinds and never becomes the active wire
- Sending real prompts from the app spends model calls; prefer replayed fixtures and ask first, as with the host probes
- Text that mirrors the webview goes through `Text(web:)` / `CJKWidth.attributed` (CJK widths, Chrome's break opportunities, the paragraph end, see below) and `textStyle(_:)` (the CSS line box). A run concatenated into a larger `Text` passes `paragraph: false`; the paragraph adds the end once
- The transcript and the rows it shares with the dock take the webview's tokens at the app's reading size (`WebType` / `WebMetrics`, `AcpiraDesign/WebScale.swift`: the airy density at ui 17 / code 14 under `Reading.phone`); the chrome around it (list, settings, composer, header, sheets) keeps the phone's `TypeScale` / `Metrics`
- `DiffLine.text` carries its sign column (' ', '-', '+'; `transcript/diff.rs`): the gutter draws the sign and the code drops the first character (`DiffLine.code`, as codeDiff.ts `plainDiffRows`). Fixtures write it the same way
- Code colours come from shiki itself in JavaScriptCore (`Logic/Syntax.swift`, the `Resources/shiki` bundle above), with the webview's JavaScriptCore regex options, so tokens and colours match the desktop's. Tokenizing runs off the main actor and is cached by source; the full-length render (`\.snapshot`) tokenizes in place, as its tasks may not run before the image is taken. The phone has no whole-file diff source, so a diff colours each visible segment, codeDiffHighlight.ts's fallback
- Where the web element has a CSS `border`, the border takes layout room; a SwiftUI `strokeBorder` overlay does not, so the padding carries `+ Metrics.hairline` (permission and question cards, buttons horizontally, the question footer's `border-t`, the code-output frame, fenced code). An `inset` box-shadow (the user card) takes no room and needs none
- The composer is the one phone-only layout (`Chat/Composer.swift`), built by subtraction: the card (the desktop's rounded-lg, `--cmp-bg`, the conversation hairline, the field two `TypeScale.field` lines high) holds the field and one row: a plain `+` (attach), then the quiet model button (mark, family name, badges, the mode glyph once the mode is not the agent's first, a caret) and send (btn-1, `Metrics.mCtl`). The model button opens one sheet (`ControlsSheet`) with everything the desktop toolbar spreads over chips: `ModelPanel`, the modes under a caption, the other options as `SelectRow`s. Staged attachments (Photos, Files, the camera where there is one) sit in a strip above the field; photos are kept as scaled inline JPEG until attachment staging reaches the engine. The dock, the plan card and the composer run at `Metrics.pad` from the screen edges, the transcript at `--page`, and the chat takes over the home indicator's safe area (`ignoresSafeArea(.container, edges: .bottom)`, the keyboard's still applies) so the dock ends `Metrics.homeReach` inside it. The bottom inset has to be read outside `ignoresSafeArea`; inside it reads 0
- The chat header is back · centred title over `agent · project` · new session (square-pen) · `…`. The desktop's account, history and settings icons fold into the `…` menu (account sheet, pin, rename, exports to the share sheet, settings, delete with a confirmation); history is the back button
- `Store/AppModel.swift` stands in for the engine until the connection lands: the fixture sessions loaded once (a listed session opens the fixture with its title, else the showcase dressed as it), the navigation stack (`Route`: chat, new session, settings), recent projects and the toast. Every control acts on it through `\.sessionActions` (send, queue / send now / edit / remove, stop, permission and question answers, retry / continue, fork, copy, mode and model changes) or `HeaderActions`. A prompt gets `DemoReply`'s turn streamed with `Replay.steps`, so a sent message shows the live turn without spending a model call; the first step lands synchronously, so a second prompt queues at once
- New session (`Sessions/NewSessionScreen.swift`): reached from the list's square-pen (preset to the list's project) and the chat's (that session's agent and project). The empty thread shows the agent's mark, name and the project path; the composer has an agent chip and a project chip under it (sheets; a not-installed agent stays listed, disabled; "Add folder" asks for a path on the engine's computer). The first prompt creates the session and replaces the screen with its chat. Under system chrome the composer stands alone at the bottom and both choices live in the hero at the page's optical centre (`Metrics.heroRise`; the geometric centre reads low): the agent mark (no tile, no caret) sits in a round drop of Liquid Glass that buds the other launchable agents as a ring of glass bubbles (`AgentRing`, one `GlassEffectContainer`), and the folder is a glass capsule `Menu`. Traps: a `scaleEffect` over glass scales the glass but not its content, so the drop never scales; the drop stays for good, as clearing it after a pick read as a second beat even with the name rising in the same move; glass hosts its content in a layer of its own, so a bubble's outer `opacity` misses its mark and the mark carries its own; a fixed ring radius left a few agents far out, so the radius follows the count; the picked mark flies over all the glass (an overlay) while the bubble's glass flies under it, since as the bubble's own content it went under the drop's glass the moment the two met and the centre stood empty; the overlay pins its own animation, as the screen's dim animation keyed on the ring otherwise ran the flight on an ease-in behind the glass; the agent swaps under the flown mark (a transaction with animations off) as it nears the centre, and the name and folder rise back then (`veil`), or after a plain close once the bubbles are home, so no bubble crosses them; ring captions use the hero name's style; a ring mark shrinks and fades on its own bubble's spring and delays (faded at once it left empty drops drifting home); the hero's name swaps by `.id` with an identity transition, since a `.transaction` with no animation on it also kept the group's offset from reaching it and the name jumped as the ring opened; a quick spring with a tiny stagger read as a pop, so the ring moves at the liquid pickers' pace. `-popup ring` / `ring.pick` put the ring out (and pick) after launch for recordings
- Settings (`Settings/SettingsScreen.swift`): theme (system / light / dark), motion, language (auto + the nine tables), the engine connection and the version, as grouped `--bg-1` cards. `Prefs` keys in UserDefaults; launch arguments override them for screenshots. A language switch calls `L10n.setLocale` before storing the choice and `RootView` rebuilds the stack by `.id(locale)`; the path lives in the model, so the reader stays on the same screen
- The session list is phone-only too (`Sessions/SessionListScreen.swift`): one page in two views picked under the large title (`Prefs.listView`), by time (sessions pinned to the top, then day captions) or by project (the same pinned run, then each project as a `ProjectHeader` folding open in place: its own pins first, the latest five, then "N more", the desktop list's project grouping and view-menu defaults). A project section stacked over the timeline showed every session twice, and a page per project put back and its title on two rows. Under system chrome the page has no navigation bar: settings is a glass circle at the end of the title row and opens `SettingsSheet` (title centred inline, close at the bar's end; a pushed settings page stacked a large title under back), presented outside the root's `.id` so a language picked in it does not dismiss it. Pins come in three levels: a session pinned to the top (`SessionSummary.pinned`, taken out of its project group as the desktop's default does), a session pinned inside its project, and a project pinned to the top of the by-project view; the last two are `AppModel` stand-ins (`projectPins`, `pinnedProjects`, with `openProjects` for the folds) until the engine carries them. Rows keep one fact per block, never joined with separators: the mark (ink-fitted, centred on both lines), the title with the time at its right end (only where no day caption dates the row under `rowMeta=quiet`), then the place (the project; the agent inside a project's group) as the second line, and the state's mark alone, no label, in a trailing `stateSlot` column centred on both lines like the lead (every row keeps the slot, so the times line up). `StateMark` ports the desktop's marks and motion (`chat/SessionList.tsx`, `styles/motion.css`) at `Metrics.state*` sizes (desktop sizes on `desk`, about half again on `phone`): a ring spinning once a second that keeps turning with motion off, an amber dot beating (1.4 s), a red dot double-flashing (3 s), a white unread dot with a halo rippling to 2.6 times (2 s), and background work as the still ring with a dot orbiting on its line (3.6 s), lit white with a dot inside when a reply came in. A folded project header shows the desktop's ranked mark (working, waiting, error, unread, background). Under system chrome the chat and the list carry `Design/TopFade.swift`: a progressive blur where content scrolls up under the bar's glass buttons (the system's soft edge effect only reached the status bar's band, so text ran sharp under the buttons; it is hidden there). Three `ultraThinMaterial` layers masked to fade out at stepped heights, under a page-colour gradient that keeps the band within a few levels of the bare page (the materials' own tint read as a grey strip); the chat's band reaches `Metrics.topFadeTail` past the bar, the list's stops at its edge so the title is never veiled at rest. A search lists one run across every project. - The model and project pickers are bottom sheets (`.pickerSheet(isPresented:title:current:)`, `Components/Sheet.swift`): iOS's own sheet (medium / large detents, drag indicator) on `--menu-bg`, one scroll for the whole body, the current row centred. `\.sheetRows` grows `MenuOption` to `Metrics.sheetRow` with a 20 pt mark and body type and drops `PopupList`'s own scroll; `dismissPopup` closes the sheet, so `ModelPanel` works unchanged in either
- Header menus and the composer's short menus (attach, mode) are popups, not sheets: `.popup(isPresented:side:edge:width:)` on the trigger and one `.popupLayer()` on the screen place them as Base UI does (side top / bottom, align start / end, `--pop-gap`, 16 pt collision padding, `w-pop-sm|md|lg` clamped to the screen), in the popup palette (`Palette.menuBg` / `menuLine` / `popFg2` / `popFg3` / `popHover` / `popActive`, the two-layer `shadow-pop`). Rows are `MenuOption`; a delete row sets `\.menuInk`. They open and close without a transition, as on the web
- Entrances follow `process-row-enter`: `AgentMessage` sets `\.rowEnter` and `\.entranceScope` (session id and turn index) while its turn runs, `EntranceOnce(id:)` wraps what the webview wraps (process items `item:<id>`, a tool's `:tool` / `:files`, thoughts, the fold head, group entries), and `Row` fades its lead, content children and trailing slot with the token delays. `EntranceLedger` remembers entered ids, so a lazy stack scrolling a turn back in replays nothing
- A streamed text renders through `StreamProse`: `StreamPacer` paces the received text out (useSmoothText, same constants), and the last text of the visible Prose fades its newest glyphs in through `InlineCodeRenderer` (opacity only, `Motion.streamChar`, CSS `ease`). The fade maps glyphs to characters by distance from the end, so only the tail path (last block, last list item) carries `\.streamFade`; tables, code and math appear whole
- Live times read the app's clock (`Components/LiveTime.swift`) and are not motion, so they tick with motion off: the fold head's counter (TurnClock.tsx, from `clockStart`, hidden under a second, stopped while a plan card waits) and a running command's whole seconds (useToolSeconds). The compaction lead ports `compacting-icon` / `compaction-settle` and `useCompactionPhase` (`CompactionRow`): the Shrink paths move one by one over an invisible `Icon` that keeps the rail anchor, and a completion waits for the loop's shared rest beat before the clamp (`CompactionMotionTests` holds that beat). `-replay` keeps commands and compactions running for `Replay.hold` steps so both can be recorded

The model has no `observation: unknown`, so a ChatGPT-bridge command whose observation was lost would tick

A body rail strips its content's leads. The rail shows at once when a fold opens and fades on the close curve when it closes

Observed 2026-10-09 with Xcode 27.0 (27A266a), Swift 6.4 and the iOS 27.0 simulator runtime:

- A package test target referenced from the project's shared scheme (`ReferencedContainer = "container:Packages/AcpiraKit"`) is not taken: `-only-testing:AcpiraKitTests` fails with "isn't a member of the specified test plan or scheme", and the package's auto-generated `AcpiraKit` scheme reached through the project reports "not currently configured for the test action". Run from the package directory, `xcodebuild -scheme AcpiraKit test` runs the suites on the simulator, which is why `check.sh` has three steps
- A test process on the iOS simulator can read the repository's files, so `ContractTests` runs there as well as on the Mac
- Xcode 27's "new project" quick start creates an untitled multiplatform project under `~/Library/Developer/Xcode/UntitledProjects/` (`SDKROOT = auto`, iOS / macOS / visionOS, a placeholder bundle id); `apps/ios/Acpira.xcodeproj` was written by hand in that file format instead, iOS only
- Opening the hand-written project in the Xcode 27 GUI leaves `project.pbxproj` and the shared scheme byte-identical, resolves the local package (both the `Acpira` and the `AcpiraKit` scheme are registered) and writes only per-user state (`xcuserdata/`, the package's `.swiftpm/xcode/`), which `.gitignore` covers. A diff in `project.pbxproj` after opening the project therefore comes from an edit in Xcode, not from the open itself

Observed 2026-10-09 with Xcode 27.0 (27A266a), the iOS 27.0 simulator and macOS 27, against Chrome in the LAB with streamdown 2.6.0 (remend 1.3.1), KaTeX 0.16.47, mermaid 11.17.2 (dagre-d3-es 7.0.14) and @fontsource-variable/inter 5.3.0:

- Blink places a line's baseline from the primary face alone: ascent and descent each rounded to whole points, the spare line height split with the smaller half above. SwiftUI's exact line height puts it at the rounded-up ascent of the line's tallest face, so a PingFang line sits a point lower than an Inter one. `CSSLineRenderer` moves every line to the Blink depth, and `cssBaseline()` aligns a label on that drawn baseline rather than SwiftUI's
- Chrome sets PingFang from the variable font's default instance with 1.02 em advances; CoreText's PingFang SC instances advance 1 em. `CJKWidth` kerns Han and fullwidth punctuation by 0.02 em so lines fill and wrap where Chrome's do
- Chrome breaks between any two ideographs, kana or Hangul syllables (`word-break: normal`); CoreText segments Chinese by dictionary words ("哪些内容" only breaks before "内容"). A zero-width space between two such characters restores Chrome's opportunities
- With those, SwiftUI `Text` still pushed "内" down: TextKit's default line-break strategy avoids a last line holding a lone CJK word, and SwiftUI exposes no strategy. Any character after the last one defeats the check; `CJKWidth.paragraphEnd` (U+2060) closes every paragraph holding CJK. Latin text gets no push-out
- CoreText's fallback from Inter sets CJK in PingFang SC Regular whatever the weight; Chrome picks PingFang SC Medium for 500 and Semibold for 600 / 700. `InterFont.ctFont` puts the matching PingFang SC face in the cascade list (verified on the simulator and on macOS)
- Chrome's font smoothing draws text heavier: summed glyph ink runs 20–35 % above the simulator's at the same colours and positions, for Inter and PingFang alike. Not corrected
- CoreText drops the space before a truncation's ellipsis (`tail…` where Chrome sets `tail …`), so a cut line ends a character earlier. Not corrected
- streamdown repairs a streaming reply with remend in default mode: links in protocol mode (`streamdown:incomplete-link`), block KaTeX on, inline KaTeX off. Single-dollar math (`$O(n)$`) stays literal on the web, and the app matches
- Web-side deviations the app does not copy: streamdown's class merge drops `text-2` next to `text-fg-2`, so thoughts render at text-1; `--spacing-msg-join` is computed once at the root at the default density, so under airy it stays 8 instead of 12 (the app keeps 12). The LAB reference page itself must import `@fontsource-variable/inter`, or Chrome renders it in the system face
