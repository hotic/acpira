# The built-in agent

Acpira's own agent (`acpira`), for models that have no official harness of their own: DeepSeek, Kimi, GLM, Qwen, MiniMax, OpenRouter and other OpenAI-compatible or Anthropic Messages endpoints, plus local servers. It is Rust inside the engine (`rust/crates/acpira-agent`), served over ACP by `acpira agent --home <root>`, so it ships without Node or any TypeScript. The engine launches it like every other agent: same spawn, warm pool, process group and stderr log. `AgentRegistry::with_self_agent` registers it first, so it leads the agent order until a saved order says otherwise. Feature set and modes follow OpenCode; the loop layering follows Pi.

## Layout

- `<root>/providers.json`: model sources as the settings page writes them (contract in `acpira-shared/src/providers.rs`, mirrored by `src/shared/providers.ts`). Keys live in `<root>/secrets.json` as `acpira.provider.<source id>`, never in the providers file. The host side is `acpira-host/src/providers.rs` (`ProviderStore`).
- `<root>/agent/sessions/<id>.jsonl`: the session log, with `<root>/agent/sessions/<id>/` beside it for `outputs/` (spilled tool output) and `plan.md`.
- `<root>/catalog/models.json`: the daily catalogue refresh the host writes. The agent takes the newer of it and the snapshot compiled into `acpira-shared` (`assets/model-catalog.json`, regenerated by `pnpm catalog:update`).
- Crate modules: `acp.rs` (the ACP surface), `turn.rs` (one turn), `tools/` (read, write, edit, bash, grep, glob, list, todo, exit_plan, plus `names.rs` for name correction), `permission.rs`, `modes.rs`, `prompt/` (layered system prompt), `budget.rs` (tool output budget), `store.rs` (session log), `catalog.rs`, `llm/` (OpenAI Chat and Anthropic Messages clients, `family.rs` per-family request differences, `discover.rs`, `presets.rs`), `mock.rs` (the scripted model server, feature `mock`).

## ACP surface

- `initialize` advertises `loadSession`, `sessionCapabilities.list` and `resume`, and image plus embedded-context prompts.
- Modes are `agent` and `plan`. Both offer the same tools (`modes::TOOLS`, `exit_plan` included; outside Plan mode it answers with an error), so a mode switch never changes the request prefix. Config options are the model select (every usable model, value `<source id>/<model id>`, the source's display name as description), an effort select when the current model has levels (default `high`, else the strongest; a model added by id with none takes the catalogue's, as discovery would have filled them, unless its thinking is off. Without a level and with thinking on `auto` no thinking switch is sent at all, which on Claude means no thinking), and the approval level: `ask` (edits and commands ask), `auto-edit` (edits run, commands ask) and `full` (everything runs). Edits to the agent's own configuration always ask, even under `full`: `providers.json`, `secrets.json`, the prompt override folders and `.agents/hooks.json`.
- Permission rules follow OpenCode's semantics: layers of (permission, pattern, decision) rules (defaults, approval level, what the user allowed in the session, then the mode), last match wins. Reading the session's `outputs/` never asks.
- The host labels the model options by source (`model_sources.rs`, the `acpira` arm), so two sources offering a model with the same name stay two rows in the picker.
- Cancelling ends the turn with `cancelled` at once and sends nothing afterwards. The tool's process group is killed; a model call still waiting for its first chunk is dropped.
- Failed model calls are retried in the turn (`turn.rs`, `MAX_ATTEMPTS` 4): network errors, broken or stalled streams, an `error` event inside a 200 stream and HTTP 408 / 409 / 425 / 429 / 5xx; a rejected key, another 4xx or an in-stream error naming the request or the context is not. The wait is `Retry-After` (at most 60 s) or 1, 2, 4 s. A stream without an event for 300 s counts as stalled (`ACPIRA_AGENT_STREAM_IDLE_SECS` overrides it; Codex's stream idle default). Before a retry the failed attempt's tool rows are marked failed and its partial text is dropped from what the model gets (the streamed chunks stay on screen); a `session_info_update` carrying an AIR `sessionFailure` warning ("Retrying <source>, attempt N of 4") puts the attempt on the working label, cleared when the stream resumes. Each attempt is its own `request` record, `attempt` from 2 on. Verify with `tests/turn.rs` (`an_interrupted_stream_is_retried_and_only_the_retry_counts`, `a_bad_request_is_not_retried`) and `tests/stall.rs`.

## Plan mode

Plan mode allows writing only the session's `plan.md`, whatever the approval level. The model writes the plan there with `write` / `edit`; `exit_plan` takes no arguments (a `plan` argument is still accepted from models that pass one) and sends the plan through `session/request_permission` with `_meta["acpira/planApproval"]` and a `switch_mode` tool call carrying `rawInput.plan` and `planFilePath`, so the host's existing plan card takes it unchanged. The tool call is titled `Exit plan mode` from its first update, which the webview localizes. Approving switches to Agent mode inside the same turn and the model carries the plan out with Agent mode's tools. Refusing ends the turn and the plan stays in place for revision. The mode change reaches the model as a reminder in the next user message, never as a system prompt change.

## Session log

`store.rs` appends one JSON event per line, each with `t` in epoch milliseconds. Nothing is rewritten; what the model gets is a view projected from `item` events.

| Event | Holds |
|---|---|
| `session` | First line: id, cwd, format version (`FORMAT` 1) |
| `item` | One conversation entry as the model sees it |
| `update` | A `session/update` as sent, for replay; streamed text and terminal output merged per block |
| `state` | Mode, model, effort and approval after a change |
| `prompt` | The system prompt whenever it was composed: variant, version, digest, text |
| `request` | One per model call: model, source, format, prompt variant / version / digest, `policies.outputBudget`, usage (input, output, cacheRead, cacheWrite, reasoning), `cost` at list prices, `ms`, `attempt` on a retry, then `stop` or `error`. A call cut off by a cancel is recorded with stop `Cancelled`. A provider that reports 0 prompt tokens gets an estimate from the request's size (about four bytes a token, a thousand per image), marked `usage.inputEstimated` |
| `view` | `changed` (any of `model`, `prompt`, `tools`), `from`, `to`: the request prefix changed between two calls |

- The file is created on the first event that needs it; the `session` and `prompt` prelude waits until then, so an unused session leaves nothing behind.
- `session/load` replays the recorded updates, then serves the session. `session/resume` serves it without a replay; the engine uses resume when reopening (checked by the reopen scenario below, host log `session/resume ok`).
- `session/list` pages 50 sessions per call with a cwd filter and a numeric `nextCursor`.
- A session that is neither open nor on disk answers `-32002`.
- A line cut short by a crash is skipped on read.

## Requests, prompt caching and cost

- The base prompt (`prompt/builtin/base.md`, version 2) is original text: working habits, tool use, honesty (a command is reported only after a tool ran it, even when its output is predictable), care with irreversible actions and the user's uncommitted changes, and answer style.
- The system prompt is composed once per session from the base, a family variant, the user's and the project's same-name files under `.agents/acpira/prompts/`, AGENTS.md and the environment. It is composed again only when a model switch selects another variant.
- Between two ordinary calls the request prefix stays byte for byte: earlier messages, tools and model do not change. Anything that does change it is a `view` event in the log. The engine scenarios assert exactly this pairing.
- Tool output above 2000 lines or 50 KB (OpenCode's limits) is saved under `outputs/`; the model gets a preview, what was cut, and the path. Command output keeps head and tail. The tool card shows the whole output.
- `catalog::complete` fills a model's missing context and output limits from the catalogue (marked estimated) and supplies its prices. `Cost::estimate` bills cache reads and writes at their own prices when the catalogue has them, else at the plain input price. The figure is an estimate at list prices, not the bill.

## Model discovery

`llm/discover.rs` serves the settings page through the host (`providerProbe` → `providerProbed`, kinds `models`, `check`, `test`, `local`), on the host's blocking pool with its proxy-aware HTTP agent.

- Metadata comes in three tiers. First the fields the endpoint reports. Then the catalogue, matched by `model_key` (gateway prefixes such as `deepseek/` stripped, case and separators normalized). Then defaults: a 128000-token context and text-only input. Every value not reported by the endpoint is named in `estimated`; the page marks it Unconfirmed until saved, and the turn loop never sends an estimated value as a limit.
- Listing shapes handled: OpenAI-style id-only lists, OpenRouter's full metadata (`context_length`, `top_provider.max_completion_tokens`, `architecture.input_modalities`, `supported_parameters`), Anthropic's paged list (`?limit=1000&after_id=`, `x-api-key` plus `anthropic-version`, and a bearer token too when the host is not api.anthropic.com), Gemini's native `models/` names with `inputTokenLimit` / `outputTokenLimit`, LM Studio's `/api/v0/models` (read first; the loaded window wins over the maximum) and Ollama's `/api/show`. Embedding models are dropped. Unverified: these shapes in `tests/discover.rs` are written from each server's public documentation, not recorded off a wire.
- Ollama's context from `/api/show` is the model's trained window, not the `num_ctx` the server actually serves, so it is always marked estimated.
- `check` lists the models (free); `test` makes one real call with `max_tokens` 16 and thinking off; `local` probes Ollama and LM Studio on their default ports with short timeouts and no proxy.
- Presets (`llm/presets.rs`): DeepSeek, Moonshot, Zhipu, Z.ai, DashScope, MiniMax, OpenRouter, SiliconFlow, Ollama and LM Studio, plus Custom. Each vendor preset resolves to a family in `llm/family.rs`.

## Tests

- `cd rust && cargo test -p acpira-agent`: the agent against the scripted model server over an in-process ACP client. Covers streaming, both wire formats, tools and permission cards, name correction, the output budget, Plan mode, the session log round trip and discovery.
- `cargo test -p acpira-host --test engine builtin_agent`: the engine drives the real `acpira agent` binary against the scripted server in four scenarios: an edit behind a permission card, a Plan approval that builds in the same turn, a cancel before the first chunk, and a reopen that resumes. Every scenario checks the prefix rule against the session log. The edit, plan and cancel transcripts are golden output in `test/fixtures/engine-builtin.json` (Unix only, temp paths written as `/acpira`, `/repo` and `SESSION`), rendered by `test/builtinAgent.test.ts`; `ACPIRA_UPDATE_FIXTURES=1` records an intended change.
- The agent reads the user-level `~/.agents/AGENTS.md` of whoever runs the tests into its system prompt. No assertion depends on it.

## Windows

The bash tool runs `powershell.exe -NoProfile -NonInteractive -Command` there, never the `bash.exe` on PATH (on the test machine that is WSL's launcher in `System32`). Windows PowerShell 5.1 writes piped output in the OEM code page (936 on a Chinese system), which came out as mojibake; every command is now prefixed with a switch of `[Console]::OutputEncoding` (and `$OutputEncoding`) to UTF-8, which native commands started from it follow because they share its hidden console. Tool results show paths with forward slashes, since joining a model's `src/util` with a file name gave `src/util\b.rs`. Cancelling kills the command's whole tree through `taskkill /T /F`.

Verified 2026-10-10 on Windows 11 (PowerShell 5.1.26100.8115, code page 936), with the agent crate's test binaries cross-built for `x86_64-pc-windows-gnu` and run over SSH: all unit tests (including the Windows-only Chinese output and cancel tests in `tools/bash.rs`) and every integration suite against the scripted server passed. The engine scenarios in `builtin_agent.rs` were not run on Windows.

## Real providers

Verified 2026-10-11 (acpira 1.9.1) through an OpenAI-compatible gateway, one `openai-chat` source with `scripts/probe-agent-host.ts acpira --home DIR` (DIR holds `providers.json` and `secrets.json`; a `--home` root is kept after the run). `--shell --attach` and `--write --plan` run separately, since the click-through approver stands down under `--write` / `--plan` until the scenario has answered its own card.

- `minimax-m3`, `gpt-6-luna` and `glm-5.3-flash` pass every check: pong, text attachment, a `bash` row with its plain-text output, an edit behind a permission card, a plan card titled `Approval needed: Exit plan mode` linked to its plan document and rejected without a write. Streaming text and reasoning, tool calls, usage and cost records all come through.
- Honesty: right after a "reply with only that word" turn, asked to run `echo acpira-shell-ok`, `glm-5.3-flash` answered without running it 2 times in 15 under the version 1 base prompt and 0 in 15 under version 2 (a command with unpredictable output: 10 of 10 ran under both).
- Caches: `gpt-6-luna` and `glm-5.3` report cache reads on a repeated prefix; `glm-5.3-flash` only once the prefix passes roughly 2.5k tokens (none at 2.3k, 2176 at 3.1k). Entering Plan mode kept `gpt-6-luna`'s cache (1792 read on the first Plan call; 0 before the tool set was shared between modes).
- This gateway streams `minimax-m3` usage with every prompt count at 0 (its non-streamed answers carry real counts), so those calls are logged with `inputEstimated`.
- Anthropic Messages: `claude-sonnet-5.5` on the gateway's `/v1/messages` passes the same checks, picks the `claude` variant, and reads the cache from the second call on (about 4100 of 4200 input tokens). Signed thinking blocks replay correctly within a tool loop (a captured request replayed with and without them both succeeded).
- The same endpoint sometimes ends a Claude stream with an SSE `error` event (`response stream interrupted`, `api_error`) right as a tool call starts. It follows the request, not chance: one captured request failed on 9 of 9 replays whenever the answer was a `write` then `exit_plan`, and none of 5 once `exit_plan` lost its optional `plan` parameter. After that change it still happened in 1 of 3 Plan runs (a `list` call after thinking). Until the retry above (2026-10-11) the turn ended with the error; in the harness comparison it ended one run after its first call.
